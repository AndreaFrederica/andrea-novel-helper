# 语言服务解决方案

我们提供了两种不同的语言服务解决方案，以满足不同的使用场景和需求。

## 解决方案一：简单语言服务代理

简单语言服务代理是一个轻量级的解决方案，用于直接从 VSCode 的原生编辑器获取语言服务数据，而不需要创建复杂的虚拟文档系统。

### 适用场景

- 只需要获取语言服务数据，不需要编辑功能
- 需要最大兼容性，支持所有语言服务
- 资源有限，不希望创建额外的虚拟文档
- 快速原型开发或测试

### 使用方法

1. 打开任何文档
2. 将光标放在需要查询的位置
3. 打开命令面板 (Ctrl+Shift+P)
4. 运行以下任一命令：
   - `andrea.getHover` - 获取当前编辑器的 Hover 信息
   - `andrea.getCompletion` - 获取当前编辑器的自动完成
   - `andrea.getDefinition` - 获取当前编辑器的定义
   - `andrea.getSymbols` - 获取当前编辑器的符号
   - `andrea.getDiagnostics` - 获取当前编辑器的诊断信息
   - `andrea.getSemanticTokens` - 获取当前编辑器的语义标记

### 详细文档

详见 [SIMPLE_LANGUAGE_SERVICE.md](SIMPLE_LANGUAGE_SERVICE.md)

## 解决方案二：代理语言编辑器

代理语言编辑器是一个实验性的自定义编辑器，它提供了对语言服务的代理支持，允许在自定义编辑器环境中使用 VSCode 的语言功能。

### 适用场景

- 需要完整的编辑功能，包括实时同步
- 需要处理不落盘的内容
- 需要复杂的文档管理功能
- 需要自定义语言服务行为

### 主要功能

- **Hover 支持**：显示悬停提示信息
- **Completion 支持**：提供自动完成建议
- **Definition 支持**：跳转到定义位置
- **Symbols 支持**：显示文档符号列表
- **Semantic Tokens 支持**：显示语义标记信息
- **Diagnostics 支持**：显示错误和警告信息

### 配置选项

#### `andrea.proxyLanguageEditor.useRealFileUri`

- **类型**：`boolean`
- **默认值**：`true`
- **描述**：控制代理语言编辑器是否使用真实文件 URI 进行语言服务查询

##### 两种模式对比

| 模式 | 优点 | 缺点 |
|------|------|------|
| 真实文件 URI（默认） | 与原生编辑器体验一致，支持所有语言服务 | 会直接修改真实文件 |
| 虚拟文档 URI | 完全在内存中操作，不修改真实文件 | 可能无法获得某些语言服务支持 |

#### `andrea.proxyLanguageEditor.syncDelay`

- **类型**：`number`
- **默认值**：`500`
- **描述**：编辑器内容同步到真实文件的延迟（毫秒）

#### `andrea.proxyLanguageEditor.enableDiagnostics`

- **类型**：`boolean`
- **默认值**：`true`
- **描述**：是否启用诊断信息

#### `andrea.proxyLanguageEditor.enableSemanticTokens`

- **类型**：`boolean`
- **默认值**：`true`
- **描述**：是否启用语义标记

### 使用方法

1. 打开一个 `.md`、`.txt` 或 `.anhproxy` 文件
2. VSCode 会自动使用代理语言编辑器打开
3. 使用编辑器中的按钮测试各种语言服务功能

### 切换模式

#### 通过设置

1. 打开 VSCode 设置
2. 搜索 `andrea.proxyLanguageEditor.useRealFileUri`
3. 切换开关值

#### 通过命令

1. 打开命令面板（Ctrl+Shift+P）
2. 搜索"切换代理语言编辑器 URI 模式"
3. 执行命令

#### 通过编辑器菜单

1. 在代理语言编辑器中
2. 点击标题栏中的设置图标

### 技术实现

#### 方案 A：真实文件 URI（默认）

所有语言服务查询（hover、completion、definition 等）都直接在真实文件上运行。这确保了与原生编辑器完全一致的语言服务体验。

#### 方案 B：虚拟文档 URI

语言服务查询在虚拟文档上运行，编辑内容通过事件同步到真实文件。这提供了更灵活的控制，但可能无法获得某些语言服务支持。

### 故障排除

#### 如果遇到空白显示问题

1. **重新打开文件**：关闭当前的代理编辑器标签页，然后重新打开文件
2. **重新加载窗口**：使用命令面板（Ctrl+Shift+P）搜索"Reload Window"并执行
3. **检查配置**：确保 `useRealFileUri` 设置符合你的需求
4. **手动同步**：在编辑器中做任何修改都会触发同步

#### 如果没有获取到语言服务数据

1. **检查文件类型**：确保文件类型支持相应的语言服务（如 TypeScript、JavaScript、JSON 等）
2. **检查扩展**：确保安装了相应的语言扩展（如 TypeScript、Python 等）
3. **切换模式**：尝试切换 `useRealFileUri` 设置
4. **使用简单语言服务代理**：如果只需要获取数据，可以尝试使用简单语言服务代理

## 如何选择

### 选择简单语言服务代理，如果：

1. 你只需要读取语言服务数据
2. 你希望代码简单、易于维护
3. 你需要最大兼容性
4. 你不希望增加系统资源消耗

### 选择代理语言编辑器，如果：

1. 你需要完整的编辑功能
2. 你需要处理不落盘的内容
3. 你需要实时同步功能
4. 你需要自定义语言服务行为

## 详细对比

| 特性 | 简单语言服务代理 | 代理语言编辑器 |
|------|------------------|----------------|
| **主要用途** | 仅获取语言服务数据 | 完整的编辑功能 |
| **复杂度** | 低 | 高 |
| **资源消耗** | 低 | 高 |
| **兼容性** | 高（支持所有原生语言服务） | 中（部分语言服务可能不支持自定义scheme） |
| **维护成本** | 低 | 高 |
| **实时性** | 中（需要手动触发） | 高（自动同步） |
| **功能完整性** | 中（只读操作） | 高（读写操作） |
