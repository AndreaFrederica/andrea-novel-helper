功能引导

入门

🚀
项目初始化向导
一步步完成项目配置：填写项目信息、配置 Git、创建基础文件结构和忽略规则。

向导流程

初始化向导共 8 步，引导你完成从零到可写的项目搭建：

  • 欢迎 — 介绍向导功能
  • 项目信息 — 填写项目名称、作者、描述
  • 项目配置 — 设置默认写入目标、角色索引键、文件识别关键词（可选，有默认值）
  • Git 账户 — 配置 Git 用户名和邮箱
  • Git 仓库 — 初始化本地仓库、设置远程地址
  • 项目文件 — 创建 novel-helper/ 目录结构、示例角色文件、.gitignore
  • 确认 — 检查所有配置
  • 完成 — 可直接打开功能引导
向导会同时生成 anhproject.md（项目元数据）和 project-config.json5（项目配置），二者共同构成 ANH 的项目配置体系。
⚙
项目设置
编辑项目名称、作者、标签、封面、文件识别关键词、默认写入目标、角色索引键等配置。

配置文件

项目设置管理两个文件：

  • anhproject.md — 项目元数据（名称、作者、描述、UUID、封面、摘要、标签）
  • project-config.json5 — 项目级配置（资源路径、索引键、文件关键词）

优先级

配置优先级：项目配置 > VSCode 设置 > 插件默认值。项目配置会覆盖同名的 VSCode 设置。

⚙
插件设置
查看和修改 ANH 的所有配置项，包括校对、翻译、排版、字数统计、Git 等功能的详细参数。
⚙
VSCode 设置
打开 VSCode 通用设置页面，管理编辑器外观、快捷键、主题、字体等全局配置。
📖
写作预览
侧边预览当前文档，支持 Markdown/TXT 纯文本预览和 Typst 专业排版预览，角色名自动着色。

Markdown/TXT 预览

侧边栏实时渲染当前文档，支持：

  • 增量更新 — 仅重渲染变化的段落，性能优秀
  • 双向滚动同步 — 编辑器和预览联动滚动
  • 角色名着色 — 预览中角色名自动按定义颜色高亮
  • TTS 朗读 — 支持文本转语音播放
  • 导出 — 可复制纯文本或导出为 TXT 文件

Typst 排版预览

将 Markdown 转换为 Typst 格式进行专业排版。需要安装 Tinymist Typst 扩展。支持模板选择、内存/文件两种存储模式。

核心概念

🧠
一切皆角色
ANH 的核心设计理念：角色、敏感词、词汇、正则都统一为"角色"对象，共享同一套编辑和引用能力。

统一对象模型

ANH 中所有资源类型都由同一个 Role 接口表示，通过 type 字段区分：

  • 主角 / 配角 / 联动角色 — 角色人物
  • 敏感词 — 需要标记或替换的词汇，附带 fixes 修复建议
  • 词汇 — 世界观术语和专业名词
  • 正则表达式 — 自定义着色规则，用 regex + regexFlags 定义匹配模式

共享能力

无论哪种类型，所有"角色"都享有：

  • 别名 — 支持多个别名，编辑器中自动识别
  • 跳转定义 — Ctrl+Click 直接跳转到角色定义文件
  • 查找引用 — 查看角色在哪些文件中被引用
  • 自动补全 — 输入 @ 或角色名时弹出补全，支持拼音匹配
  • 高亮装饰 — 编辑器中自动按颜色标记
  • 角色卡编辑器 — 可视化编辑所有字段
这意味着你不需要学习不同的工具来管理不同类型的资源。一个角色卡编辑器、一套补全系统、一种高亮机制，统一管理所有写作资产。
📦
包管理器
侧栏中的资源管理器。"包"即 novel-helper/ 下的目录，每个目录可包含角色库、敏感词库、词汇表等资源文件。

什么是"包"

包管理器中的"包"就是 novel-helper/ 下的一个目录。每个目录可以包含：

  • 角色库文件（character-gallery.json5、*_roles.md 等）
  • 敏感词库（sensitive-words.json5）
  • 词汇表（vocabulary.json5）
  • 正则着色规则（regex-patterns.json5）
  • 关系文件（*.rjson5）和时间线（*.tjson5）
  • 子包（子目录）

推荐结构

典型的小说项目目录结构：

  • novel-helper/main/ — 主要角色和资源
  • novel-helper/faction-a/ — 按阵营/势力分包
  • novel-helper/worldbuilding/ — 世界观词汇和术语

操作方式

  • 右键文件夹 — 创建新的资源文件（角色库、敏感词库等）
  • 拖放 — 在包之间移动或复制文件
  • 展开文件 — 查看文件内包含的角色列表
  • 外部资源 — 可挂载工作区外的目录
包管理器支持 JSON5、Markdown、TXT、CSV 四种文件格式。推荐使用 JSON5 格式，字段最完整。

角色与资源

🧑
角色管理
通过角色卡编辑器管理角色信息。支持 JSON5、CSV、Markdown 等格式。角色会在编辑器中自动高亮和补全。
在包管理器中右键文件夹可新建角色库

角色类型

通过 type 字段区分角色类型：

  • 主角 — 核心角色，通常有详细描述和颜色标记
  • 配角 — 次要角色
  • 联动角色 — 跨作品联动的角色

文件格式

  • JSON5（推荐）— 字段最完整，支持注释和尾逗号
  • CSV — 适合批量导入，表头行定义字段
  • Markdown — 用二级标题分隔角色，YAML frontmatter 定义元数据

角色卡编辑器

在包管理器中点击角色文件或角色节点，会打开可视化角色卡编辑器，支持编辑所有字段（名称、类型、别名、描述、颜色等）。

角色的 name 是唯一标识。别名 aliases 和索引键 lookupKeys 用于补全和搜索匹配，支持拼音。
⚠
敏感词检测
定义敏感词库，编辑器会实时标记匹配的词汇。支持自定义严重级别、别名和修复建议。
在包管理器中右键文件夹可新建敏感词库

工作原理

敏感词本质上是 type: '敏感词' 的角色。编辑器会实时扫描文本，用波浪线标记匹配的敏感词。

关键字段

  • name — 敏感词本身
  • aliases — 敏感词的别名变体
  • fixes — 修复建议列表（右键可快速替换）
  • priority — 严重级别，影响标记颜色
敏感词也支持角色名误报抑制 — 如果某个"敏感词"实际上是你作品中的角色名，ANH 会自动跳过。
📚
词汇表
管理世界观术语和专业词汇。支持分类、别名、自动补全和高亮显示。
在包管理器中右键文件夹可新建词汇表

用途

词汇表用于管理世界观中的专有名词：地名、组织名、魔法术语、科技名词等。type 为 词汇。

使用方式

  • 在编辑器中输入词汇名或别名时自动弹出补全
  • 词汇名在编辑器中按定义颜色高亮
  • 支持 Ctrl+Click 跳转到定义、查找所有引用
词汇和角色共享同一套能力（补全、高亮、跳转、引用），区别仅在于 type 字段。
🎨
正则着色
用正则表达式定义自定义着色规则。可匹配对话、书名号、特殊标记等，用颜色直观区分文本类型。
在包管理器中右键文件夹可新建着色规则

工作原理

正则着色规则是 type: '正则表达式' 的角色。通过 regex 字段定义匹配模式，regexFlags 定义标志位。

典型用例

  • 匹配对话引号（「[^」]+」）
  • 匹配书名号（《[^》]+》）
  • 匹配特殊标记（如旁白、心理活动等）

关键字段

  • regex — 正则表达式模式
  • regexFlags — 标志位（如 g、i）
  • color — 匹配文本的高亮颜色
  • priority — 优先级，高优先级规则优先生效

写作辅助

⌨
角色补全
输入 @ 或角色名时自动弹出补全列表。支持拼音、别名、索引键匹配，快速插入角色名。

触发方式

  • 输入 @ 触发全量角色列表
  • 直接输入角色名或别名的前几个字符
  • 支持拼音首字母匹配（如输入 zsf 匹配 "张三丰"）

匹配规则

补全系统会匹配角色的 name、aliases、lookupKeys 字段。索引键可自定义，支持拼音和罗马字转写。

📝
字数统计
状态栏实时显示当前文件字数和写作速度。支持多种统计方式（含标点/不含标点/万字显示）。

统计模式

  • 含标点 / 不含标点
  • 万字显示（如 12.3 万字）
  • 实时写作速度（字/分钟）

可通过底部工具栏或 .wcignore 文件排除不需要统计的区域。

⏱
写作时间统计
追踪写作时长和产出量，支持里程碑提醒（如达到 1 万字时通知）。可通过仪表板查看历史趋势。

功能

  • 自动追踪每次写作会话的时长和产出字数
  • 里程碑提醒 — 达到设定字数时弹出通知
  • 仪表板 — 查看每日/每周/每月的写作趋势图表
🔍
校对与纠错
基于规则或 LLM 的错别字检测。支持自动扫描、角色名误报抑制、自定义服务端点。

校对模式

  • 规则校对 — 基于内置规则检测常见错别字和标点错误
  • LLM 校对 — 接入大语言模型进行更智能的纠错，支持自定义 API 端点

特性

  • 角色名误报抑制 — 已定义的角色名不会被标记为错别字
  • 自动扫描 — 打开文件时自动检测
  • 快速修复 — 点击标记即可应用修复建议
🌐
翻译
右键选中文本即可翻译。支持中、英、日、德、法、韩等多种目标语言，结果可替换选区或复制。

使用方式

选中文本 → 右键 → 翻译。翻译结果可以：

  • 替换选中的原文
  • 复制到剪贴板
  • 插入到文档末尾

支持配置翻译服务端点和 API 密钥。

📐
排版辅助
段落首行缩进、段间空行、智能引号补全、智能回车和跳出括号。底部工具栏可快速切换选项。

排版功能

  • 首行缩进 — 自动在段落开头添加全角空格
  • 段间空行 — 自动在段落之间插入空行
  • 智能引号 — 输入引号时自动配对（如 " → 「」）
  • 智能回车 — 在引号内回车时自动跳出
  • 跳出括号 — 输入右括号时自动跳过而非重复插入

底部工具栏可快速开关各项排版选项。也可通过 Ctrl+Alt+I 打开快速设置面板。

📑
大纲
双重大纲视图：目录大纲展示项目文件结构，文件大纲展示当前文档的标题层级。支持懒加载。

双重大纲

同时打开两个大纲视图：

  • 目录大纲（上）— 显示当前目录下的文件和子目录结构
  • 文件大纲（下）— 显示当前文档的标题层级（类似 Markdown 目录）

懒加载模式

默认开启。大纲文件仅在可见时才生成/刷新，避免不必要的磁盘写入。可通过 AndreaNovelHelper.outline.lazyMode 配置。

大纲存储

大纲文件存储在 novel-helper/outline/ 目录下，使用自定义文件系统方案 andrea-outline:// 提供。

高级功能

📂
外部资源目录
将工作区外的角色库、词汇表等目录挂载到 ANH 中统一管理，无需移动文件。

使用场景

当你有多个项目共享同一套角色库或词汇表时，可以将公共资源目录挂载为外部资源，避免重复复制。

操作

  • 点击"管理外部目录"按钮添加或移除外部路径
  • ANH 会自动扫描挂载目录中的所有角色文件
  • 外部资源中的角色与项目内角色享有相同的补全、高亮和引用能力
🔥
引用维护与热力图
查看角色在各章节中的出场频次热力图，检测引用断裂和孤立引用，维护角色引用一致性。

功能

  • 热力图 — 可视化展示每个角色在各章节中的出场频次
  • 引用断裂检测 — 发现文本中提到但未定义的角色名
  • 孤立引用检测 — 发现定义了但从未在文本中出现的角色
引用维护是保持角色一致性的关键工具，尤其在长篇小说中角色众多时非常有用。
🔀
Git 集成
可选的 Git 版本控制集成。支持自动提交、自动推送、自动拉取，追踪每次重要改动。

功能

  • 自动提交 — 保存文件时自动创建 Git 提交
  • 自动推送 — 提交后自动推送到远程仓库
  • 自动拉取 — 打开项目时自动拉取最新更改

所有 Git 功能均可在设置中独立开关。初始化向导可一键完成 Git 仓库配置。

🤝
角色关系图
用可视化关系图管理角色之间的关系（亲属、敌对、同盟等）。支持自定义关系类型和方向。
在包管理器中右键文件夹可新建关系文件

关系文件

关系文件扩展名为 .rjson5，用 JSON5 格式定义角色之间的关系。支持：

  • 自定义关系类型（亲属、敌对、同盟、师徒等）
  • 有向/无向关系
  • 关系描述文本

可视化关系图会自动从关系文件渲染，支持交互式浏览。

🕒
时间线
管理故事中的事件时间线。按时间顺序排列事件，关联涉及的角色和地点。
在包管理器中右键文件夹可新建时间线

时间线文件

时间线文件扩展名为 .tjson5，用于管理故事中的事件序列。每个事件可包含：

  • 事件名称和描述
  • 发生时间（支持自定义时间体系）
  • 涉及的角色和地点
  • 事件之间的因果关系
⚡
脚本运行时
在 ANH 中运行自定义 JS/TS 脚本，支持 MCP 服务器集成和丰富的运行时上下文注入。

脚本运行

脚本位于 novel-helper/scripts/ 目录下（可在设置中修改）。右键脚本文件即可运行。

运行时上下文

脚本执行时会注入丰富的上下文对象：

  • ctx.activeDoc — 当前编辑器文档的原始文本和纯文本
  • ctx.mcp — MCP 客户端实例，可调用 MCP 工具
  • ctx.os / ctx.fs / ctx.path — Node.js 内置模块
  • ctx.output — 输出通道（console.log 自动重定向到此）

MCP 服务器集成

可配置多个 MCP 服务器，脚本运行时自动连接。支持 Chrome 浏览器控制、数据库访问等扩展能力。

脚本运行时是 ANH 最灵活的扩展机制。你可以用它实现自定义的文本处理、批量操作、数据导入导出等任何自动化任务。
☁
WebDAV 同步
通过 WebDAV 协议同步项目文件到云端，支持多设备协作。可配置同步策略和自动同步间隔。

功能

  • 通过 WebDAV 协议将项目文件同步到支持 WebDAV 的云存储
  • 支持配置同步策略（全量同步 / 仅同步特定目录）
  • 可设置自动同步间隔
  • 适合多设备写作场景
