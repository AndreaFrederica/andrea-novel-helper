自动补全是什么

ANH 提供多种自动补全功能，让你在写作时更高效：

  • 角色名补全 — 打字时自动弹出匹配的角色名，选中后直接插入
  • 敏感词修复建议 — 输入敏感词时，自动弹出推荐的替换词
  • &Def 元数据补全 — 输入 &Def 快速插入标题、副标题、分类等元数据
  • 项目配置补全 — 编辑项目配置文件时，自动补全配置项

角色名补全

最常见的用法。打字时自动弹出匹配的角色列表：

  • 直接打字 — 输入角色名的前几个字，自动弹出匹配的角色（默认模式）
  • 输入 @ — 打 @ 后自动列出所有角色
  • 拼音首字母 — 如果角色有 lookupKeys_pinyin，输入 zsf 可匹配"张三丰"；自动生成拼音查询键默认关闭，需要在设置中开启或手动填写字段
  • 别名匹配 — 角色定义中的别名（昵称、外号）也能匹配

提示列表里能看到什么

  • 颜色标记 — 每个角色名前有小色块，一眼认出是谁
  • 类型和从属 — 显示角色是主角/配角，属于哪个阵营
  • 描述预览 — 鼠标停在角色上显示完整简介

一键生成拼音/罗马字查询键

如果想用 zsf 这类拼音首字母匹配，但又不想长期打开自动生成，可以对当前角色文件手动生成一次：

  1. 打开角色库文件（Markdown、JSON5 或 OJSON5）
  2. 按 Ctrl+Shift+P
  3. 运行 Andrea Novel Helper: 为当前角色文件生成查询键

也可以从包管理器顶部“常用功能”点击“+ 为当前角色文件生成查询键”。如果正在使用角色卡编辑器，可以在查询键字段旁请求拼音 / 罗马字候选，多选后直接追加。

命令会把生成结果写入 lookupKeys_pinyin / lookupKeys_romanized，以后补全就能用这些查询键匹配。

敏感词修复

输入敏感词时，补全列表会弹出推荐的替换词。选择后自动替换，帮你避免发布时的审查问题。

&Def 元数据补全

在 Markdown 文件中输入 &Def，会弹出元数据模板：

  • &Def Title = 标题 — 定义主标题
  • &Def Subtitle = 副标题 — 定义副标题
  • &Def Category = 分类 — 定义分类

这些元数据会被 Typst 排版导出时使用。

如果提示没更新

有时候新建了角色但提示列表里没有，可以用命令"刷新角色库"强制重新加载。

一、角色名补全系统

核心文件：src/Provider/completionProvider.ts，通过 createRoleCompletionProvider() 工厂函数创建 CompletionItemProvider。

触发方式

补全在以下情况下触发：

  • 输入任意字母、数字或下划线 — 所有 word 字符都是触发字符
  • 输入符号前缀 — 默认 @（可通过配置添加 # 等其他符号）

触发模式由 AndreaNovelHelper.completion.triggerMode 控制：

  • loose — 无符号，包含匹配（默认）。输入"三"可匹配"张三丰"
  • startsWith — 无符号，前缀匹配。必须从角色名开头匹配
  • symbolLoose — 需要符号前缀（如 @），包含匹配
  • symbolStartsWith — 需要符号前缀，前缀匹配

匹配机制

补全系统通过 getRoleMatchKeys() 获取每个角色的全部匹配键：

  • name — 角色主名称
  • aliases — 别名数组
  • lookupKeys_pinyin — 拼音查询键（全拼 + 首字母缩写）
  • lookupKeys_romanized — 罗马字查询键（日文假名→罗马字）
  • lookupKeys_spelling — 拼写查询键（英文名变体）
  • 其他自定义索引键前缀（通过 AndreaNovelHelper.extendedLookupKeyPrefixes 配置）

重要：查询键一旦存在就会参与匹配。例如角色含有 lookupKeys_pinyin: ["zhangsanfeng", "zsf"] 时，输入 zsf 可匹配到"张三丰"。但查询键不会默认自动生成；lookupKeys.autoGeneratePinyin 和 lookupKeys.autoGenerateRomanized 默认关闭，需要开启后才会为角色名/别名补齐对应字段，或手动在角色文件中填写。

treatPinyinAsAlias 和 treatRomanizedAsAlias 只控制已有查询键是否在补全列表中显示为独立条目（默认关闭），不控制匹配本身。默认情况下，zsf 可以作为匹配键，但列表里仍显示"张三丰"或其别名，而不是单独显示"zsf"。

手动一键生成查询键

如果不想长期开启自动生成，可以只对当前打开的角色文件手动生成一次：

  1. 打开一个 Markdown、JSON5 或 OJSON5 角色文件
  2. 按 Ctrl+Shift+P 打开命令面板
  3. 运行 Andrea Novel Helper: 为当前角色文件生成查询键

命令会根据角色的 name 和 aliases 生成 lookupKeys_pinyin 与 lookupKeys_romanized，并与已有字段去重合并。Markdown 文件会插入或更新 ### 拼音查询键 / ### 罗马字查询键 字段；JSON5/OJSON5 文件会写回数组字段。

角色卡编辑器内的查询键候选功能不会立刻改写整个文件，而是把候选追加到当前编辑中的角色字段；保存时再随角色卡一起写回。

JSON5/OJSON5 执行后会被重新格式化。Markdown 会尽量保留原有结构，只更新查询键字段。

前缀提取使用分词器（AndreaNovelHelper.completion.segmenterType：auto/intl/jieba）将光标前的文本分词，生成由长到短的候选前缀（最长 48 字符 / 8 个分词段），选择最佳匹配。分词器会自动将角色名/别名加入自定义词典，确保它们作为原子分词单元。

补全项内容

每个匹配的角色会为每个显示名称（主名称 + 别名 + 可选的拼音/罗马字）生成一个 CompletionItem：

  • 插入文本 — 选择后插入角色名，替换已输入的前缀（含符号前缀）
  • 详细信息 — 显示角色类型和从属
  • 文档弹窗 — 悬停时显示完整的 Markdown 文档，包含：
    • 颜色标记（内联 SVG 色块 + 色值）
    • 类型和从属
    • 描述（支持 Markdown 格式，自动识别列表/标题/加粗等）
    • 包路径和源文件名
    • 自定义扩展字段（通过 Markdown 解析器提取）

排序与过滤

  • 排序规则 — 前缀开头匹配排在包含匹配之前；同一匹配级别内按字母顺序排列（中文按 locale 排序）
  • 敏感词过滤 — 类型为"敏感词"的角色会被自动排除在补全列表之外
  • 敏感词修复建议 — 敏感词角色的 fixes（或兼容旧字段 fixs）数组中的替换词会作为独立的补全项出现，标记为"修复: 来自敏感词「xxx」"，排序在普通角色之后。选择后会将敏感词替换为建议的修复词
  • 最终安全过滤 — 生成所有补全项后，再次检查并移除任何意外匹配到敏感词名称的项目，防止异步角色加载导致的竞争条件

二、&Def 元数据补全

核心文件：src/language/defCompletion.ts

在 Markdown/纯文本文件中，输入 &、D、主、副、分 时触发，提供 6 个代码片段：

  • &Def Title = ${1} — 定义主标题
  • &Def Subtitle = ${1} — 定义副标题
  • &Def Category = ${1} — 定义分类
  • 以上三项的中文版本：&Def 主标题、&Def 副标题、&Def 分类

使用 vscode.SnippetString 实现 tab-stop 插入，选择后光标自动定位到值的位置。

三、项目配置补全

anhproject.md 配置补全

核心文件：src/projectConfig/projectConfigCompletionProvider.ts

在 anhproject.md 文件中，输入 # 或空格时触发，提供 Markdown 章节标题补全：

  • ## 项目名称、## 项目描述、## 作者、## 项目UUID、## 封面 等
  • 空行时提供"所有配置项"大全片段，一次性插入所有配置章节

project-config.json5 配置补全

核心文件：src/projectConfig/projectKeywordConfigJson5.ts + projectJson5Config.ts

在 project-config.json5 文件中，输入引号时触发，提供 JSON5 键补全：

  • 关键词配置项：key: ['$1'],
  • 扩展字段：rolesFile、sensitiveWordsFile、defaultRoleLookupKeys 等

四、分词器与中文支持

核心文件：src/utils/segmenter.ts + src/utils/completionPrefix.ts

  • 使用 @node-rs/jieba 进行中文分词，不可用时回退到 Intl.Segmenter
  • 自定义词典自动从角色名、别名、修复词构建
  • containsPrefix() 使用分词器感知的匹配，短前缀也能准确匹配
  • 前缀候选生成：从光标前文本分词，逐步组合生成由长到短的候选（最多 8 段 / 48 字符）

五、配置项

  • AndreaNovelHelper.completion.triggerMode — 触发模式（loose/startsWith/symbolLoose/symbolStartsWith）
  • AndreaNovelHelper.completion.symbolPrefixes — 符号触发前缀数组（默认 ["@"]）
  • AndreaNovelHelper.completion.segmenterType — 分词器类型（auto/intl/jieba，默认 auto）
  • AndreaNovelHelper.completion.minChars — 最小触发字符数（默认 1）
  • AndreaNovelHelper.lookupKeys.treatPinyinAsAlias — 将拼音查询键作为补全项显示（默认关闭，不影响匹配）
  • AndreaNovelHelper.lookupKeys.treatRomanizedAsAlias — 将罗马字查询键作为补全项显示（默认关闭，不影响匹配）
  • AndreaNovelHelper.lookupKeys.autoGeneratePinyin — 自动生成拼音查询键（默认关闭）
  • AndreaNovelHelper.lookupKeys.autoGenerateRomanized — 自动生成罗马字查询键（默认关闭）
  • AndreaNovelHelper.generateLookupKeysForCurrentFile — 对当前打开的角色文件手动生成查询键
  • AndreaNovelHelper.defaultRoleLookupKeys — 默认查询键配置
  • AndreaNovelHelper.extendedLookupKeyPrefixes — 扩展索引键前缀
  • AndreaNovelHelper.debug.completionLog — 启用补全系统的控制台调试日志

六、注册与语言支持

补全提供者在 activate.ts 中通过 registerLanguageFeatures() 注册，支持以下文件类型：

  • Markdown、纯文本、JSON5、CSV
  • OJSON5、RJSON5、TJSON5（ANH 自定义格式）
  • 每种类型同时支持 file 和 untitled 方案

当 supportedFileTypes、completion.triggerMode 或 completion.symbolPrefixes 配置变更时，提供者会自动重新注册。

补全系统使用异步角色匹配缓存（roleAsyncShared），首次加载后响应极快。如果补全列表未更新，可使用命令"刷新角色库"强制重新加载。敏感词角色的 fixes 字段是一个字符串数组，定义了建议的替换词；选择修复补全项会将敏感词替换为对应的修复词。
