这是什么文件

character-gallery.* 是初始化时默认创建的角色库示例文件。它的默认目标路径由 project-config.json5 里的 rolesFile 决定，默认是 novel-helper/character-gallery.json5。

这个默认文件更像“起步样例”，不是包机制下唯一推荐的终局结构。长期手工维护通常更推荐拆到多个包目录里，并优先用 roles.md；Excel / 表格来源则更适合先落 character-gallery.csv。

为什么这里写成 *

因为 ANH 不只支持一种角色库格式。初始化常见是：

  • character-gallery.json5：字段完整，适合结构复杂、机器处理较多的角色数据
  • character-gallery.csv：适合从 Excel / 表格迁入
  • roles.md：更适合手工阅读、长期维护和分层组织

什么时候该优先用 JSON5

  • 字段多
  • 要写颜色、样式、别名、描述、优先级
  • 希望结构化、易于程序处理

什么时候 Markdown 更好

  • 你会经常阅读这些设定，而不只是把它们当数据库
  • 你想按阵营、卷册、势力拆成多个包目录长期维护
  • 你更习惯“像写设定手册一样写角色”

什么时候 CSV 更好

  • 你手里原本就是 Excel 表格
  • 你要一次性导入很多条简单角色数据
角色库是“写作体验”的核心文件之一。补全、着色、检索、角色面板都跟它直接相关。

JSON5 版最小示例

[
  {
    name: '林小满',
    type: '主角',
    color: '#FF6B6B',
    aliases: ['小满', '小林'],
    description: '一个喜欢雨天咖啡店的女孩',
  }
]

CSV 版适合什么

CSV 更像导入中转站，不一定适合承载特别复杂的角色结构。你可以先用 CSV 导入，再逐步迁成 JSON5 或 Markdown。

和 roles.md 的关系

roles.md 更像“可读性优先”的角色手册；character-gallery.json5 更像“结构化优先”的角色数据库。二者不是谁绝对替代谁，而是看你的维护方式。

常见错误

  • 把敏感词或词汇表也塞进角色库里
  • 角色别名字段写成一整段自然语言
  • 把 CSV 当成无限复杂结构容器，结果维护困难
