这页文档讲什么

这页讲的是 VS Code 里怎么用 Git，以及 ANH 在 Git 流程里额外帮了你什么。如果你还没系统理解 Git 本身，建议先按这个顺序读：先看 版本管理是什么，再看 Git 本体详解，最后回到这页；如果你正在选 GitHub、GitLab、Gitee、Codeberg、CODING 之类的平台，继续看 Git 托管平台比较。

VS Code 里的 Git 是怎么工作的

VS Code 自带 Source Control 视图。你可以把它理解成一个把常用 Git 命令“做成按钮”的界面：

你在 VS Code 里看到的操作 本质上对应的 Git 行为
初始化仓库 git init
把文件加入暂存区 git add 文件名
提交 git commit -m "说明"
拉取 / 推送 / 同步 git pull / git push
查看文件差异 git diff
切分支 git switch 分支名
发布到远端 git remote add origin ... + git push -u

最适合新手的 VS Code 流程

  1. 打开小说项目文件夹。
  2. 点左侧 Source Control 图标。
  3. 如果还没有仓库，点“初始化仓库”。
  4. 改完文件后，先看文件列表和差异。
  5. 把要提交的文件点 + 暂存。
  6. 在消息框里写一句清楚的人话，比如“完成第六章初稿”或“补齐角色关系设定”。
  7. 点“提交”。
  8. 需要上云时，再点“发布分支”或“同步更改”。

什么时候该用 VS Code 按钮，什么时候该用原始命令

  • 日常写作：看差异、暂存、提交、推送，优先用 VS Code 就够了
  • 第一次绑定远端：VS Code 可以做，但命令行更能帮助你理解发生了什么
  • 处理冲突：VS Code 的冲突编辑器很好用，优先用图形界面
  • 高级操作：例如 rebase、cherry-pick、stash、多远端推送，通常还是命令行更直接
  • 排错：当按钮提示看不懂时，去终端输入 Git 命令最清楚

ANH 在 Git 这件事上帮了什么

  • Git 身份配置向导：命令 AndreaNovelHelper.setupGitIdentity，帮你补齐 user.name 和 user.email
  • 状态栏同步状态：把 Git 与 WebDAV 的自动同步状态合并显示在底部状态栏
  • 自动 Git：可以当安全网，但不建议拿来代替你自己的提交节奏
  • GitGuard 字数统计：可以基于 Git 基线统计“自上次提交以后真实新增的字数”
一句话建议：新手先学会“看差异、写提交、推送远端”这三件事。先把这三件事做稳定，比一开始就学一堆高级命令更重要。如果你想把这些按钮背后的 Git 机制一次性学明白，直接去看 Git 本体详解。

你至少应该认识的 10 个命令

命令 用途 新手常见场景
git status 看当前仓库状态 先确认哪些文件改了
git add 文件名 加入暂存区 只提交你真正想保存的改动
git commit -m "说明" 创建版本快照 写清楚本次修改意图
git log --oneline 看历史 回忆“昨天到底改了什么”
git diff 看未暂存差异 提交前复查
git diff --cached 看已暂存差异 确认暂存区没有混进多余文件
git switch -c 分支名 创建并切换分支 开一个“试验剧情”支线
git pull 拉取远端更新 换电脑前先同步
git push 把本地提交发到云端 做备份，或和别的设备同步
git revert 提交号 安全撤销一个已提交版本 比乱用强制回退更稳

分支对小说作者到底有什么用

你不一定需要复杂分支模型，但下面这三种情况很适合开分支：

  • 你想试写一个“平行剧情版本”，又不想污染主线
  • 你想大改角色设定，但还没决定要不要保留
  • 你和合作者分工改不同章节，最后再合并
git switch -c alt-ending
# 写另一种结局
git add .
git commit -m "试写另一版结局"

git switch main
# 如果满意，再 merge 过来

冲突是什么，VS Code 怎么帮你解

冲突通常发生在“两边都改了同一段内容”。VS Code 会把冲突区块高亮出来，并提供“接受当前更改 / 接受传入更改 / 同时接受 / 手工编辑”等操作。原则很简单：

  • 先读清楚两边分别改了什么
  • 不要机械点“Accept Both”
  • 解决后重新检查正文是否通顺，再提交一次“解决冲突”

自动 Git 的定位

ANH 的 AutoGit 更像安全网，不像主工作流。它适合“防忘记”，不适合“整理历史”。你仍然应该手动做里程碑提交。

  • AndreaNovelHelper.autoGit.enabled：总开关
  • AndreaNovelHelper.autoGit.autoPush：是否自动推送
  • AndreaNovelHelper.autoGit.autoPull：是否自动拉取
  • AndreaNovelHelper.autoGit.commitMessageTemplate：自动提交信息模板
  • AndreaNovelHelper.autoGit.excludePatterns：忽略文件模式
  • AndreaNovelHelper.autoGit.compactStatus：状态栏紧凑模式

推荐习惯

  1. 每天开写前先 pull，收工前至少 commit 一次。
  2. 提交信息写“动作 + 对象”，例如“补完第三章追逐戏”“重写叶青角色背景”。
  3. 大改结构前先开分支，不要拿主分支裸奔。
  4. 远端仓库主要用来同步和备份，不要把它当唯一存档；关键节点最好还有压缩包或导出备份。
如果你的重点是“怎么创建云仓库、怎么绑定远端、怎么在两台电脑之间同步”，继续看 云仓库同步与备份。
