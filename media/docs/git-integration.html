Git 版本控制是什么

Git 是一种版本控制工具，可以帮你记录文件的每次修改。就像给你的小说写"修改日志"——每次重要改动都可以保存一个快照，以后想找回旧版本随时可以。

为什么推荐手动使用 Git

虽然 ANH 提供了自动 Git 功能，但我们强烈推荐你学习手动使用 Git。原因：

  • 有意义的提交信息：手动提交时你会写下"完成了第三章初稿"、"修改了主角背景设定"这样的描述，而不是"Auto commit: 2024-01-01"。半年后回看历史，你能一眼看出每次改动做了什么
  • 干净的版本历史：自动提交会生成大量无意义的快照（每 30 秒一个），淹没掉真正重要的改动。手动提交让你精确控制什么时候保存快照
  • 更好的协作体验：如果以后要和别人合作写作，有意义的提交信息是协作的基础
  • 学习一项实用技能：Git 是软件开发中最常用的工具，学会了对你的职业生涯也有帮助

手动使用 Git 的基本流程

  1. 安装 Git — 从 git-scm.com 下载安装
  2. 初始化仓库 — 在项目文件夹中右键 → "Git Bash Here" → 输入 git init
  3. 配置身份 — 输入 git config user.name "你的名字" 和 git config user.email "你的邮箱"
  4. 提交改动 — 写完一段后，在终端输入： 
    git add .                    # 暂存所有改动
git commit -m "完成第三章初稿"  # 提交并写描述
  5. 查看历史 — 输入 git log 查看所有提交记录
  6. 找回旧版本 — 输入 git log --oneline 查看版本号，然后 git checkout <版本号> -- 文件名 恢复

ANH 提供的 Git 辅助

  • Git 身份配置向导 — 在命令面板输入"设置 Git 身份"，一步步引导你配置
  • 自动 Git（可选） — 如果你觉得手动太麻烦，ANH 也提供自动提交功能，但不推荐作为主要使用方式
  • Git 状态显示 — 底部状态栏显示 Git 同步状态

推荐的工作习惯

  • 每完成一个场景或章节就提交一次
  • 提交信息写清楚做了什么（如"完成第三章初稿"、"修改了反派角色设定"）
  • 重要里程碑打标签：git tag v1.0-初稿完成
  • 定期推送到远程仓库（如 GitHub）做备份

一、手动 Git（推荐）

手动使用 Git 能给你最干净、最有意义的版本历史。以下是进阶技巧：

分支管理：

git branch 修订版        # 创建修订分支
git checkout 修订版      # 切换到修订分支
git checkout master      # 切回主线
git merge 修订版         # 合并修订到主线

标签：

git tag v1.0-初稿
git tag v2.0-终稿
git tag -a v3.0 -m "出版版"

查看差异：

git diff                 # 查看未暂存的改动
git diff --cached        # 查看已暂存的改动
git log --oneline        # 简洁版提交历史
git log --graph          # 图形化分支历史

撤销操作：

git checkout -- 文件名    # 撤销工作区改动
git reset HEAD 文件名     # 取消暂存
git revert HEAD           # 撤销最近一次提交（创建新提交）

二、自动 Git（可选）

ANH 的自动 Git 功能（AutoGitService）可以自动提交你的改动。虽然不推荐作为主要方式，但在某些场景下可以作为辅助：

  • 你完全不想学习 Git 命令
  • 你只需要基本的版本备份，不需要有意义的提交历史

自动提交行为：

  • 保存文件时自动创建 Git 提交
  • 内置 30 秒冷却 + 3 秒防抖，避免频繁提交
  • 提交信息格式："Auto commit: {timestamp}"
  • 可选自动推送到远程仓库
  • 可选自动拉取远程更新

配置项：

  • AndreaNovelHelper.autoGit.enabled — 总开关
  • AndreaNovelHelper.autoGit.autoPush — 自动推送
  • AndreaNovelHelper.autoGit.autoPull — 自动拉取
  • AndreaNovelHelper.autoGit.checkIntervalSeconds — HEAD 检查间隔（默认 30 秒）
  • AndreaNovelHelper.autoGit.commitMessageTemplate — 提交信息模板
  • AndreaNovelHelper.autoGit.includeUntracked — 包含未跟踪文件
  • AndreaNovelHelper.autoGit.excludePatterns — 排除文件模式
  • AndreaNovelHelper.autoGit.compactStatus — 状态栏紧凑模式

提交信息模板变量：

  • {timestamp} — 当前时间
  • {files} — 变更文件列表
  • {branch} — 当前分支名

三、GitGuard — 智能字数统计

ANH 的字数统计可以与 Git 联动，只统计自上次提交以来真正新增的字数，而不是每次保存都重新计算。

  • 通过 VS Code Git 扩展 API 读取 Git 状态（不依赖 CLI）
  • 三种基线模式：HEAD（对比最新提交）、INDEX（对比暂存区）、WORKTREE（对比工作区）
  • 内容哈希去重，避免重复统计相同内容

四、Git 身份配置向导

命令：AndreaNovelHelper.setupGitIdentity

  • 检查 Git 是否已安装
  • 检测已有的全局/本地 user.name 和 user.email
  • 交互式向导配置 Git 身份
  • 支持全局配置和本地（仅当前仓库）配置
  • 本地配置时自动初始化 Git 仓库

五、状态栏

Git 状态与 WebDAV 同步状态整合显示在底部状态栏：ANH:Sync Git:ON/OFF WebDAV:ON/OFF。点击可快速切换开关。

novel-helper/.anh-fsdb/

node_modules/

我们推荐手动使用 Git，因为有意义的提交信息和干净的版本历史对长期写作项目至关重要。自动 Git 可以作为安全网，但不应该替代你的主动版本管理。如果你是 Git 新手，建议花 30 分钟学习基本命令，这会让你的写作流程受益终身。
