这一页讲什么

这页讲 VS Code 里最核心的三个动作：找文件、开文件、搜内容。对写作者来说，这比任何高级功能都更重要，因为你每天都在处理章节、设定、备忘录、导出稿和缓存文件。

先建立一个正确习惯：打开文件夹，不要只打开单个文件

VS Code 最适合的工作方式是“打开项目文件夹”，不是“单独打开某个 md 文件”。

  • 打开文件夹：文件 → 打开文件夹。
  • 为什么重要：只有打开文件夹后，资源管理器、全局搜索、Git、工作区设置、ANH 的各种视图才完整工作。
  • 在 ANH 里更重要：ANH 的包管理器、工作区初始化、字数统计、角色索引、本地数据都依赖工作区根目录。

资源管理器怎么用

资源管理器就是左边文件树。你在这里最常做的事有：

  • 新建文件：右键文件夹，选择新建文件。
  • 新建文件夹：右键文件夹，选择新建文件夹。
  • 拖动移动：把文件拖到别的目录。
  • 重命名：选中文件按 F2。
  • 删除：按 Delete 或右键删除。
  • Reveal in File Explorer：在系统资源管理器里定位当前文件。

右键文件夹还能直接“Open in Integrated Terminal”，这会让终端从该目录打开，非常方便。

Open Editors 是什么

资源管理器顶部通常有一个 Open Editors 区域，显示当前已经打开的标签页。它不是磁盘里的真实文件夹，只是“当前会话里打开过的编辑器列表”。

如果你开了很多章节文件，想快速切回刚才那几个文件，这里很好用。

Quick Open：最快的开文件方式

按 Ctrl+P 打开 Quick Open。它是很多老用户真正的主入口。

  • 输入文件名：直接模糊匹配，例如输入 chap12。
  • 连续按 Ctrl+P：在最近打开的文件之间切换。
  • 选中后按右箭头：在后台继续打开多个文件。
  • 配合分屏：在想放入的编辑器组里先点一下，再用 Quick Open 打开文件。
如果你项目里文件特别多，Quick Open 往往比在树里一层层展开快得多。

当前文件内搜索和替换

  • Ctrl+F：当前文件查找。
  • Ctrl+H：当前文件替换。
  • 向上/向下：跳下一个或上一个结果。
  • 区分大小写、全词、正则：查找框右侧有开关。

如果你只是想在一章里替换某个称呼或地名，先用文件内搜索，不要急着全局替换。

全局搜索：查整个工作区

按 Ctrl+Shift+F 打开全局搜索。它会查当前工作区下的所有相关文件。

  • 搜索角色名：查某个角色在多少章节出现。
  • 搜索设定词：查某个组织名、地点名是否前后统一。
  • 搜索标题：快速定位章节。
  • 批量替换：统一改名时很有用。

包含与排除路径怎么用

全局搜索面板里有“要包含的文件”和“要排除的文件”。这是控制搜索范围的关键。

  • 只搜正文：例如填 novel/**/*.md。
  • 只搜设定：例如填 novel-helper/**/*.md。
  • 排除缓存：例如填 **/node_modules/** 或别的输出目录。

这套规则和 glob 匹配有关，适合中大型项目。新手如果暂时不熟，可以先只用搜索框，后面再学范围限制。

正则搜索什么时候有用

当你不是找“某个固定词”，而是找“某一类模式”时，用正则搜索：

  • 找所有章节标题。
  • 找某种括号写法。
  • 找连续空行或半角空格问题。
  • 找形如“第十二章”这种标题格式。

不过如果你还不熟正则，先用普通搜索就够了。ANH 里已经有专门的 正则表达式入门。

Outline 和 Breadcrumbs：长文档导航神器

  • Outline：当前文件结构树，Markdown 会按标题层级显示。
  • Breadcrumbs：编辑器顶部路径导航，也能显示符号路径。

写长篇大纲或设定文档时，如果你已经用了清晰的 Markdown 标题层级，这两个功能会极大降低迷路概率。

Timeline：找回历史版本

资源管理器底部的 Timeline 可以看某个文件的历史，包括：

  • 本地历史：你保存过的历史版本。
  • Git 历史：如果项目纳入 Git，就能看提交记录。

如果你误删了一段内容，除了撤销和 Git 之外，Timeline 的本地历史也经常能救命。

Explorer 过滤与隐藏

官方文档里很强调两个设置：

"files.exclude": {
  "**/.git": true,
  "**/node_modules": true
},
"search.exclude": {
  "**/node_modules": true
}
  • files.exclude：控制资源管理器里看不看见。
  • search.exclude：控制全局搜索要不要跳过。

这两个很容易混淆。你觉得“树里太乱”，用 files.exclude；你觉得“搜索结果太脏”，用 search.exclude。

Explorer 高级导航

官方文档提到，树视图本身就支持过滤。焦点在 Explorer 时，按 Ctrl+Alt+F 可以打开过滤框，快速定位文件或目录。

这对多层目录的小说项目很实用，比如你知道文件名里有“番外”或“设定”，但不记得放在哪层包里。

文件预览、正式标签、固定标签

  • 预览标签：单击文件查看时使用，适合浏览。
  • 正式标签：双击文件或开始编辑后形成，适合长期停留。
  • 固定标签：把重要文件钉住，避免被误关。

写作时推荐把“当前章节”“总大纲”“角色总表”这类文件固定标签，其余用预览浏览。

Quick Open 的其他模式

Quick Open 不只是开文件：

  • Ctrl+P：按文件名开文件。
  • Ctrl+Shift+O：跳到当前文件符号。
  • Ctrl+T：跳到整个工作区的符号。
  • Ctrl+G：跳到指定行。

在 Markdown 中，Ctrl+Shift+O 往往直接就是“跳到某个标题”。这对超长大纲非常高效。

本地历史与脏写冲突

官方 Tips & Tricks 还特别提到“Preventing dirty writes”。意思是：如果磁盘上的文件在 VS Code 外部被改过，VS Code 会阻止你直接保存覆盖，并提供对比界面。

这在同时使用外部同步工具、脚本、Git 切分支时尤其重要。看到保存冲突提示时，不要机械点掉，先看左边磁盘版本、右边编辑器版本到底谁更新。

多选、比较与批量操作

  • Ctrl 选择多个文件：做批量拖动、删除、比较。
  • Shift 选择范围：连续多选。
  • Compare Selected：对比两个选中的文件。

如果你经常保留多个导出稿或多版章节，直接在 Explorer 里比较两个文件会比复制到外部工具更顺手。

和 ANH 的边界怎么理解

  • 资源管理器：显示真实文件系统。
  • ANH 包管理器：显示 ANH 识别出来的资源与常用功能入口。
  • 写作资源管理器：更偏正文和统计。

所以“找真实文件、重命名目录、处理 .vscode 配置、看隐藏文件”时，优先回到 VS Code 原生资源管理器；“找角色库和设定资源”时，再用 ANH 视图。
