这篇文档解决什么问题

这不是“正则着色功能说明”，而是一篇专门讲正则表达式怎么读、怎么写、怎么在 ANH 里落地的入门文档。整篇都围绕工作区初始化时自动创建的 regex-patterns.json5 展开，用那四条默认规则做完整示例。

先看结论：初始化自带的 4 条规则

规则名 正则 抓什么 为什么这样写
中文对话 "[^"]*" 英文双引号里的内容 从 " 开始，到下一个 " 结束，中间允许出现任意数量的“非双引号字符”
中文对话 2 「[^」]*」 角引号里的内容 思路和双引号完全一样，只是把边界字符换成了 「 与 」
中文思考 '[^']*' 单引号里的内容 利用单引号作为左右边界，中间不允许再出现单引号
书名号 《[^》]*》 书名号里的内容 与前面三条是同一个模板：左边界 + 非右边界字符若干 + 右边界

图 1：一条正则规则在 ANH 里怎么工作

你写的正文
   ↓
JavaScript RegExp 逐段扫描整篇文本
   ↓

   ↓

在 ANH 里，priority 是数字越小越优先。这和有些系统“数字越大越高”相反，写规则时不要搞反。

图 2：把一条默认规则拆开读

以 「[^」]*」 为例：

片段 读法 作用
「 字面量字符 要求匹配必须从左角引号开始
[^」] 字符类取反 匹配“不是右角引号”的任意单个字符
* 重复 0 次或多次 允许中间内容为空，也允许有很多字符
」 字面量字符 要求在右角引号结束

图 3：为什么不是 「.*」

写法 结果 问题
「.*」 从第一个 「 吞到最后一个 」 容易过度匹配
「[^」]*」 严格停在最近的右角引号 更适合做着色规则

你真正需要记住的 6 类语法

类别 写法 含义 在默认规则里的例子
字面量 「 」 《 就匹配这个字符本身 《[^》]*》
字符类 [abc] 三选一 如果你想匹配多种收尾符号时会用到
取反字符类 [^」] 匹配“不是某字符”的任意字符 四条默认规则都在用
量词 * + ? {n,m} 控制重复次数 * 表示 0 次或多次
边界 ^ $ \b 限制开头、结尾或单词边界 做章节标题、整行匹配时常用
分组/或 (...) | 把多个片段当一组，或在多个模式中选一个 例如同时支持两种引号

图 4：最常用量词速查

量词 含义 例子 适合用在哪
* 0 次或多次 [^」]* 允许空内容，如 「」
+ 1 次或多次 [^」]+ 要求引号内至少有 1 个字符
? 0 次或 1 次 第?一章 可有可无的部分
{n,m} 最少 n 次，最多 m 次 \d{1,3} 限制长度

图 5：从需求写到表达式的最短路径

先问自己 3 个问题：
1. 左边界是什么？     例如 「
2. 右边界是什么？     例如 」
3. 中间不能出现谁？   例如 不能再出现 」

于是得到模板：
左边界 + [^右边界]* + 右边界

例子：
「 + [^」]* + 」  →  「[^」]*」
《 + [^》]* + 》  →  《[^》]*》

Markdown 和 JSON5 写法有什么区别

场景 Markdown 规则文件 JSON5 规则文件
写 \d+ \d+ "\\d+"
写引号规则 "[^"]*" '"[^\"]*"' 或等价安全写法
推荐程度 复杂正则更推荐 适合程序生成或统一结构化管理

最容易踩的 4 个坑

  • 把 . 当成“任意字符但会自动停下”：不会，它通常会尽量吞更多内容
  • 忘了转义：在 JSON5 里，反斜杠经常要写成两个
  • 把 priority 写反：ANH 里数字越小越优先
  • 一上来就写复杂表达式：先把左右边界写对，再逐步加条件

ANH 里的执行模型

ANH 的正则着色底层使用 JavaScript RegExp。正则角色会用 new RegExp(role.regex, role.regexFlags || 'g') 在整篇文本上执行，然后再和普通角色命中一起做范围冲突处理。

字段 真实含义 你该怎么用
regex JavaScript 正则 pattern 写匹配规则本体
regexFlags JavaScript flags 着色规则通常至少带 g
priority 数值排序键 越小越先占用范围
color / style Decoration 样式 决定命中后怎样显示

图 6：推荐先学会的 flags

flag 作用 在 ANH 着色里常不常用 例子
g 全局匹配 几乎必带 「[^」]*」 + g
i 忽略大小写 匹配英文字段时常用 todo + gi
m 让 ^ / $ 对每一行生效 匹配章节标题时常用 ^第.+章$ + gm
s 让 . 可以跨换行 只在确实要跨段落时用 开始.*结束 + gs
u 启用 Unicode 语义 要用 Unicode 属性类时再带 \p{L}+ + gu

套进去：

案例 1：如果你想匹配章节标题

需求：整行形如“第十二章 雨夜”“第 3 章 重逢”的标题。

步骤 写法 说明
限定从行首开始 ^ 避免匹配到正文中间
固定前缀 第 字面量
数字部分 [一二三四五六七八九十百千\d]+ 支持中文数字和阿拉伯数字
固定后缀 章 标题级别词
后面允许有标题正文 .* 比如“雨夜”“重逢” 
推荐写法：
^第[一二三四五六七八九十百千\d]+章.*$

推荐 flags：
gm

案例 2：如果你想同时匹配两种对话引号

(?:"[^"]*"|「[^」]*」)

这里的关键是：

  • | 表示“二选一”
  • (?: ... ) 是非捕获分组，只是把两个分支包起来，不额外记组

案例 3：如果你不想让规则贪太多

写法 行为
.* 贪婪，通常会尽量吃更多
.*? 懒惰，通常会尽量早点停
[^」]* 最稳妥，直接规定“不能吃到右边界”

推荐工作流

  1. 先用“边界版模板”写出第一版：左边界 + 中间内容 + 右边界。
  2. 先在 Markdown 规则文件里调通，再决定要不要写成 JSON5。
  3. 只有确实需要时，再引入分组、或、断言、懒惰量词。
  4. 多条规则可能重叠时，主动规划 priority，不要靠运气。
这篇文档的术语和 JavaScript 正则语义按 MDN/ECMAScript 口径整理，同时结合了 ANH 当前实现：规则使用 JavaScript RegExp 执行，标志位如 g、m、s、u 的行为与 JS 一致。
