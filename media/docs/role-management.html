如何创建和管理角色

ANH 最推荐的创建角色方式是写 Markdown。就像写普通文档一样，用标题和段落来组织角色信息。

Markdown 角色格式

结构很简单：

  • 每个角色用一个二级标题 ## 角色名
  • 角色的属性用三级标题 ### 属性名
  • 属性内容写在三级标题下面的段落里

必填字段

每个角色至少需要两个字段：

  • 名称（name）— 角色的名字，必填
  • 类型（type）— 决定角色的用途，必填（不填默认为"词汇"）

角色类型说明

ANH 以 type 字段区分资料用途。主角、主要角色、反派、配角、联动角色是常用人物类型；敏感词、词汇、正则表达式有额外的专用行为。你也可以自定义任意类型。

  • 主角 — 主要角色，享有高亮、补全、引用等全部能力
  • 主要角色 / 反派 — 常用人物分类，能力与主角、配角一致
  • 配角 — 次要角色，与主角能力相同
  • 联动角色 — 跨作品角色，用于引用其他作品的角色
  • 敏感词 — 需要替换的词汇，配合"修复"字段提供替换建议
  • 词汇 — 世界观术语、专有名词
  • 正则表达式 — 自定义着色规则，需配合"正则"字段使用

可选的常用属性

  • 颜色 — 给角色名上色，比如 #FF6B6B 是珊瑚红
  • 别名 — 角色的昵称、外号等
  • 描述 — 角色简介
  • 外貌 — 长相、穿着等
  • 技能 — 能力、特长

一个完整的例子

# 主角人物

## 博丽灵梦

### 类型
主角

### 颜色
rgb(255, 30, 64)

### 别名
灵梦
Reimu

### 描述
乐园的巫女，负责解决异变。

### 外貌
- 发色：黑色
- 服装：红白巫女服

### 技能
1. 飞行程度的能力
2. 灵力操纵

其他格式

  • JSON5 — 一种带注释的表格格式，字段最完整，适合用编辑器管理
  • OJSON5 — JSON5 角色库的专用扩展名，优先用角色卡编辑器打开
  • CSV — 表格格式，适合从 Excel 批量导入
各种文件格式的完整结构、字段和示例见文档中心的"文件格式指南"。

可视化角色卡编辑器

如果你不想手写，可以用可视化编辑器：

  1. 右键 .json5 角色文件
  2. 选择 "Open With" → "角色 JSON5 编辑器"
  3. 在表单里填写角色信息，保存即可

新版角色卡编辑器提供表格化界面，并保留经典编辑路径。工具栏可切换字段显示名语言（中文、英文、日文）或显示原始 JSON key；这只影响界面展示，保存时仍写回真实字段名。编辑器还内置随机角色生成器和拼音 / 罗马字查询键候选弹窗，生成或选择后可直接追加到当前角色字段。

文件命名建议

推荐用这些名字，ANH 会自动识别：

  • character-gallery.md / character-gallery.json5
  • my-character.md / my-character.json5

推荐格式：Markdown

ANH 的推荐角色格式是 Markdown。它使用自然的 Markdown 结构来组织角色数据，既可直接阅读，又能被插件完整解析。

结构规范：

  • 文件顶层可选 # 角色库 作为标题
  • 每个角色是一个二级标题 ## 角色名
  • 角色的字段使用三级标题 ### 字段名 表示
  • 字段标题支持中文别名，如 ### 颜色 等价于 ### color
  • 字段内容写在三级标题下方的正文段落中

完整字段别名映射（不区分大小写）：

  • 基础：名称/name、描述/description、类型/type、UUID/uuid、颜色/color、从属/affiliation、别名/aliases/alias、样式/style
  • 样式子字段：背景色/backgroundColor、粗体/bold、斜体/italic、删除线/strikethrough、下划线/underline
  • 扩展：年龄/age、性别/gender、职业/occupation、性格/personality、外貌/appearance、背景/background、关系/relationship/relationships、技能/skill/skills、弱点/weakness/weaknesses、目标/goal/goals、动机/motivation、恐惧/fear/fears、秘密/secret/secrets、台词/quote/quotes、备注/note/notes、标签/tag/tags、分类/category、等级/level、状态/status、位置/location、出身/origin、家庭/family、教育/education、爱好/hobby/hobbies
  • 修复：修复/fixes/fixs/fix、替换/replacements/replacement
  • 查询键：拼音查询键/拼音检索键、罗马字查询键/罗马字检索键、拼写查询键/拼写检索键
  • 正则：正则/regex/pattern、正则标志/regexFlags/flags/匹配标志
  • 其他：优先级/priority、分词过滤/wordSegmentFilter/分词筛选

示例：

# 主角人物

## 博丽灵梦

### 类型
主角

### 颜色
rgb(255, 30, 64)

### 别名
灵梦
Reimu

### 描述
乐园的巫女，负责解决异变。

### 外貌
- 发色：黑色
- 服装：红白巫女服

### 技能
1. 飞行程度的能力
2. 灵力操纵

JSON5 格式

JSON5 格式字段最完整，适合需要程序化生成或与外部工具集成的场景：

  • 文件内容必须是一个JSON5 数组，每个元素是一个角色对象
  • 也兼容对象格式（键为角色名）和含 roles / characters 键的对象
  • 支持中文键名：名称、类型、描述、颜色、别名、修复、优先级、分词过滤、正则、正则标志、样式、拼音查询键、罗马字查询键、拼写查询键 等
  • 扩展名 .json5 或 .ojson5（后者会被优先识别为外部角色标记）
[
  {
    name: "博丽灵梦",
    type: "主角",
    aliases: ["灵梦", "Reimu"],
    color: "#E60033",
    description: "乐园的巫女",
    priority: 10,
    wordSegmentFilter: true
  }
]

CSV 格式

CSV 适合从 Excel 批量导入。支持分隔符自动检测（逗号/分号/制表符），表头支持中文别名：

name,description,aliases,type,color
博丽灵梦,乐园的巫女,"灵梦,Reimu",主角,#E60033
雾雨魔理沙,普通的魔法使,"魔理沙,Marisa",主角,#FFD700

布尔字段支持 true/1/yes/on/是（真），false/0/no/off/否（假）。列表字段（aliases、fixes）可用分号、逗号、斜杠分隔。

角色卡编辑器（GUI）

ANH 提供了可视化角色卡编辑器，支持多种编辑路径：

  • 表格化角色卡 — 默认推荐的新界面，把基础字段、查询键、样式、扩展字段和自定义字段收敛到更紧凑的表格/分组控件中
  • 经典角色卡模式 — 旧版可视化表单，适合迁移期保留原有操作习惯
  • 代码编辑器模式 — 内置 Monaco Editor，直接编辑 JSON5 源码
  • Markdown 模式 — 内置 Vditor，直接编辑 Markdown 源码

编辑器辅助能力：

  • 字段显示名 — 可在中文、英文、日文显示名和原始 JSON key 之间切换；保存时不改变真实字段名
  • 查询键候选 — 可向扩展后端请求拼音 / 罗马字候选，多选后批量追加到当前查询键字段
  • 随机角色生成器 — 可按文化背景、性别、风格、角色类型、从属和颜色生成角色草案，并补充拼写、罗马字和适用的拼音查询键
  • 样式合并编辑 — 前景色、背景色、粗体、斜体、删除线和下划线集中在同一组控件中编辑

打开方式：

  • 右键 .json5 角色文件 → "Open With" → "角色 JSON5 编辑器"
  • 在左侧"所有角色"面板中点击某个角色（需开启设置 andrea.roleJson5.openWithRoleManager）

编辑器支持的字段：

  • 基础字段 — 名称、类型（下拉选择或自定义）、UUID（只读）、前景色/背景色（输入框+颜色选择器）、文本样式开关（粗/斜/删/下划）、优先级、描述、从属、别名/拼音/罗马字/拼写查询键（逐行输入，回车添加）、正则表达式专属字段、修复词、分词过滤开关
  • 扩展字段 — age、gender、occupation、personality、appearance、background、relationship、skill、weakness、goal、motivation、fear、secret、quote、note、tag、category、level、status、location、origin、family、education、hobby
  • 自定义字段 — 任意键值对，支持 string/number/boolean/string[] 四种类型

编辑器按 VS Code 的 files.autoSave 策略执行。当 autoSave 开启时修改自动写回磁盘；当 autoSave=off 时，修改会形成 dirty 状态，需要手动按 Ctrl+S 保存。

文件命名

角色库文件推荐使用以下命名：

  • character-gallery.md / character-gallery.json5
  • *_character.md / *_character.json5

可通过设置 AndreaNovelHelper.rolesFile 自定义默认角色文件路径（默认 novel-helper/character-gallery.json5）。

角色类型与必填字段

每个角色必须包含 name 和 type 两个字段。常用类型及其特殊行为：

  • 主角 / 主要角色 / 反派 / 配角 / 联动角色 — 角色人物类型，用于角色名高亮、自动补全、引用查找
  • 敏感词 — 标记需要替换的词汇。专属字段：fixes（修复建议数组），匹配到时触发诊断标记和 Quick Fix
  • 词汇 — 世界观术语和专业名词，与角色共享补全/高亮/跳转能力
  • 正则表达式 — 自定义着色规则。专属字段：regex（正则模式）+ regexFlags（标志，如 g）

除内置类型外，type 字段接受任意自定义字符串（如 "炼金顾问"），自定义类型的角色在树视图中按自定义类型名分组。

角色类型排序

当前文章角色和全部角色视图都支持自定义类型排序。相关设置是 AndreaNovelHelper.docRoles.typeOrder 和 AndreaNovelHelper.allRoles.typeOrder，默认顺序会让“主角”排在“配角”前面。未列入列表的自定义类型会排在后面，并继续按中文自然顺序排序。

推荐从“图形化快速设置 → 角色列表”编辑这个顺序。可视化编辑器支持预设、添加、删除、上移、下移和恢复默认，不需要手写 JSON 数组。

按类型查找角色

在"所有角色"树视图中，角色默认按从属分组。你可以切换为按类型分组：

  • 在树视图标题栏点击分组图标，切换为"按类型分组"后，所有角色按类型（主角、配角、联动角色、自定义类型等）归类显示
  • 敏感词、词汇、正则表达式三种特殊类型会单独归入"词汇 / 敏感词 / 正则表达式"分组

在包管理器中，展开角色文件节点可以看到其中定义的角色列表，每个角色旁显示其类型名称。

创建角色

在包管理器中右键目录节点，上下文菜单中可选择：

  • + 新建角色库 — 创建 Markdown/JSON5/CSV/TXT 格式的角色库文件，内含模板
  • + 新建角色文件 — 创建 .ojson5 格式的单个角色定义文件，包含 UUID 和示例字段

也可以通过命令面板执行 AndreaNovelHelper.createCharacterGallery 或 AndreaNovelHelper.createRoleFile。

样式字段说明

角色外观有两种写法，新版推荐 style 对象，旧版独立字段保持兼容：

// 新版推荐
style: { color: "#E60033", backgroundColor: "#FFF0F0", bold: true }

// 旧版兼容（保存时自动收敛到 style）
color: "#E60033", backgroundColor: "#FFF0F0", bold: true
Markdown 是 ANH 推荐的角色格式。它兼具可读性和完整性，用任何 Markdown 编辑器都能直接查看和修改，不需要专门的工具。
