拼写检查是什么

拼写检查（也叫"校对"）就像你的自动校对员。它会在你写作时自动扫描文字，发现可能的错别字、语法问题或不恰当的用词，并在问题处画波浪线提醒你。

两种检查方式

ANH 支持两种校对方式，你可以任选其一：

  • 规则校对 — 通过外部服务进行规则匹配，速度快但需要有配套后端
  • AI 校对 — 直接调用大语言模型（如 GPT、Claude 等），智能程度更高，只需配置 API 密钥

如何开启

  1. 打开 ANH 设置
  2. 找到"拼写检查"分类
  3. 开启总开关 typo.enabled
  4. 选择模式（macro/llm）或开启 clientLLM

AI 校对配置（推荐小白使用）

  1. 开启 typo.clientLLM.enabled
  2. 填写 API 地址（如 https://api.openai.com/v1）
  3. 填写 API 密钥
  4. 填写模型名称，或在图形化快速设置中使用模型选择器从兼容 API 拉取模型列表

使用方式

  • 打开文档时自动扫描
  • 编辑时自动更新
  • 点击波浪线或 💡 灯泡 → 选择"替换为：xxx"

角色名不会被误改

校对前 ANH 会把文档中的角色名传给 AI，告诉它"这些名字不要改"。

校对系统架构

ANH 的校对系统由插件内的调度层和外部检测服务共同组成。插件负责文档分段、缓存管理、结果展示；实际的检测逻辑由外部 HTTP 服务或客户端直连 LLM 完成。

两种检测路径

校对系统有两条独立的路径，通过不同配置项控制：

1. 服务端检测（由 typo.mode 控制）

  • macro 模式 — 调用外部 HTTP 服务的 POST /correct 接口，由服务端执行规则检测
  • llm 模式 — 调用外部 HTTP 服务的 POST /correct/llm 接口，由服务端代理调用大语言模型

服务端地址由 AndreaNovelHelper.typo.service.baseUrl 配置，默认 http://127.0.0.1:8001。

2. 客户端直连 LLM（独立开关）

  • 启用 AndreaNovelHelper.typo.clientLLM.enabled 后，插件会直接调用 LLM API，绕过服务端
  • 支持 OpenAI 兼容格式和 Gemini 原生 API
  • 启用后优先级高于服务端检测

检测流程

  1. 文档分段 — 按空行分成段落，再按 。！？!? 和换行符分成句子
  2. 段落哈希 — 使用 FNV-1a 32-bit 计算段落哈希，作为缓存 key
  3. 缓存命中检查 — 已扫描且未变更的段落直接跳过
  4. 分批发送 — 缺失缓存的段落按 batchSize（默认 30 句）分块发送给检测器
  5. 并发限流 — 受 docConcurrency（默认 3）限制，避免同时发送过多请求
  6. 结果解析 — 服务端返回完整 JSON；客户端 LLM 在流式响应中实时解析，发现 corrections 数组即返回中间结果
  7. 生成诊断 — 将结果转为 vscode.Diagnostic，在编辑器中显示波浪线标记和 Quick Fix

Prompt 与请求格式

LLM 检测的系统提示词来自 resources/typo_llm_prompt.txt，要求模型严格输出 JSON 对象 {"corrections": [...]}。User prompt 包含：

  • texts — 待检测句子数组
  • context — 段落合并后的上下文（用 —— 段落分隔 —— 分隔）
  • known_roles — 文档中的角色名列表（用于抑制误报）
  • doc_uuid — 文档标识

角色名误报抑制

检测前会将文档中的角色名（排除"正则表达式"和"敏感词"类型）作为 known_roles 传给检测器，要求模型不要纠正这些名称。

插件层面的抑制由 AndreaNovelHelper.typo.suppressRolesMode 控制：

  • roleNameExact — 错字文本与角色名完全相等时抑制（默认）
  • regexContain — 正则表达式角色完全包含整段时抑制
  • nonSensitiveIntersect — 与任意非敏感词角色范围相交则抑制
  • none — 不抑制

注意：当 typo.mode === 'llm' 或 clientLLM.enabled === true 时，插件层面的抑制被强制禁用（设为 none），完全依赖 LLM 的 known_roles 提示。

缓存机制

  • 内存缓存 — 以文档 URI → 段落哈希 → 扫描结果的形式存储在 Map 中
  • LRU 淘汰 — 最大文档数由 typo.maxDocs 控制（默认 10），优先淘汰已关闭的文档
  • 持久化缓存 — 可选保存到 <workspace>/novel-helper/typo/data/{docUuid}.json，由 typo.persistence.enabled 控制，默认关闭
  • 自动清理 — typo.persistence.autoCleanup 默认开启，maxAgeDays 默认 30 天
  • 防抖保存 — 持久化写入有 500ms 防抖，内容未变则跳过

自动扫描触发条件

  • 打开文档 — onDidOpenTextDocument，需开启 typo.autoIdentifyOnOpen
  • 编辑变更 — onDidChangeTextDocument，需开启 typo.autoScanOnChange
  • 白空格过滤 — 仅输入空白/换行时不触发重新扫描，只刷新诊断显示位置
  • 防抖 — 默认 400ms；启用 AndreaNovelHelper.timeStats.typoDelay.enabled 后使用 timeStats.typoDelay.windowMs（默认 5000ms）

高亮装饰

  • AndreaNovelHelper.typo.enableHighlight — 启用标黄背景装饰，默认关闭
  • AndreaNovelHelper.typo.highlightColor — 标黄颜色，默认 #fff3a3
  • AndreaNovelHelper.typo.applyPartialDecorationsImmediately — 即时高亮部分结果，默认 false

配置项

  • AndreaNovelHelper.typo.enabled — 校对总开关
  • AndreaNovelHelper.typo.mode — 服务端检测模式：macro / llm
  • AndreaNovelHelper.typo.service.baseUrl — HTTP 校对服务基地址（默认 http://127.0.0.1:8001）
  • AndreaNovelHelper.typo.clientLLM.enabled — 启用客户端直连 LLM
  • AndreaNovelHelper.typo.clientLLM.apiBase — 客户端 API 基地址
  • AndreaNovelHelper.typo.clientLLM.apiKey — API 密钥
  • AndreaNovelHelper.typo.clientLLM.model — 模型名称
  • AndreaNovelHelper.typo.clientLLM.temperature — 温度参数
  • AndreaNovelHelper.typo.clientLLM.enableThinking — 启用思考过程
  • AndreaNovelHelper.typo.clientLLM.thinkingProvider — 思考供应商（auto/glm/deepseek/qwen/custom）
  • AndreaNovelHelper.typo.clientLLM.qwenThinkingMethod — Qwen 思考方式（parameter/suffix）
  • AndreaNovelHelper.typo.clientLLM.geminiThinkingBudget — Gemini 思考预算
  • AndreaNovelHelper.typo.clientLLM.geminiApiFormat — Gemini API 格式（openai/native）
  • AndreaNovelHelper.typo.llm.model — 服务端 LLM 代理的模型名称
  • AndreaNovelHelper.typo.llm.apiKey — 服务端 LLM 代理的 API 密钥
  • AndreaNovelHelper.typo.llm.apiBase — 服务端 LLM 代理的 API 基地址
  • AndreaNovelHelper.typo.autoIdentifyOnOpen — 打开文件时自动扫描
  • AndreaNovelHelper.typo.autoScanOnChange — 编辑时自动扫描
  • AndreaNovelHelper.typo.batchSize — 批次大小（默认 30）
  • AndreaNovelHelper.typo.docConcurrency — 文档并发数（默认 3）
  • AndreaNovelHelper.typo.docGroupSize — 文档分组大小（默认 3）
  • AndreaNovelHelper.typo.timeoutMs — 超时时间（默认 30000）
  • AndreaNovelHelper.typo.maxDocs — 内存缓存最大文档数（默认 10）
  • AndreaNovelHelper.typo.keepCacheOnClose — 关闭文档后保留缓存（默认 true）
  • AndreaNovelHelper.typo.enableHighlight — 启用标黄背景装饰
  • AndreaNovelHelper.typo.highlightColor — 标黄颜色（默认 #fff3a3）
  • AndreaNovelHelper.typo.warningLevel — 诊断级别（error/warning/information/hint）
  • AndreaNovelHelper.typo.suppressRolesMode — 角色名误报抑制模式
  • AndreaNovelHelper.typo.persistence.enabled — 启用持久化缓存
  • AndreaNovelHelper.typo.persistence.autoCleanup — 自动清理过期数据
  • AndreaNovelHelper.typo.persistence.maxAgeDays — 数据保存天数（默认 30）
  • AndreaNovelHelper.typo.debug.llmTrace — LLM 请求/响应调试日志
  • AndreaNovelHelper.typo.debug.serverTrace — 服务端 HTTP 调试日志
  • AndreaNovelHelper.typo.debug.compactTrace — 压缩调试输出
  • AndreaNovelHelper.typo.debug.traceMaxLen — 调试日志最大长度

使用方式

  • 命令面板：
    • andrea.typo.scanDocument — 扫描未扫描段落
    • andrea.typo.rescanDocument / rescanCurrentFile — 强制全量重扫（清除缓存）
    • andrea.typo.stopAllRequests — 中止所有活动请求
    • andrea.typo.quickSettings — 打开快速设置面板
  • 状态栏 — 左下角显示 Typo macro/llm，点击打开快速设置面板
  • Quick Fix — 点击编辑器内的波浪线标记或 💡 灯泡，选择 🔧 替换为: xxx

日志调试

开启调试后可查看 Output 面板中的 Andrea Typo LLM 通道：

  • typo.debug.llmTrace — 查看完整的 LLM 请求/响应（含流式输出）
  • typo.debug.serverTrace — 查看服务端 HTTP 请求/响应概要
  • typo.debug.compactTrace — 压缩为单行输出

注意事项

  • 插件不包含内置规则引擎，规则检测依赖外部 HTTP 服务。如需使用 macro 模式，需自行部署配套后端
  • 客户端 LLM 和服务端 LLM 是两套独立配置，启用 clientLLM.enabled 后会绕过服务端
  • 持久化缓存默认关闭，开启后会在 novel-helper/typo/data/ 目录下生成缓存文件
  • 错别字延迟扫描配置在 timeStats.typoDelay 命名空间下，不在 typo.delay 下
规则校对（macro）的"规则"不在插件内，而在外部 HTTP 服务中。如果你无法部署后端服务，建议直接使用客户端 LLM 模式（clientLLM.enabled），只需配置好 API 密钥即可。
