这一组文档在解决什么问题

ANH 的角色系统不是一个“人物名单小功能”，而是整个资源模型的核心。现在把角色相关文档独立成类，就是为了把角色建模、文件格式、全局面板、补全、关系图、时间线这些原本分散的话题串成完整路径。

建议阅读顺序

  1. 一切皆角色：先理解 ANH 为什么把很多资源统一抽象成 role。
  2. 角色管理：掌握字段、类型、继承、派生、组合等核心规则。
  3. roles.md：看最推荐的 Markdown 角色写法。
  4. character-gallery.*：看 JSON5、CSV 等角色库文件的场景和边界。
  5. 全局角色面板：学会集中查看、筛选和 Raw 编辑。
  6. 角色补全：把角色数据接回正文写作。
  7. 角色关系图、角色关系图谱、时间线：进一步处理关系和事件结构。

先记住的核心观念

  • 角色系统不只存人物，也能承载词汇、敏感词、正则规则等“可识别资源”。
  • Markdown 是最推荐的人手维护格式，但不是唯一格式。
  • 全局角色面板看的是工作区里已加载的统一视图，不是某一个文件的局部表格。
  • 关系图和时间线不是装饰品，它们是角色系统往结构化创作继续延伸的能力。

为什么角色系统要单独成类

因为角色系统同时覆盖了四层事情：

  • 数据模型：字段、类型、别名、查询键、继承和派生。
  • 文件格式：Markdown、JSON5、CSV、OJSON5。
  • 交互界面：角色卡编辑器、全局角色面板、图谱、时间线。
  • 写作联动：高亮、补全、引用、预览、导出。

如果这些内容继续分散在“核心概念”“项目文件”“高级功能”“写作辅助”里，用户会知道 ANH 有很多入口，但不知道它们其实都围着同一套角色模型在工作。

推荐的建模顺序

  1. 先把最重要的人物和世界观名词建起来。
  2. 再补别名、颜色、类型和必要字段，让识别与补全稳定。
  3. 再决定哪些关系应该显式建模，哪些只留在正文里。
  4. 最后再引入关系图、时间线和更复杂的继承派生结构。
