这一组文档在解决什么问题

很多 ANH 用户不是不会写小说，而是不熟 VS Code 这套工作台本身：不知道面板和侧边栏的区别，不知道设置写到哪里，不知道为什么 Git、搜索、终端、工作区会一起工作。

所以这里不再只放一页概述，而是把 VS Code 基础拆成一个完整大类。结构主要参考 VS Code 官方文档的 Getting Started、User Interface、Settings、Keybindings、Terminal、Source Control 等章节，但会用更贴近写作和 ANH 的语境重写。

建议阅读顺序

  1. 界面与布局：先搞清活动栏、侧边栏、编辑器、面板、状态栏各是什么。
  2. 文件、标签与全局搜索：解决“怎么找文件、找内容、找历史”。
  3. 编辑器与高效编辑：解决“怎么改字更快”。
  4. 终端、任务与工作区：解决“项目环境怎么在 VS Code 里运转”。
  5. 设置、配置与扩展：解决“设置到底存在哪里、怎么覆盖”。
  6. 命令面板与快捷键：解决“找不到功能时怎么办”。

读完基础之后建议继续补哪几类

  • 扩展与市场：解决“扩展到底从哪装、不同编辑器为什么不一样”。
  • Git 与版本管理：解决“怎么在 VS Code 和终端之间建立统一版本流”。
  • Markdown 与格式：解决“正文怎么写、资源文件该选什么格式”。
  • 角色系统：解决“角色、关系、时间线和补全是怎么串起来的”。

如果你只想先会最少的东西

那就先把下面 7 件事练熟：

  • 打开文件夹，而不是只打开单个文件。
  • Ctrl+Shift+P 打开命令面板。
  • Ctrl+P 快速打开文件。
  • Ctrl+Shift+F 全局搜索。
  • Ctrl+` 打开终端。
  • Ctrl+, 打开设置。
  • Ctrl+Shift+G 打开源代码管理。

只要这 7 件事熟了，ANH 绝大部分功能你都能顺利落地。

和 ANH 的关系怎么理解

可以把 VS Code 当成底层写作工作台，ANH 是叠在上面的小说工作流增强层：

  • VS Code 负责：文件树、搜索、分屏、终端、Git、设置、快捷键、扩展系统。
  • ANH 负责：项目初始化、角色/词汇资源、写作统计、预览、关系图、快速设置、文档中心。

如果 VS Code 基础不熟，你会觉得 ANH“功能很多但入口混乱”；一旦把底层工作台用顺，ANH 的所有入口就会变得自然。

这里和其他文档的边界

  • 这组文档讲 VS Code 原生能力。
  • 插件设置 讲的是 ANH 自己贡献的设置。
  • 快速设置 讲的是 ANH 面向写作者做的快捷入口。
  • Git 与 VS Code 集成 更偏把 Git 工作流映射到 ANH 项目里。

这组内容为什么要独立成大分类

之前把 VS Code 基础压成一页，信息密度太低，只能解决“我大概知道哪里是搜索、哪里是 Git”。但用户真正卡住的问题往往更具体：

  • 为什么有些设置是全局生效，有些只影响当前项目？
  • 为什么文件树能隐藏目录，但搜索还是会搜到？
  • 为什么快捷键有时候生效，有时候不生效？
  • 为什么 VS Code 里的 Git 和我终端里的 Git 看起来像两套东西？
  • 为什么同一个项目在另一台电脑打开布局和设置会不一样？
  • 为什么 AI、终端、任务、工作区信任会互相影响？

这些都已经超出“单页新手导览”的承载范围，所以现在拆成专题页。

官方资料映射关系

为了避免这组文档只是经验帖，结构是按官方资料体系收敛的：

  • User Interface → 对应“界面与布局”。
  • Getting Started → 对应整个学习路径和基础动作。
  • Settings → 对应“设置、配置与扩展”。
  • Keybindings → 对应“命令面板与快捷键”。
  • Terminal Basics → 对应“终端、任务与工作区”。
  • Tips and Tricks → 分散吸收进文件导航、编辑效率、分屏和布局章节。

其中 Source Control 相关内容现在不再混挂在“VS Code 基础”里，而是拆进独立的 Git 与版本管理 分类，避免“工具概念”和“编辑器入门”继续混在一起。

针对写作者的阅读建议

  • 纯写作用户：优先看界面、文件搜索、设置、Git。
  • 会做一点脚本或自动化：把终端、任务、快捷键也读掉。
  • 多设备切换写作：重点补 Settings Sync、Profile、Git 同步。
  • 大量使用 AI 或扩展：重点补命令面板、键盘冲突、工作区信任。

你读完这组之后应该达到什么状态

  1. 知道每个主要 UI 区域在干什么。
  2. 知道工作区、设置、扩展、任务分别落到哪里。
  3. 知道怎样在不离开 VS Code 的情况下完成绝大多数日常操作。
  4. 知道 ANH 和 VS Code 原生能力的边界，不再把所有问题都归到 ANH 头上。
如果你现在最具体的痛点是“我老是找不到入口”，先读 命令面板与快捷键；如果痛点是“项目看起来很乱”，先读 文件、标签与全局搜索。
