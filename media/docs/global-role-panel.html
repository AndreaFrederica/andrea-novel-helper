全局角色面板是干什么的

全局角色面板把当前工作区里已经加载到 ANH 的角色、词汇、敏感词、正则规则等条目汇总到一个统一界面。它解决的不是“编辑某个文件的一小块”，而是“我想从全局视角快速找到某条资源并定位来源”。

什么时候该用它

  • 你忘了某个角色到底定义在哪个包或哪个文件里。
  • 你想按名称、类型、包路径、关键词快速筛选资源。
  • 你想查看角色附带的头像、插图、别名或查询键。
  • 你想直接打开原始数据，做精确修改。

现在这块面板能做什么

  • 全局筛选：按名称、类型、包、关键词收缩结果集。
  • 详情查看：直接看统一后的角色字段和值。
  • 图片预览：对本地头像或插图做 webview 可视化展示。
  • Raw：打开该条目对应的原始源文件内容进行查看和编辑。

Raw 编辑为什么重要

因为统一面板展示的是“加载后的结果”，而不是源文件的全部原貌。很多高级维护动作仍然必须回到原始文本：例如保留注释、微调层级、检查文件真实结构、处理某些还没做成表单项的字段。

草稿和保存语义

现在 Raw 编辑不是一改就立刻落盘。你在面板里修改后，只有按保存才会真正写回文件；没保存之前，它只是当前面板里的草稿。这能减少误触和半成品写回。

外部文件变化会怎样

如果源文件发生了外部变化，而且不是当前面板自己写回导致的，Raw 视图会跟着刷新或提醒你处理。这一点很关键，因为角色文件可能同时被下面几条路径修改：

  • 你直接在编辑器里改了源文件。
  • 你通过包管理器或其他编辑器改了同一份资源。
  • Git 切换分支或同步远端后，文件内容发生变化。
  • 某些自动化脚本或导入流程重写了文件。

为什么要区分“自己写回”和“外部改动”

如果不做这个区分，面板一保存就会把自己的写回也当成外部变动，导致你不断看到误报刷新。现在这层抑制逻辑的意义，就是让真正值得关注的变化浮出来，而不是把正常保存也当成冲突。

适合它做的事，不适合它做的事

  • 适合：全局查找、统一审阅、快速核对来源、做小范围精确修改。
  • 不适合：长时间大篇幅重写整份角色库；那种情况更适合直接回原始文件或专用编辑器。

图片预览命名规则

全局角色面板支持显示角色的头像和插图。图片文件需要放在角色同目录下，命名规则如下：

  • 头像：与角色同名的图片文件（如 博丽灵梦.png、博丽灵梦.jpg）
  • 插图：角色名加后缀（如 博丽灵梦_插图.png）
  • 支持格式：PNG、JPG、JPEG、GIF、WebP、SVG
  • 图片路径会记录在角色的 image 或 avatar 字段中

角色合并优先级

当同一个角色在多个文件中定义时，ANH 会按优先级合并字段。合并策略由 AndreaNovelHelper.rolePriority.strategy 控制：

  • 按文件路径 — 特定目录下的定义优先级更高
  • 按最后修改 — 最后修改的文件优先
  • 按包层级 — 包目录下的定义优先于根目录

合并时，后加载的字段会覆盖先加载的同名字段，但不会清除未定义的字段。

推荐工作流

  1. 先在全局角色面板定位条目。
  2. 确认来源文件和包路径。
  3. 需要轻量修正时用 Raw 编辑。
  4. 需要大改结构时回到原文件或专用编辑器。
  5. 完成后用角色补全、预览或图谱视图验证联动结果。
如果你想先理解底层字段和建模规则，再回来用这个面板，先读 角色管理；如果你想看 Markdown 角色文件本身怎么组织，去看 roles.md。
