本指南涵盖什么

本指南介绍两件事：用 Markdown 写小说正文和用各种格式编写角色/词汇等资源文件。ANH 同时支持 Markdown、JSON5、CSV、TXT、TOML 等多种文件格式，你可以在"包管理器"中右键目录节点选择要创建的格式。

如果你想确认某个文件该用什么扩展名、会打开哪个编辑器、能不能被当作角色库扫描，直接看本页的"角色/资源文件格式"和"自定义 XJSON5 扩展名总结"。

一、用 Markdown 写小说正文

你的小说章节文件（.md）就是标准的 Markdown 文本。ANH 的预览器会渲染 Markdown 格式，同时自动给角色名上色。以下是 ANH 预览器支持的 Markdown 语法：

标题

# 第一章 雨夜

## 第二章 重逢

### 第三节 小巷

标题在预览中会按层级显示不同大小。章节文件通常用 # 作为大标题，## 作为节标题。

加粗、斜体、删除线

**加粗文字**
*斜体文字*
***加粗斜体***
~~删除线~~

引用（对话/旁白/内心独白）

> 她站在雨中，看着远处的灯火。
> > "你还是来了。" 他轻声说。

列表

- 第一项
- 第二项
- 第三项

1. 第一步
2. 第二步
3. 第三步

- [ ] 待办事项
- [x] 已完成

分隔线（场景分隔）

---

***
___

在小说写作中，--- 是最常用的场景分隔符。在预览中会显示为一条横线。

代码块

```
代码块中的文字
不会被渲染为 Markdown
```

图片

![图片描述](图片路径)

图片使用相对于当前文件的路径。预览中会正常显示。

链接和表格

[链接文字](https://example.com)

| 角色 | 年龄 | 职业 |
|------|------|------|
| 林小满 | 22 | 学生 |

注释（写作笔记，预览中不显示）

<!-- 这是 HTML 注释，预览中不显示 -->

%% 这是 Obsidian 风格注释，预览中也不显示 %%

可以用来记录写作灵感、待修改标记等，不会出现在预览和导出中。

ANH 专有语法

&Def Title = 我的小说标题
&Def Subtitle = 副标题
&Def Category = 玄幻

&Def 是元数据标注，用于 Typst 导出。预览中不会显示。

对话语法（Typst 导出专用）

@林小满: 今天天气真好。
@陈宇[下午三点]: 是啊。
> @林小满: 引用的对话

Obsidian 风格双链和标签

如果你从 Obsidian 迁入，ANH 可以直接识别常见的双链和标签写法：

今天林小满去了 [[第02章 失控的货舱]]。
这个伏笔来自 [[世界观/星辉议会#议会禁令|议会禁令]]。

#伏笔 #人物/林小满 #世界观
  • [[文件名]]：跳转到同名 Markdown / TXT 文件。
  • [[文件名|显示名]]：显示名可以和真实文件名不同。
  • [[文件名#标题]]：跳转到目标文件里的标题。
  • #标签、#父标签/子标签：用于保留 Obsidian 式标签整理习惯。
  • #FF6B6B 这类颜色值也会作为颜色标签识别，方便追踪角色颜色、敏感词颜色和其他视觉标记。
  • \#标签：默认按普通转义文本保留；如需在预览和导出中显示为 #标签，可开启“渲染转义标签”。
双链补全会从当前工作区里的 Markdown / TXT 文件名生成候选；标签补全会从工作区已有标签中生成候选。ANH 会把双链、标题和标签索引缓存到当前项目的 novel-helper/.anh-fsdb/obsidian-index.json，后续只增量更新变更文件。左侧“标签”侧边栏按“标签 → 文件”的结构展示已有标签，其中颜色标签会单独分组，并用对应颜色渲染节点图标。普通标签可以直接查看引用，也可以在右键菜单中基于标签创建角色或绑定到已有角色；绑定关系使用角色 UUID，保存到 novel-helper/.anh-fsdb/tag-role-bindings.json。绑定不会改写角色语义，也不会把标签变成另一套角色来源；角色仍由原角色文件和角色系统负责，但绑定后的 #标签 会作为该角色的外部别名键参与识别、补全和 hover，角色详情中也会把已绑定标签作为元数据展示。标签活动栏里还提供“角色追踪”视图，可手动建立分组，把关心的角色固定下来并按引用文件展开查看。预览、复制纯文本、TXT 导出、Typst 预览和 Typst 导出会按设置渲染双链和标签；可关闭标签渲染，让 #标签 只作为整理标记存在于源文件中。
这张图重点看：左上是“标签”视图，按标签名聚合文件；左下是“角色追踪”视图，会把你关心的角色按文件展开；正文里蓝色的 #标签 和 [[双链]] 都能被识别，这正是 ANH 的 Obsidian 兼容能力。

二、角色/资源文件格式

ANH 支持多种格式编写角色库、词汇表、敏感词库等资源文件：

格式 扩展名 特点
Markdown .md 最推荐，直观易读，用标题层级组织
JSON5 .json5 支持注释，适合程序生成
OJSON5（角色卡） .ojson5 JSON5 的变体，双击打开可视化角色卡编辑器
RJSON5（关系图） .rjson5 角色关系图专用格式，双击打开关系图编辑器
TJSON5（时间线） .tjson5 事件时间线专用格式，双击打开时间线编辑器
CSV .csv 表格格式，适合大量简单条目
TXT .txt 最简单，每行一个名称
TOML .toml 结构化配置格式，清晰易读，适合手工编辑

Markdown 角色文件格式

用标题层级组织角色信息：## 是角色名，### 是字段名，字段名后面换行写内容。

# 角色库

## 林小满

### 类型
主角

### 颜色
#FF6B6B

### 别名
小满
小林

### 描述
一个喜欢雨天咖啡店的女孩。

## 陈宇

### 类型
配角

### 颜色
#4ECDC4

### 别名
宇哥

必填字段只有一个：类型（### 类型）。不写类型会被默认当作"词汇"。

所有支持的字段

  • 基础字段：类型、颜色、别名、描述、所属、优先级
  • 角色专属：性别、年龄、职业、性格、外貌、背景、技能、弱点、目标、动机、恐惧、秘密、台词、备注、标签
  • 结构关系字段：继承自（extend / extends）、派生自（derived / derivedFrom）、包含角色（includes / composedOf / uses / parts）
  • 敏感词专属：修复（每行一个修复建议）、严重级别
  • 正则专属：正则、正则标志
  • 样式：粗体、斜体、删除线、下划线、背景色

角色层级和引用写法

Markdown 角色文件除了平铺字段，也支持直接表达角色之间的结构关系：

## 量产近卫

### 类型
模板

### 颜色
#8899AA

## 星港近卫

### 类型
配角

### 继承自
量产近卫

### 包含角色
制式步枪
识别吊牌
  • 继承 会尝试继承上游角色的可继承字段。
  • 派生 更偏向“语义来源”，默认不自动拷贝字段；需要显式配合 inherit: true 才复制字段。
  • 包含角色 / 引用角色 只是建立组合关系，不会像继承那样改写当前角色字段。
  • 这些字段既可以写角色名，也可以写 UUID；多项组合关系可按逗号或换行分隔。

常见错误

  • 标题层级写错：# 是文件标题，## 是角色名，### 是字段
  • "类型"写错：必须精确匹配"主角""配角"等，不能有空格
  • 别名用逗号分隔：应该每个别名单独一行，或者用逗号分隔（两种都支持）
  • 颜色格式：#FF6B6B、rgb(255,0,0)、hsl(0,100%,50%) 都可以

一、JSON5 格式详解

JSON5 是 JSON 的超集，支持注释和尾随逗号。文件扩展名 .json5。

支持三种写法：

写法 1：数组（最常用）

[
  {
    name: "林小满",
    type: "主角",
    color: "#FF6B6B",
    aliases: ["小满", "小林"],
    description: "一个喜欢雨天咖啡店的女孩",
    affiliation: "星光文学社",
    priority: 5,
    style: {
      color: "#FF6B6B",
      bold: true
    }
  },
  {
    name: "陈宇",
    type: "配角",
    color: "#4ECDC4"
  }
]

写法 2：对象包装

{
  "roles": [
    { "name": "林小满", "type": "主角" }
  ]
}

写法 3：字典映射

{
  "林小满": { "type": "主角", "color": "#FF6B6B" },
  "陈宇": { "type": "配角", "color": "#4ECDC4" }
}

JSON5 完整字段列表

  • name / 名称 / 名字 — 条目名称（必填）
  • type / 类型 — 类型：主角、配角、联动角色、敏感词、词汇、正则表达式，或自定义字符串
  • color / 颜色 — 颜色值
  • aliases / 别名 — 别名数组
  • description / 描述 — 描述文本
  • affiliation / 从属 — 所属组织
  • priority / 优先级 — 补全优先级（数字越小越优先）
  • fixes / 修复 — 敏感词修复建议数组
  • regex / 正则 — 正则表达式（类型为"正则表达式"时使用）
  • regexFlags / 正则标志 — 正则标志，如 "gi"
  • wordSegmentFilter / 分词过滤 — 是否启用分词过滤
  • extend / extends / 继承自 — 继承来源，可写角色名、UUID 或 { uuid } 对象
  • derived / derivedFrom / 派生自 — 派生来源；如需同时继承字段，可再配合 inherit: true
  • includes / composedOf / uses / parts — 组合/引用的其他角色，可写单项、数组或 { uuid } 对象
  • style / 样式 — 样式对象：{ color, backgroundColor, bold, italic, strikethrough, underline }
  • 扩展字段：age/年龄、gender/性别、occupation/职业、personality/性格、appearance/外貌、background/背景、skill/技能、weakness/弱点、goal/目标、motivation/动机、fear/恐惧、secret/秘密、quote/台词、note/备注、tag/标签
JSON5 还支持直接写嵌套角色树。子角色可以放在 children、childRoles、subRoles、roles、characters 等键里；加载时会自动扁平化，并把父级信息映射到父子关系字段。

正则表达式 JSON5 示例

[
  {
    name: "中文对话",
    type: "正则表达式",
    regex: "「[^」]*」",
    regexFlags: "g",
    color: "#98FB98",
    priority: 100
  },
  {
    name: "书名号",
    type: "正则表达式",
    regex: "《[^》]+》",
    regexFlags: "g",
    color: "#87CEEB",
    priority: 90
  }
]

正则表达式 Markdown 示例

# 着色规则

## 中文对话

### 类型
正则表达式

### 正则
```regex
「[^」]*」
```

### 正则标志
g

### 颜色
#98FB98

### 优先级
100

Markdown 中建议把正则表达式放进围栏代码块，避免 #、*、[] 等字符被 Markdown 标题或格式语法影响。

二、OJSON5 格式详解（角色卡）

OJSON5 扩展名 .ojson5，内容仍然是 JSON5 角色数组；区别是 VS Code 会优先用角色 JSON5 编辑器打开它。它适合"一个文件就是一个结构化角色库"的场景。

[
  {
    name: "林小满",
    type: "主角",
    aliases: ["小满", "小林"],
    lookupKeys_pinyin: ["linxiaoman", "lxm"],
    color: "#FF6B6B",
    description: "一个喜欢雨天咖啡店的女孩。",
    age: "22",
    occupation: "学生",
    customField: "任意自定义字段也会保留"
  }
]

角色卡编辑器会用表格化界面编辑这些字段，也可以切回经典界面或源码模式。无论用哪种界面，保存到文件时仍是上面这种普通 JSON5 对象：

  • 基础字段（base）：name、type、color、aliases、description、affiliation、priority、fixes、style
  • 扩展字段（extended）：age、gender、occupation、personality、appearance、background、skill、weakness、goal、motivation、fear、secret、quote、note、tag
  • 自定义字段（custom）：任意用户定义的字段

编辑器还支持字段显示名本地化（中文 / 英文 / 日文 / 原始 key）、查询键候选生成、随机角色生成器、UUID 复制反馈，以及前景色、背景色和文本样式的集中编辑。

.json5 和 .ojson5 的数据结构相同；区别主要是打开方式和识别优先级。.ojson 是旧式标记扩展名，仍可作为外部资源标识识别，但新文件推荐用 .ojson5。编辑器保存和 UUID 自动写回默认优先使用无损写回，尽量保留你原先手写的注释、空白和字段顺序；如需关闭，可把 AndreaNovelHelper.json5.losslessEditorEnabled 设为 false。

三、CSV 格式详解

表格格式，扩展名 .csv。实际解析器支持逗号、Tab、分号三种分隔符，并会自动检测。适合从 Excel、表格软件或 AI 批量导入简单条目。

带表头的 CSV：

名称,类型,颜色,别名,描述,从属
林小满,主角,#FF6B6B,"小满;小林","一个喜欢雨天的女孩",星光文学社
陈宇,配角,#4ECDC4,宇哥,"学长",星光文学社

不带表头的 CSV（自动识别）：第一列是名称，第二列是描述，其余列作为查询键。

林小满,一个喜欢雨天的女孩,lxm; linxiaoman
陈宇,学长,cy; chenyu

TSV / 分号分隔也可读取：

name	type	aliases	lookupKeys_pinyin
林小满	主角	小满; 小林	linxiaoman; lxm

CSV 支持的列名（中英文均可）

  • name / 名称 / 角色 / 人物 / 词条
  • description / 描述 / 简介
  • type / 类型
  • aliases / 别名 / 别称
  • color / 颜色
  • affiliation / 从属 / 阵营
  • priority / 优先级
  • fixes / 修复 / 替换
  • regex / 正则
  • regexFlags / 正则标志
  • wordSegmentFilter / 分词过滤
  • lookupKeys、lookupKeys_pinyin、lookupKeys_romanized、lookupKeys_spelling，以及项目中定义的其他查询键字段
  • gender / 性别
  • origin / 来源

未识别的列不会丢弃：ANH 会把它作为自定义字段保存；如果列名单独用于查询键，也会生成对应的 lookupKeys_列名 字段。数组类字段（别名、修复、查询键）可用分号、逗号、顿号、换行等分隔。

四、TXT 格式详解

最简单的格式。扩展名 .txt。每行一个名称，没有其他字段。

林小满
陈宇
张伟
# 这是注释，不会被读取
// 这也是注释
  • 空行跳过
  • # 或 // 开头的行是注释
  • 行内也可以写注释：林小满 # 主角 → 只读取"林小满"
  • TXT 文件不支持颜色、别名、描述等任何额外字段
  • TXT 不能表达正则规则；正则着色请使用 Markdown 或 JSON5

四（补）、TOML 格式详解

扩展名 .toml。TOML（Tom's Obvious Minimal Language）是一种人类友好的配置文件格式，语法清晰、结构明确。适合手工编辑，也可配合推荐扩展 Even Better TOML 获得语法高亮和校验。

基本写法：用 [[roles]] 数组表定义角色

# 角色库

[[roles]]
name = "林小满"
type = "主角"
color = "#FF6B6B"
aliases = ["小满", "小林"]
description = "一个喜欢雨天咖啡店的女孩"
affiliation = "星光文学社"

[[roles]]
name = "陈宇"
type = "配角"
color = "#4ECDC4"

TOML 基础语法速查

  • 字符串用双引号：name = "林小满"
  • 整数直接写数字：priority = 5
  • 布尔值：bold = true，wordSegmentFilter = false
  • 数组用方括号：aliases = ["小满", "小林"]
  • 注释用 # 开头
  • [[roles]] 表示追加一个角色条目（数组表语法）

敏感词 TOML 示例

# 敏感词表

[[roles]]
name = "禁用词"
type = "敏感词"
color = "#FF4D4F"
description = "需要避免使用的词汇"
aliases = ["禁用词2"]
fixes = ["不是禁用"]
category = "内容安全"

词汇 TOML 示例

# 专业词汇表

[[roles]]
name = "灵能"
type = "词汇"
color = "#1890FF"
description = "世界观核心能量"
aliases = ["灵力", "能量"]
category = "世界观"

正则表达式 TOML 示例

# 着色规则

[[roles]]
name = "中文对话"
type = "正则表达式"
regex = "「[^」]*」"
regexFlags = "g"
color = "#98FB98"
priority = 100

所有字段名称与 JSON5 格式一致（见下方字段列表），支持中英文别名。自定义字段也可直接添加。

TOML 格式不支持嵌套对象（如 style 字段），需要使用 JSON5 来表达复杂嵌套结构。其余场景推荐 TOML，可读性最佳。

五、RJSON5 关系图格式

扩展名 .rjson5，内容是 JSON5，双击打开可视化关系图编辑器。它不作为角色库加载，而是用于描述角色之间的关系网络。

{
  nodes: [
    { id: "reimu", text: "博丽灵梦", color: "#E60033" },
    { id: "marisa", text: "雾雨魔理沙", color: "#FFD700" }
  ],
  lines: [
    {
      source: "reimu",
      target: "marisa",
      data: { type: "朋友" },
      text: "解决异变的搭档"
    }
  ]
}

常用字段：

  • nodes — 节点数组，通常对应角色、组织、地点等实体
  • lines — 关系线数组，source / target 指向节点 id
  • data.type 或 relationshipType — 关系类型
  • text — 关系说明文字

内置关系类型：朋友、恋人、夫妻、父子、母子、父女、母女、兄弟、姐妹、师父、同事、上司、下属、敌人、仇人、竞争对手、合作伙伴、盟友。.rjson 是旧式关系标记扩展名，新文件推荐 .rjson5。

六、TJSON5 时间线格式

扩展名 .tjson5，内容是 JSON5，双击打开可视化时间线编辑器。它不作为角色库加载，而是用于组织事件、时间顺序和事件之间的连接。

{
  events: [
    {
      id: "event1",
      title: "幻想乡建立",
      date: "1885年",
      description: "博丽大结界建立",
      type: "main",
      bindings: [
        { uuid: "reimu", type: "character", label: "博丽灵梦" }
      ]
    },
    {
      id: "event2",
      title: "第一次异变",
      date: "春",
      type: "side"
    }
  ],
  connections: [
    { source: "event1", target: "event2", connectionType: "normal" }
  ]
}

常用字段：

  • events — 事件数组，核心字段是 id、title、date、description、type
  • bindings — 事件关联对象，可绑定角色、地点、物品、文章等
  • connections — 事件之间的连接，使用 source / target 指向事件 id

连接类型：normal、time-travel、reincarnation、parallel、dream、flashback、other。时间格式完全自由（"第一章"、"2024年春"、"第三纪元"都可以）。

七、自定义 XJSON5 扩展名总结

ANH 的自定义 JSON5 扩展名本质上仍是 JSON5，只是用扩展名告诉 VS Code 应该启用哪个专用编辑器或识别逻辑：

扩展名 用途 是否角色库
.json5 通用角色/词汇/敏感词/正则库，靠文件名关键词识别类型 是
.ojson5 角色 JSON5 编辑器优先打开 是
.rjson5 关系图编辑器 否
.tjson5 时间线编辑器 否
外部资源目录识别仍兼容 .ojson / .rjson 这类旧标记扩展名；新建文件建议统一使用 .ojson5、.rjson5、.tjson5。

八、格式选择指南

场景 推荐格式 原因
手动编写角色 Markdown 最直观，可读性好

九、ANH 预览器支持的 Markdown 语法

ANH 使用自研 Markdown 解析器（非第三方库），支持以下语法：

块级元素：

  • ATX 标题（# ~ ######）— 预览中按层级显示不同大小
  • Setext 标题（=== / --- 下划线）— 1 级和 2 级
  • 段落 — 两个换行之间为一个段落
  • 引用块（>）— 预览中有左边框和缩进
  • 无序列表（-、*、+）
  • 有序列表（1.、2.）
  • 任务列表（- [ ]、- [x]）
  • 围栏代码块（```、~~~）
  • 缩进代码块（4 空格或 Tab）
  • 表格（管道符分隔）
  • 水平线（---、***、___）
  • 图片（![alt](src)）— 相对路径自动解析

行内元素：

  • **加粗** — 预览中显示为粗体
  • *斜体* — 预览中显示为斜体
  • ***加粗斜体***
  • ~~删除线~~ — 预览中显示为删除线
  • `行内代码` — 预览中有背景色
  • [链接文字](url) — 预览中只显示文字，链接被剥离

注释（被剥离）：

  • <!-- HTML 注释 -->
  • %% Obsidian 注释 %%

不支持的语法：嵌套列表、脚注、LaTeX 数学公式、Mermaid 图表。

十、预览器设置

预览器右下角有齿轮按钮，可以调整：

  • 显示模式：滚动模式（连续）或翻页模式（PgUp/PgDn）
  • 排版：左对齐或两端对齐、1 栏或 2 栏
  • 字体：字号、字体、行高、段间距
  • 主题：跟随 VS Code、纯白、纯黑、自定义颜色
  • Markdown 渲染：可独立开关标题、列表、加粗、斜体、引用、代码块等
  • 角色名着色：可开关、可按类型过滤
  • 预设：保存/加载/删除自定义配置

十一、TTS 语音朗读

预览器底部有语音朗读控件，支持播放、暂停、停止。当前朗读位置会以金色背景高亮。可选择朗读全文或选中文本。翻页模式下朗读会跨页继续。

十二、导出

预览器右键菜单支持：

  • 复制纯文本到剪贴板
  • 导出为 TXT 文件
ANH 的正文写作 Markdown 是标准 Markdown，没有特殊的 ANH 标注语法（&Def 仅用于 Typst 导出元数据）。角色名的自动上色完全基于你在角色库中定义的名称和别名，不需要在正文中做任何特殊标记。
