这页文档讲什么

这页不是泛泛讲“迁移原则”，而是专门教你：怎样从别的软件或旧文件夹，一步一步迁移到 ANH。起点是 先创建工作区，然后 运行初始化向导，再把旧正文、角色表、词汇表、敏感词表一点点搬进来，最后得到一个真正能继续写、能搜索、能备份的 ANH 项目。

如果你还没看过向导说明，先读 项目初始化向导；如果你想知道向导最终会生成哪些文件，再读 工作区初始化文件。

先说结论：迁移不是“把旧文件夹直接扔进来”

正确做法是：

1. 新建一个给 ANH 用的新工作区
2. 运行初始化向导，先把 ANH 的基础骨架搭起来
3. 把旧资料按类型搬进对应位置
4. 检查补全、词汇、敏感词、搜索是否正常
5. 再做 Git / WebDAV 备份

不要在旧项目原地硬改，也不要一上来就把几十个旧目录整个复制进正文主目录。

图 1：迁移的正确起点

旧软件 / 旧文件夹 / 压缩包
   ↓ 先保留原件
新建一个 ANH 工作区
   ↓
运行初始化向导
   ↓
得到标准项目骨架
   ↓
分批迁入正文和资料
   ↓
检查功能是否正常
   ↓
再开始继续写作

第 0 步：先备份旧资料

在做任何迁移动作前，先把旧项目完整复制一份。你可以叫它：

旧项目原件/
旧项目迁移副本/

后面所有整理、改名、拆章节、转换格式的动作，都只对“迁移副本”做，不碰原件。

第 1 步：先创建一个新的 ANH 工作区

  1. 打开 ANH Hello 页。
  2. 点击“新建写作工作区”。
  3. 选择一个新的空文件夹，例如 D:\Novel\星港回声-ANH。
  4. 让 VS Code 直接打开这个新工作区。

这里的关键是：迁移最好迁到一个新的 ANH 工作区里，而不是直接在旧软件项目目录上强行叠加。

第 2 步：运行项目初始化向导

新工作区打开后，初始化向导通常会自动弹出。按顺序填完它：

  1. 项目信息：填小说名、作者名、简介。
  2. 项目配置：先用默认值就行，不要一开始就自定义太多路径。
  3. Git 账户：暂时不会也没关系，可以先跳过。
  4. Git 仓库：先不填远端地址也可以，迁移完再配。
  5. 项目文件：让向导把基础文件一次性创建出来。
  6. 确认：点完成。

第 3 步：你应该先看到什么结果

向导结束后，工作区里至少应该先有这些东西：

星港回声-ANH/
├── anhproject.md
├── project-config.json5
├── .gitignore
├── .wcignore
└── novel-helper/
    ├── character-gallery.json5
    ├── character-gallery.csv
    ├── sensitive-words.json5
    ├── vocabulary.json5
    ├── regex-patterns.json5
    └── roles.md

到这里，你只是把 ANH 项目的骨架 建好了。注意：这些默认文件只是起步样例，真正迁移时你通常会继续把资料拆成多个包目录和多个独立文件，而不是永远只往这几个根目录 JSON5 里塞。

第 4 步：先决定“来源类型对应什么格式”

旧资料来源 优先迁成什么 为什么
Word / WPS 正文 章节 .md 正文本来就最适合 Markdown 写作流
Excel / 表格里的人物设定 character-gallery.csv 表格到 CSV 最直接，字段映射最省事
手工写的人物卡、人物手册 roles.md 长期人工阅读和维护更舒服
世界观术语文档 vocabulary.md 术语表通常是“人看得多”，Markdown 更自然
Excel / 表格里的术语表 vocabulary.csv 先保留表格结构，后面再决定要不要转 Markdown
纯文本敏感词列表 sensitive-words.txt 或 sensitive-words.md TXT 可以直接一行一个词；想补说明、修复建议、别名时再转 Markdown
带修复建议、等级、说明的敏感词规则 sensitive-words.json5 结构字段比较多，JSON5 更合适
旧归档、PDF、截图、导出稿 archive/ 或工作区外备份目录 不应该和当前正文、当前资源包混在一起
旧软件数据库、缓存、索引文件 通常不迁 保留原件备查即可，别污染当前工作区
一句话版规则：手工长期维护优先 Markdown，表格来源优先 CSV，复杂结构再用 JSON5。

第 5 步：先把默认根目录文件“升级”为包结构

不要一开始就把所有资料都塞回初始化时那几个默认文件。更推荐先在 novel-helper/ 里建几个包目录，例如：

novel-helper/
├── cast-main/
├── world/
├── style-guide/
└── coloring/
  1. 打开包管理器。
  2. 在 novel-helper/ 上右键，连续创建几个子包。
  3. 以后角色放 cast-main/，术语放 world/，敏感词放 style-guide/，正则规则放 coloring/。
  4. 初始化生成的根目录样例文件可以保留作参考，也可以在确认迁移稳定后删除。

第 6 步：先迁正文，不要先迁杂项

正文永远是第一优先级。你应该先做的是：

  1. 从旧软件或旧文件夹里找出“当前有效正文”。
  2. 按章节拆开，尽量整理成多个 Markdown 文件。
  3. 把这些章节文件放到 ANH 工作区根目录，或者你自己的章节子目录里。
  4. 打开几章看看，确认能正常显示、搜索和编辑。

例子 A：从 Word / WPS + Excel 迁移

假设你原来是这么管理的：

D:\OldNovel\
├── 第一卷总稿.docx
├── 角色设定.xlsx
├── 世界观术语.docx
└── 敏感替换词.txt

建议你这样迁：

  1. 先在 novel-helper/ 里建三个包：cast-main/、world/、style-guide/。
  2. 把 第一卷总稿.docx 导出或整理成 Markdown / TXT 副本。
  3. 按章节拆成多个 .md 文件，例如：
星港回声-ANH/
├── 第01章 初到星港.md
├── 第02章 失控的货舱.md
├── 第03章 雨夜追踪.md
└── novel-helper/...
  1. 把 角色设定.xlsx 另存为 CSV。
  2. 把这个 CSV 文件重命名成 character-gallery.csv，放进 novel-helper/cast-main/。
  3. 打开 CSV，至少确认第一列是名字；如果有类型、描述、别名列就一起保留。
  4. 在包管理器里确认它已经被识别为角色资源文件。
  5. 如果 Excel 里还有少数“核心角色”的长篇设定，不要硬塞 CSV；把这几个核心角色另写进 novel-helper/cast-main/roles.md。
  6. 把 世界观术语.docx 整理成 novel-helper/world/vocabulary.md。术语这类资料通常更推荐 Markdown，因为后续是“人读得多”。
  7. 如果 敏感替换词.txt 本来就是一行一个词，可以直接重命名为 sensitive-words.txt，放进 novel-helper/style-guide/；如果你想同时写修复建议、说明、别名或优先级，再整理成 Markdown / CSV / JSON5。

例子 A-1：Excel 人物设定迁到 CSV 的具体做法

  1. 在 Excel 里保留最关键的列，例如：name、type、description、aliases。
  2. 删除纯视觉排版用的合并单元格、彩色分隔行、空白装饰列。
  3. 执行“另存为 CSV”。
  4. 把文件名改成能命中角色关键词的名字，例如 character-gallery.csv。
  5. 把它放到包目录，例如 novel-helper/cast-main/character-gallery.csv。
  6. 回到 VS Code，确认包管理器能展开这个文件。
name,type,description,aliases
林小满,主角,雨天咖啡店常客,"小满;小林"
周既白,配角,货运站调度员,"老周"

例子 A-2：TXT 敏感词列表怎么迁

如果你原来的 敏感替换词.txt 大概长这样：

某个不推荐词
另一个不推荐词
某个投稿禁用表达

那么最直接的迁法就是保留 TXT 格式：

  1. 在 novel-helper/style-guide/ 里创建或复制出 sensitive-words.txt。
  2. 保持“一行一个敏感词”。
  3. 空行会被跳过；以 # 或 // 开头的行会被当作注释。
  4. 在包管理器里确认这个文件被识别为敏感词库。
# 一行一个敏感词，支持 # / // 注释
某个不推荐词
另一个不推荐词
某个投稿禁用表达

TXT 的限制也很明确：它只能表达“词本身”，不能写修复建议、别名、颜色、优先级和说明。如果你需要这些字段，再升级成 Markdown：

  1. 创建 novel-helper/style-guide/sensitive-words.md。
  2. 第一行写 # 敏感词库，表示这是一个敏感词资源文件。
  3. 把每个旧词改成一个二级标题，也就是 ## 词条名。
  4. 每个词条下面写 ### 类型，下一行写 敏感词。
  5. 如果有替换建议，再加 ### 修复，下面一行一个建议词。
# 敏感词库

## 某个不推荐词

### 类型
敏感词

### 修复
推荐替换词
更温和的表达

## 另一个不推荐词

### 类型
敏感词

### 修复
替代表达

这样迁完以后，你能直接在 VS Code 里读懂每一条规则，也能继续补说明、别名、优先级和颜色：

### 别名
某个变体
某个谐音

### 优先级
2

### 颜色
#FF4D4F

例子 A-3：带“原词 / 替换词 / 说明”的敏感词表怎么迁

如果旧资料不是一行一个词，而是类似这样的表格：

原词,替换词,说明
某个不推荐词,推荐替换词,成稿前统一替换
另一个不推荐词,替代表达,投稿平台不建议出现

它本来就是表格来源，先落 CSV 会更清楚：

novel-helper/style-guide/sensitive-words.csv

如果你想让字段更完整，或者需要一条敏感词对应多个修复建议，再迁成 JSON5：

[
    {
        name: '某个不推荐词',
        type: '敏感词',
        fixes: ['推荐替换词', '更温和的表达'],
        description: '成稿前统一替换',
        priority: 2,
    },
    {
        name: '另一个不推荐词',
        type: '敏感词',
        fixes: ['替代表达'],
        description: '投稿平台不建议出现',
    },
]

所以敏感词迁移不是“全部扔进默认 sensitive-words.json5”。正确路线是：一行一个词可以直接保留 TXT；想手工写说明和修复建议就用 Markdown；原始表格先 CSV；规则复杂、要多修复建议和说明时再 JSON5。

例子 B：从 Obsidian / Markdown 项目迁移

假设你原来长这样：

obsidian-vault/
├── 小说正文/
│   ├── 第1章.md
│   ├── 第2章.md
│   └── 第3章.md
├── 人物卡/
│   ├── 女主.md
│   └── 男主.md
├── 术语.md
└── 零散笔记/

这种情况通常更好迁，因为正文本来就是 Markdown：

  1. 把 小说正文/ 下的章节直接复制到新 ANH 工作区。
  2. 先在 novel-helper/ 下建 cast-main/ 和 world/ 两个包。
  3. 把 人物卡/ 里的关键信息整理进 novel-helper/cast-main/roles.md。
  4. 把 术语.md 整理进 novel-helper/world/vocabulary.md。
  5. 双链、标签、frontmatter 不是不能留，但不要让它们妨碍你先完成迁移。

例子 C：把旧项目目录的一部分先标成“外部包”

如果你有一批旧资料暂时不想塞进 novel-helper/，但又想让 ANH 先识别它，更适合这样做：

当前工作区/
├── novel-helper/
└── imports/
    └── 旧项目角色迁移包/
        ├── roles.md
        └── character-gallery.csv
  1. 把旧资料先整理到 imports/旧项目角色迁移包/。
  2. 打开“外部资源目录管理”。
  3. 选择这个目录。
  4. 让 ANH 创建 __init__.ojson5。
  5. 这样它就会作为当前工作区里一个非 novel-helper/ 的外部包出现在包管理器顶层。

这比一上来就挂工作区外目录更符合 ANH 的日常使用方式。

迁移阶段最重要的原则是：先能继续写，再追求漂亮结构。不要在第一天就试图把所有历史废稿、截图、索引库、插件缓存都“标准化”。

一个完整的迁移示例

假设你的旧项目叫“星港回声”，原目录如下：

D:\OldNovel\星港回声\
├── 正文总稿.docx
├── 人物关系.xlsx
├── 敏感词.txt
├── 设定术语.docx
├── 历史归档.zip
└── 截图素材/

迁移到 ANH 之后，一个比较合理的结果可以是：

D:\Novel\星港回声-ANH\
├── anhproject.md
├── project-config.json5
├── .gitignore
├── .wcignore
├── 第01章 初到星港.md
├── 第02章 失控的货舱.md
├── 第03章 雨夜追踪.md
├── archive/
│   └── from-old-project/
│       └── 历史归档.zip
├── imports/
│   └── 旧项目角色迁移包/
│       ├── __init__.ojson5
│       ├── roles.md
│       └── character-gallery.csv
└── novel-helper/
    ├── cast-main/
    │   ├── roles.md
    │   └── character-gallery.csv
    ├── world/
    │   └── vocabulary.md
    ├── style-guide/
    │   └── sensitive-words.md
    ├── coloring/
    │   └── regex-patterns.json5
    └── mcp.json

上面这个最终效果意味着什么

  • 项目根目录：放当前还在写的正文主文件。
  • novel-helper/：放项目主资源，而且是按包拆开的，不再只依赖初始化那几个默认 JSON5 文件。
  • imports/旧项目角色迁移包/：这是一个当前工作区里的外部包示例，它不在 novel-helper/ 下，但仍可被 ANH 识别。
  • archive/：放旧归档、旧导出、旧压缩包，不和当前正文混在一起。
  • 向导生成的基础文件：保证 ANH 能正常识别这个项目。

哪些东西不要急着迁

  • 其他软件的数据库文件。
  • 自动保存缓存。
  • 过期导出 PDF。
  • 一大堆截图和零散素材。
  • 几十个“最终版2”“最终版3”之类的旧副本。

这些东西可以先保留在旧项目备份里，或者放到 archive/，但不要让它们污染当前工作区主目录。

迁移完成后立刻做的 6 件事

  1. 打开几章正文，确认文件都能正常编辑。
  2. 跑一次全文搜索，确认章节没有丢。
  3. 检查角色补全、词汇识别、敏感词识别是否开始工作。
  4. 补齐 anhproject.md 和 project-config.json5。
  5. 确认 .gitignore 是否合理。
  6. 做一次“迁移完成初始状态”提交。
