这一页讲什么

这页讲 VS Code 的命令面板和快捷键。如果你经常“知道某个功能存在，但忘了按钮在哪”，这页会非常值。

命令面板：最应该先学会的入口

按 Ctrl+Shift+P 打开命令面板。几乎所有功能都能从这里搜到。

  • 搜命令：输入中文或英文关键词。
  • 看默认快捷键：很多命令右侧会显示快捷键。
  • 不用记菜单层级：不知道按钮在哪时，先开命令面板。

新手最值得养成的习惯就是：找不到功能时，不要先翻菜单，先按 Ctrl+Shift+P。

图上英文对照：> = 命令模式；Go to File = 转到文件；Go to Line/Column = 转到行 / 列；Go to Symbol in Editor = 转到当前文件符号；Go to Symbol in Workspace = 转到整个工作区符号；Show and Run Commands = 显示并运行命令。

命令面板和 Quick Open 的关系

  • Ctrl+Shift+P：偏“找命令”。
  • Ctrl+P：偏“找文件”。

官方 Getting Started 文档还提到，命令面板其实支持多种模式：

  • >：命令模式。
  • 直接输入文件名：快速打开模式。
  • #：符号搜索模式。

先记住一组高频快捷键

  • Ctrl+Shift+P：命令面板。
  • Ctrl+P：快速打开文件。
  • Ctrl+,：设置。
  • Ctrl+Shift+F：全局搜索。
  • Ctrl+Shift+G：源代码管理。
  • Ctrl+Shift+X：扩展。
  • Ctrl+`：终端。
  • Ctrl+B：切换侧边栏。

如果你只用鼠标，VS Code 也能工作；但只要你愿意记住上面这几项，效率会明显提升。

键盘快捷键编辑器

按 Ctrl+K Ctrl+S 打开 Keyboard Shortcuts Editor。这里可以：

  • 搜索某个命令现在绑定了什么键。
  • 给命令重新设置快捷键。
  • 删除某个快捷键。
  • 恢复默认快捷键。
图上英文对照：Keyboard Shortcuts = 快捷键编辑器；@source:user = 只看用户自定义；Command = 命令；Keybinding = 按键绑定；When = 生效条件；Show User Keybindings = 显示用户快捷键。

什么时候值得改快捷键

  • 你每天都会用某个命令。
  • 默认快捷键太绕，记不住。
  • 某个键位和你熟悉的软件冲突。
  • 你想把高频写作动作放在更顺手的位置。

但不要为了“显得专业”就改一大堆。先从 1 到 3 个高频动作开始，最稳。

查看当前有哪些自定义快捷键

官方 Keyboard Shortcuts 文档提到可以过滤“只看用户修改过的快捷键”。这对排查冲突很有帮助，尤其是你装了很多扩展以后。

如果快捷键不生效怎么办

  • 先看是否被别的命令抢走。
  • 再看当前焦点是不是在编辑器、终端、搜索框还是侧边栏。
  • 最后看是不是和系统快捷键冲突。

Customize Shortcuts for UI Actions

官方文档特别提到一个很好用的入口：右键某个 UI 动作，直接选择 Configure Keybinding。这样 VS Code 会自动把你带到对应命令，并尽量保留它的上下文条件。

keybindings.json 是什么

和设置有 settings.json 一样，快捷键也有自己的底层文件：keybindings.json。

图形界面适合大多数用户；keybindings.json 则适合做更精确的改动，例如带条件的快捷键、连续命令、移除默认绑定。

图上英文对照：keybindings.json = 快捷键配置文件；Press desired key combination and ENTER = 按下想绑定的组合键后回车；Define Keybinding = 定义快捷键。

键盘规则的三个核心字段

官方把一条快捷键规则定义为：

{
  "key": "ctrl+f",
  "command": "actions.find",
  "when": "editorTextFocus"
}
  • key：按键。
  • command：执行的命令 ID。
  • when：什么情况下这条规则才生效。

when 子句为什么重要

同一个按键在不同上下文里可以做不同事，关键就在 when。

例如：

  • 编辑器聚焦时，F5 可能是启动调试。
  • 调试中时，F5 变成继续执行。
  • 终端聚焦时，很多键又会交给 Shell。

这也是“明明设置了快捷键，为什么有时候不触发”的根本原因之一。

冲突检测和故障排查

官方提供了两种很关键的排查能力：

  • Show Same Keybindings：查某个键位绑定了哪些命令。
  • Developer: Toggle Keyboard Shortcuts Troubleshooting：记录按键分发日志。

如果你修改快捷键后毫无反应，别靠猜，直接看冲突和日志。

移除默认快捷键

官方文档说明，可以在 keybindings.json 中用带减号的命令 ID 来移除默认规则。例如：

{ "key": "tab", "command": "-jumpToNextSnippetPlaceholder" }

这适合处理某些扩展或系统行为把你常用按键占掉的情况。

运行多个命令

官方还支持 runCommands，让一个快捷键连续执行多个命令。这很强，但也更容易把自己绕晕。

对普通写作用户而言，不建议一开始就做复杂链式快捷键。先把“打开终端”“打开图形化快速设置”“切换侧边栏”这类单命令绑定稳定就够了。

键盘布局差异

官方文档专门提醒：快捷键显示会受键盘布局影响。也就是说，别人的教程写的某个键位，在你的非美式布局键盘上可能显示成另一种组合。

如果你经常遇到“教程说 Ctrl+\，我这边显示完全不一样”，优先怀疑键盘布局，不要先怀疑功能消失了。

和 ANH 的实际结合

  • 你可以给“打开图形化快速设置”自定义快捷键。
  • 你可以给“打开文档中心”加快捷键。
  • 你可以给“Open in Integrated Terminal”或“运行某个任务”绑定组合键。
  • 你也可以把 AI、终端、搜索、字数统计相关动作放进自己的肌肉记忆里。
如果你已经理解“命令是什么、快捷键如何分发”，下一步就可以读 内建 Git 与版本流，因为 Git 面板里大多数动作本质上也都能从命令面板和快捷键触发。
