这一页讲什么

这页讲 VS Code 里的终端、任务、工作区。很多人会把 VS Code 当成“只能编辑文本的窗口”，但它其实内置了完整终端和项目级配置能力。

终端是什么

终端就是 VS Code 底部那块可以输入命令的区域。你可以把它看成“不用离开编辑器的命令行”。

  • 打开/关闭终端：Ctrl+`
  • 新建终端：Ctrl+Shift+`
  • 菜单入口：Terminal → New Terminal

在 Windows 上，你常见的终端 Shell 会包括 PowerShell、命令提示符、Git Bash、WSL 等。

图上英文对照：TERMINAL = 终端面板；bash - hello-world = 当前终端标签；+ = 新建终端；分栏图标 = 分屏终端；垃圾桶 = 关闭终端；X = 关闭当前标签。

为什么写作者也要会终端

  • 运行 Git 命令。
  • 安装或更新扩展依赖。
  • 跑构建、导出、打包命令。
  • 处理一些批量文件操作。
  • 查看脚本输出和错误日志。

你不必成为命令行高手，但至少要知道终端在哪、怎么切目录、怎么复制输出。

终端最常见的操作

  • 切换不同 Shell：终端面板右上角下拉菜单里选。
  • 开多个终端：点加号创建多个实例。
  • 分屏终端：把终端一分为二，适合一边跑服务一边看日志。
  • 杀掉终端：垃圾桶图标或右键关闭。
  • 在资源管理器某文件夹打开终端：右键文件夹，Open in Integrated Terminal。

默认工作目录

VS Code 终端默认会从你当前打开的工作区根目录启动。这意味着：

  • 你打开的是小说项目文件夹，终端就从这个项目开始。
  • 很多命令不用先手动切路径。
  • ANH 项目里的命令通常都可以直接跑。

终端里也能搜索、复制、跳文件

  • Ctrl+F：在终端输出中查找。
  • 复制粘贴：Windows 下一般是 Ctrl+C / Ctrl+V。
  • 文件链接：很多输出里的文件路径可以按住 Ctrl 点击直接打开。

如果命令输出报错位置，VS Code 终端往往能直接把你带到对应文件和行号。

任务是什么

任务可以理解成“事先定义好的一键命令”。比如：

  • 一键编译。
  • 一键构建 webview。
  • 一键启动预览服务。
  • 一键打包扩展。

在当前仓库里，VS Code 已经有现成任务，例如 watch、打包扩展等。这就是为什么你在 VS Code 里经常能直接运行构建任务，而不必每次手敲完整命令。

图上英文对照：task = 在命令面板里筛任务；build / buildAll / buildTests = 可执行任务；OUTPUT / Tasks = 任务输出面板。

工作区是什么

在 VS Code 语境里，工作区通常就是你打开的项目文件夹。它不只是一个路径，还代表：

  • 当前文件树。
  • 工作区设置。
  • 任务配置。
  • 调试配置。
  • 扩展在该项目下的状态。

所以“打开项目”不是简单的浏览文件，而是在切换一整套环境。

Workspace Trust 是什么

官方 Getting Started 文档把 Workspace Trust 放在很前面。它的意思是：你是否信任这个项目里的代码和配置可以被执行。

  • 你自己建的小说项目：通常可以信任。
  • 网上下载的不明仓库：先检查再决定。
  • 限制模式：某些功能会被禁用，例如终端或自动执行类能力会受影响。

终端管理：标签、分组、编辑器终端

官方 Terminal Basics 文档里提到，终端不只有底部面板一种形态：

  • 普通终端面板：最常见。
  • 分组终端：多个终端并排显示。
  • Editor Area Terminal：把终端当成编辑器标签放到中间区域。
  • New Window Terminal：把终端移到新窗口。

如果你一边写文档一边盯着长日志，用编辑器终端或新窗口终端会比底部小面板更舒服。

图上英文对照：pwsh = PowerShell 终端；终端标签出现在编辑器标签栏里，说明它已经不是底部面板模式，而是编辑器区域终端。

Split CWD 和目录继承

官方还特别提到 terminal.integrated.splitCwd。它控制分屏终端的工作目录继承方式。

如果你经常在不同子目录开多个终端，这个设置能明显减少“为什么新终端跑到根目录了”的困惑。

Run Selected Text / Run Active File

VS Code 终端可以直接执行编辑器里选中的文本，或运行当前活动文件。这对脚本、批量命令、一次性调试非常省事。

你不必手动复制整段到终端，特别适合处理 PowerShell、Shell 片段或简单脚本。

Tasks 与 .vscode

大多数项目级自动化配置都放在 .vscode/ 里：

  • .vscode/settings.json：工作区设置。
  • .vscode/tasks.json：任务。
  • .vscode/launch.json：调试配置。

官方 Tips & Tricks 把这块归类为“workspace-specific configuration files”。也就是说，这些文件不是你的正文内容，但它们决定了项目在 VS Code 里的体验。

工作区设置和用户设置的实际边界

  • 工作区设置：适合项目约定，例如换行、缩进、排除目录、终端 cwd、搜索排除。
  • 用户设置：适合个人习惯，例如主题、字体、全局快捷键。

写小说时，如果某个设置只想影响这个项目，就尽量写入工作区而不是全局。

任务的几个典型使用场景

  1. 把常用构建命令固化成任务。
  2. 给打包/编译/预览分配明确入口。
  3. 在团队里共享同一套任务，减少“你这边怎么运行”的沟通成本。
  4. 和默认构建任务结合，用 Ctrl+Shift+B 快速执行。

终端里的链接、滚动和复制细节

官方终端文档提到很多不显眼但非常实用的能力：

  • 文件链接识别：日志里的文件路径可点击。
  • URL 识别：终端里的网址可直接打开浏览器。
  • 滚动缓冲区：默认保留一定历史行数，可调 terminal.integrated.scrollback。
  • 多行粘贴警告：防止误把大段内容直接执行。

故障排查：终端为什么不好用

  • 打不开：先看是不是 Restricted Mode / Workspace Trust 限制。
  • Shell 不对：检查终端 profile。
  • 目录不对：检查当前工作区和 terminal.integrated.cwd。
  • 渲染怪异：可尝试调整 GPU acceleration。
  • 快捷键冲突：去键盘快捷键页看终端命令映射。
