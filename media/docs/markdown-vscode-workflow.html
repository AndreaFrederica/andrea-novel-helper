VS Code 里写 Markdown 的核心工作流

VS Code 官方 Markdown 文档强调的不是“会不会写井号标题”，而是整套编辑体验：标题导航、智能补全、预览、文件内跳转、工作区链接补全。这些能力对长篇小说写作非常关键。

图上英文对照：OUTLINE = 文档大纲；Filter = 过滤；Markdown and Visual Studio Code = 当前文档主标题；Outline view = 当前选中的标题节点。

最常用的基础动作

  • Outline：根据标题层级快速跳转结构。
  • Go to Symbol：快速跳到当前文档某个标题。
  • 工作区搜索：全局搜章节、角色名和伏笔。
  • 标题补全：输入链接时自动补全工作区内 Markdown 文件和标题。

为什么标题层级特别重要

对小说正文来说，标题不只是排版，它还决定了导航结构：

  • # 常用于章。
  • ## 常用于节或场景大段。
  • ### 往下通常只在资料、长附录、结构化说明里使用。

标题层级一旦混乱，Outline、跳转和标题链接就都会变得难用。

标题和链接补全

官方 Markdown 支持在输入链接时补全文件和标题。对写作者来说，这意味着你可以较稳定地维护：

  • 章节之间的互链。
  • 世界观文档到正文的引用。
  • 设定页里的目录和索引页。

和 ANH 的组合用法

  • 用 ANH 写正文时，Markdown 仍是基础源文件格式。
  • ANH 负责角色着色、双链、标签、导出等增强。
  • VS Code 原生负责标题导航、搜索、补全、预览框架。

官方 Markdown 文档里最值得用起来的能力

  • Workspace header completions：链接时直接补全文档标题。
  • Go to header / file：从链接或命令直接跳转。
  • Document outline：把大纲视作正文导航的一部分，而不是可有可无的侧栏。
  • Rename support：重命名标题或移动文件时自动更新相关链接。

对长篇项目的建议

  1. 尽量让章节标题稳定，不要反复改到面目全非。
  2. 对经常被引用的章节或设定，优先建立标题级锚点，而不是只靠全文搜索。
  3. 正文里如果只是临时记笔记，注释优先，不要把半成品结构直接写进正式标题层级。
  4. 一旦项目开始跨文件互链，就尽量让文件移动通过编辑器完成，别在资源管理器外乱拖乱改。
