这页解决什么问题

很多新手以为“Git = GitHub”。其实 Git 是工具，GitHub/GitLab/Gitee/Codeberg/CODING 这些是托管 Git 仓库的网站。你完全可以本地用 Git，不上任何网站；也可以选一个最适合你的平台做远端同步和备份。

先记住：平台不是一回事

名字 它是什么 更偏什么场景
GitHub 全球最流行的 Git 托管平台 开源、公共协作、生态最全
GitLab 托管平台 + DevOps 工具体系 团队协作、CI/CD、可自建
Codeberg 基于 Forgejo 的非营利平台 自由软件 / 开源社区
Gitee 中国大陆本土托管平台 大陆访问、企业/政企、本土协作
CODING 腾讯系企业 DevOps 平台 企业私有协作、研发管理
Forgejo / Gitea 自建 自己部署的 Git 平台 自己掌控数据和规则

最重要的对比表

平台 私有库政策 中国大陆可访问性 内容审查 / 合规特点 一句建议
GitHub 官方文档明确支持 public / private；Free 账号可建不限数量私有库，但私有库高级能力受套餐影响 通常可访问，但速度和稳定性受网络环境影响较大 以平台规则、版权、滥用和安全规则为主；不按中国大陆本地平台逻辑治理 个人作者默认首选
GitLab.com 支持 private / internal / public 三种可见性；private 仅成员可见 在大陆通常可访问，但稳定性和速度常不如本土平台 平台规则 + SaaS / 自建双路线；如果你自建，治理策略由你定 团队和自建路线都很强
Codeberg 官方 FAQ 明确：不提供通用商业私有托管；私有内容只做有限容忍，主要服务自由软件生态 大陆一般能访问，但通常比 GitHub 更看网络状况 强调自由软件使命，不适合把它当商业私有仓库存放地 适合开源，不适合当主私有备份
Gitee 官方条款明确允许私有仓库；公开仓库无限成员，私有仓库成员数有限制 大陆访问通常最好 受中国大陆法律与平台规则约束更直接；公开内容合规要求更强，平台保留限制、下架、封禁等权利 大陆团队友好，但别忽视合规约束
CODING 偏团队/企业空间模型，私有协作是核心场景之一；具体容量和高级能力看套餐 大陆访问通常较好 同样适用中国大陆法律与平台规则；条款明确可因违规或主管部门要求采取限制措施 更像企业研发平台，不只是代码仓库
自建 Forgejo / GitLab 你自己决定 public / private 规则 取决于你部署在哪 平台规则由你定，但机房所在司法辖区仍然重要 最自由，也最费维护

关于“私有库”你必须知道的现实

  • 私有库不等于离线保险箱：私有只表示“不是所有人都能公开访问”
  • 平台仍然有规则、日志、访问控制和合规义务
  • 你不能假设任何云平台对违规内容、侵权内容、违法内容完全不介入
  • 真正最强控制权 仍然来自“本地加密备份 + 自己控制的存储 / 自建服务”

Gitee 为什么要单独提醒审查问题

因为它是中国大陆本土平台，平台条款直接适用中国大陆法律，公开页面带有备案与举报入口，条款也明确平台可在违规或按主管部门要求时采取限制、终止等措施。对一般技术项目来说这很正常，但如果你要托管的内容可能涉及题材敏感、表达敏感、版权风险高、或者你就是不希望受大陆平台规则约束，那么 不要把 Gitee 的公开仓库当成唯一主仓。

对小说作者最稳妥的思路通常是：主仓放 GitHub 或自建，国内访问需求强时再镜像到 Gitee / CODING；或者直接双远端备份。

平台逐个看

1. GitHub

  • 优点：生态最大，教程最多，第三方工具支持最好
  • 官方文档明确仓库可设为 public / private，个人免费计划支持不限数量私有库
  • 缺点：大陆访问速度和稳定性不完全可控，尤其是大附件、Release、某些静态资源
  • 适合：绝大多数个人作者、开源项目、跨国协作

2. GitLab

  • 优点：项目、分组、权限、CI/CD 一体化很完整
  • 官方文档明确支持 private / internal / public；如果是自建 GitLab，控制权更强
  • 缺点：对纯个人写作项目来说可能偏重
  • 适合：团队、组织、想要以后自建迁移的人

3. Codeberg

  • 优点：非营利、自由软件导向、技术路线透明
  • 官方 FAQ 明确说明：它不是“通用私有商业仓库托管服务”，私有内容只有有限容忍
  • 缺点：不适合长期大量私有、闭源、商业化内容
  • 适合：开源仓库、文档、社区型项目

4. Gitee

  • 优点：大陆访问好，中文环境友好，本土企业流程适配强
  • 官方条款明确允许私有仓库，并写明私有仓库成员数限制、仓库容量限制等
  • 条款同时明确：平台可在违反法律法规或网站条款时终止使用
  • 适合：大陆团队、内网外协、国内访问优先、希望降低网络波动的人
  • 不适合：把敏感公开表达放上去又假设完全不受平台规则约束

5. CODING

  • 优点：更像企业研发平台，代码托管只是其中一环，团队、权限、流水线、部署都能串起来
  • 条款明确它受中国大陆法律与监管要求约束，并保留审查、删除、暂停服务等权利
  • 比起“开源社区平台”，它更偏“企业工作台”
  • 适合：团队、企业、研发流程管理、腾讯云生态用户

图 1：个人作者怎么选

只想要一个简单又通用的远端备份？
  → GitHub

主要在中国大陆，最在意访问稳定？
  → Gitee 或 CODING

重视自由软件理念，项目本身也是开源？
  → Codeberg

想要以后自建，或者团队流程比较重？
  → GitLab / 自建 Forgejo

对小说作者最实用的 3 种组合

  1. 最省心：GitHub 私有仓库 + 本地压缩包备份。
  2. 兼顾大陆访问：GitHub 主仓 + Gitee 镜像仓。
  3. 最强调控制权：本地 Git + 自建 Forgejo / GitLab + 异地备份。
平台政策、免费额度、成员限制和高级功能会变。做长期项目时，请把“当前套餐页 / 条款页”当作最终准绳，不要完全依赖旧教程截图。
