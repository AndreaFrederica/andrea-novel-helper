这是什么文件

sensitive-words.* 是项目的敏感词库文件。初始化默认会创建 novel-helper/sensitive-words.json5，它的默认路径也可以在 project-config.json5 里改。

默认的 sensitive-words.json5 是初始化样例，不是说敏感词永远最推荐放 JSON5。按包机制，一行一个词的简单规则可以直接用 TXT；想写说明、修复建议和别名时用 Markdown；表格来源适合 CSV；结构字段很多时再用 JSON5。

它解决什么问题

它让 ANH 知道哪些词需要提示、标注或给出修复建议。常见用法包括：

  • 错别字或常错词
  • 投稿敏感项
  • 项目内部禁用表达

推荐维护方式

  • 最简单的一行一个词：可以直接用 TXT
  • 简单列表、长期人工维护、需要说明或修复建议：更推荐 Markdown
  • 原始来源是表格：先迁成 CSV
  • 带修复建议、等级、说明：更推荐 JSON5

从旧敏感词表迁移时怎么选格式

旧资料长什么样 建议目标
一个 TXT，一行一个词 sensitive-words.txt，直接一行一个词；需要额外字段时再转 sensitive-words.md
Excel / CSV，列是“原词、替换词、说明” 先保留为 sensitive-words.csv，确认识别后再决定是否转 Markdown 或 JSON5
一条词有多个替换建议、别名、优先级、颜色 sensitive-words.json5
如果你关注的是“功能怎么生效”，去看 敏感词检测；这页主要讲的是“这个文件是什么、该怎么放”。

最小 JSON5 示例

[
  {
    name: '某个不推荐词',
    type: '敏感词',
    fixes: ['推荐替换词 1', '推荐替换词 2'],
    description: '为什么不推荐使用',
  }
]

文件级建议

  • 把真正项目级规则放这里，不要散落在各章节里
  • 多人协作时，把修复建议也写清楚，避免不同人各改各的
  • 如果规则越来越多，考虑按主题拆分多个文件并在项目配置里统一指向
