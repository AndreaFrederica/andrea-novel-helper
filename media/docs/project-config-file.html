这是什么文件

project-config.json5 是 ANH 的项目级功能配置表。它主要管两类事：

  • 新建角色、词汇、敏感词、正则规则时默认写到哪个文件
  • 角色索引键默认怎么补
这里的 rolesFile、sensitiveWordsFile、vocabularyFile、regexPatternsFile 不是“整个项目只扫描这些文件”。ANH 会按包机制扫描 novel-helper/ 下的多个资源文件，也会识别当前工作区里标记出来的非 novel-helper/ 外部包。

为什么它很重要

因为它的优先级高于 VS Code 里的同名设置。也就是说，同一台电脑上不同小说项目可以用不同的资源文件路径和识别策略，而不会互相干扰。

最小示例

{
  rolesFile: 'novel-helper/character-gallery.json5',
  sensitiveWordsFile: 'novel-helper/sensitive-words.json5',
  vocabularyFile: 'novel-helper/vocabulary.json5',
  regexPatternsFile: 'novel-helper/regex-patterns.json5',
  defaultRoleLookupKeys: [],
  extendedLookupKeyPrefixes: [],
}

更符合包机制的示例

{
    rolesFile: 'novel-helper/cast-main/roles.md',
    sensitiveWordsFile: 'novel-helper/style-guide/sensitive-words.md',
    vocabularyFile: 'novel-helper/world/vocabulary.md',
    regexPatternsFile: 'novel-helper/coloring/regex-patterns.json5',
    defaultRoleLookupKeys: [],
    extendedLookupKeyPrefixes: [],
}

这样设置的含义是：以后你用“新建角色”“新建敏感词”这类命令时，默认往这些包里的文件写。它不妨碍 ANH 同时扫描其他包里的 roles.md、character-gallery.csv、vocabulary.md 等文件。

字段说明

键 作用
rolesFile 新建角色时的默认写入文件
sensitiveWordsFile 新建敏感词时的默认写入文件
vocabularyFile 新建词汇时的默认写入文件
regexPatternsFile 新建正则规则时的默认写入文件
defaultRoleLookupKeys 新建角色时默认补上的索引键字段
extendedLookupKeyPrefixes 把额外前缀识别成“索引键家族”

JSON5 和 JSON 有什么区别

JSON5 比 JSON 宽松，支持注释、尾逗号、无引号键。对人手工编辑更友好，所以 ANH 用它做项目配置。

如果你更想改项目名称、作者、标签、封面，那该看的是 anhproject.md。这两个文件是配套关系，不是替代关系。

真实优先级

project-config.json5
   > VS Code 工作区设置
   > 插件默认值

defaultRoleLookupKeys 是干什么的

它决定新建角色时默认补哪些“索引键字段”。如果你的项目会额外维护日文名、拼音名、罗马字、内部代号等字段，这里就有用。

extendedLookupKeyPrefixes 是干什么的

它是给高级用户的。如果你有一整套自定义索引字段前缀，比如 refkeys、tagkeys，你可以把前缀登记在这里，让系统把这类字段也视作索引键家族。

常见错误

  • 顶层写成数组，而不是对象
  • 路径写成绝对路径，导致项目换电脑就坏
  • 把章节正文路径误写进这里
  • 以为 rolesFile 只要指向一个文件，ANH 就不会再扫描其他角色包
  • 填了 defaultRoleLookupKeys 却不知道它只影响“默认补字段”，不是自动生成内容

推荐做法

  • 路径尽量写相对路径
  • 可以把默认写入目标指向某个包里的 Markdown 文件，例如 novel-helper/cast-main/roles.md
  • 只放项目级行为，不要把临时实验参数塞满
  • 如果项目要长期维护，把这个文件纳入 Git
