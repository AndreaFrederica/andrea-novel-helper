这一页讲什么

这页讲 Markdown 写作里最容易踩坑的三个点：链接、图片、预览。官方 VS Code 的 Markdown 工作流对这三块支持已经很完整，但前提是你要知道它的边界。

链接的常见写法

  • 站外链接：例如网页资料。
  • 同工作区文件链接：例如章节之间互跳、世界观索引页。
  • 标题链接：直接跳到某份 Markdown 文档里的指定标题。

图片路径为什么总容易错

因为 Markdown 图片通常依赖相对路径，而长篇项目又经常有深层目录。最稳的做法是：

  • 保持图片目录结构长期稳定。
  • 尽量通过 VS Code 内部的拖拽或粘贴流程插入图片。
  • 不要频繁在编辑器外直接搬动目录。

预览怎么和编辑配合

  • 侧边预览：一边写一边看渲染结果。
  • 锁定预览：防止每次切文件都把预览页带跑。
  • 预览滚动联动：大致对应编辑位置和渲染位置。

对写小说的人来说，预览的价值不只是“好看”，更是检查段落断行、引用块、表格、图片说明和导出前结构。

图上英文对照：Preview 'Readme.md' = Readme.md 的预览页；EXPLORER = 资源管理器；WORKING FILES = 当前工作文件；Readme.md = 当前正在预览的源 Markdown 文件。

ANH 环境下要额外注意什么

  • ANH 预览和 VS Code 原生预览有不同定位，前者更偏小说阅读与扩展渲染，后者更偏原生 Markdown 工作流。
  • 双链、标签、角色着色这些增强能力，最好配合稳定的文件命名和目录结构使用。
  • 如果你准备 Typst 导出，源 Markdown 的标题、分隔和图片组织应尽早保持一致。

官方 Markdown 文档里和这页直接相关的能力

  • Link validation：帮你发现失效链接。
  • Update links on file move：文件移动时更新链接。
  • Rename headers and update links：标题改名时同步相关引用。
  • Drag and drop / paste image：通过编辑器动作生成图片引用。
  • Markdown preview：原生预览与预览安全设置。
  • Preview of changes：查看 Markdown 文件的差异预览。

对大型小说项目的建议

  1. 把“目录结构稳定”当成链接稳定的前提。
  2. 对核心索引文档启用更严格的链接检查意识。
  3. 移动章节文件时尽量在 VS Code 内完成，让链接更新机制接手。
  4. 对插图、地图、人物图统一约定目录，不要一半在正文旁边、一半在随机文件夹里。
