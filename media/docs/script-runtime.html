脚本运行时是什么

脚本运行时是 ANH 的自动化工具。你可以写一些小脚本来完成重复性工作，比如批量统计字数、自动整理文件等。

脚本放在哪里

默认放在 novel-helper/scripts/ 文件夹里。支持 .js 文件。

脚本长什么样

最简单的一个脚本：

export async function run(ctx) {
    const text = ctx.activeDoc.processed;
    const count = text.length;
    ctx.output.appendLine(`当前文档字数: ${count}`);
    return "完成";
}

如何运行

  • 右键脚本文件 → "运行脚本"
  • 命令面板 → "ANH: 运行脚本"
  • 左侧"脚本运行时"面板点击脚本名

能做什么

脚本可以访问当前文档的内容、读写文件、调用外部工具等。比如：

  • 统计字数
  • 批量重命名
  • 导出数据
  • 调用 AI 工具（通过 MCP）
  • 注册生命周期 hooks 和自定义纯文本处理器

安全提示

脚本拥有完整的系统权限，请只运行你自己写的或信任来源的脚本。

脚本目录

脚本默认位于 novel-helper/scripts/ 目录下。ANH 支持 .js 和 .ts 两种扩展名，但脚本没有内置 transpiler——.ts 文件直接通过 import() 加载，能否运行取决于当前 Node.js 版本是否支持原生 TypeScript（Node.js 22+ 实验性支持）。建议优先使用 .js 文件以确保兼容性。

脚本结构

脚本必须导出一个 run 函数或默认导出：

// 方式一：命名导出 run
export async function run(ctx, args) {
    ctx.output.appendLine(`Hello, ${ctx.activeDoc.name}`);
    return "完成";
}

// 方式二：默认导出
export default async function(ctx, args) {
    ctx.output.appendLine("执行成功");
}

运行方式

  • 右键运行 — 在包管理器或文件资源管理器中右键脚本文件 → "运行脚本"
  • 命令面板 — "ANH: 运行脚本"
  • 脚本树视图 — 左侧"脚本运行时"面板列出所有可用脚本，点击即可运行

运行时上下文（ctx）

脚本执行时会注入 ctx 上下文对象：

  • ctx.activeDoc — 当前编辑器文档对象：
    • raw — 原始文本内容
    • processed — 处理后的纯文本（Markdown 会去除标记语法）
    • name / title — 文件名/标题
    • filePath / path / fullPath / uri — 文件路径
  • ctx.mcp — MCP 客户端实例，可调用已配置的 MCP 工具
  • ctx.os — Node.js os 模块
  • ctx.fs — Node.js fs 模块（原始同步/异步 API）
  • ctx.path — Node.js path 模块
  • ctx.env — 环境变量对象
  • ctx.output — ANH 输出通道，结构为 { clear, append, appendLine, show }：
    console.log 自动重定向到此通道
  • ctx.hooks — 注册生命周期回调：ctx.hooks.on(name, handler)
  • ctx.processors — 注册外挂处理器：ctx.processors.registerPlainText(meta, handler)、ctx.processors.registerTypst(meta, handler)
  • ctx.renderers — 注册独立渲染器：ctx.renderers.registerTypst(meta, handler)

Hooks 与处理器扩展

脚本如果导出 activate(ctx) 或 register(ctx)，ANH 会在脚本扩展加载时调用它。可用 hooks 包括 extensionActivated、documentSaved、beforePlainTextExport、afterPlainTextExport、beforeTypstRender、afterTypstRender。

export function activate(ctx) {
    ctx.hooks.on('documentSaved', async (event, runtime) => {
        runtime.output.appendLine(`保存了: ${event.fileName}`);
    });

    ctx.processors.registerPlainText({
        id: 'chapter-header',
        label: '章节标题增强',
        description: '导出 TXT 时给每章标题加分隔线'
    }, async (input) => {
        return input.fallbackText.replace(/^第(.+?)章(.+)$/gm, '==== 第$1章$2 ====');
    });

    ctx.renderers.registerTypst({
        id: 'simple-typst',
        label: '简单 Typst 渲染器',
        description: '不使用 Liquid 模板，直接把解析后的 blocks 生成为 Typst'
    }, async (input) => {
        const lines = ['#set page(margin: 2cm)'];
        for (const block of input.renderContext.blocks || []) {
            if (block.type === 'heading') {
                lines.push(`#heading(level: ${block.level}, [${block.text}])`);
            } else if (block.text) {
                lines.push(block.text);
            }
            lines.push('');
        }
        return lines.join('\n');
    });
}

在脚本面板可以执行“选择默认纯文本处理器”和“选择默认 Typst 渲染器”。当 Typst 渲染器不是 internal / liquid 时，Typst 导出和预览会直接调用脚本渲染器，不再要求选择 Liquid 模板。

MCP 服务器集成

MCP（Model Context Protocol）允许脚本调用外部工具：

  • 配置方式 — 在 VS Code 设置中配置 AndreaNovelHelper.mcp.servers，或在项目根目录创建 mcp.json 配置文件
  • 调用方式 — await ctx.mcp.callTool('serverName', 'toolName', params)
  • 多服务器 — 如果配置了多个启用的 MCP 服务器，脚本会同时对每个服务器运行，每个服务器一个独立实例
  • 无 MCP 模式 — 如果没有启用的 MCP 服务器，脚本以"无MCP"模式运行，ctx.mcp 为 null 或空对象
  • 可用工具 — Chrome 浏览器控制、数据库访问、文件系统操作、网络请求等（取决于配置的 MCP 服务器）

简单示例

// 统计当前文档的字数
export async function run(ctx) {
    const text = ctx.activeDoc.processed;
    const count = text.replace(/\s/g, '').length;
    ctx.output.appendLine(`当前文档字数: ${count}`);
    return { wordCount: count };
}

// 使用 MCP 工具
export async function run(ctx) {
    if (!ctx.mcp) {
        ctx.output.appendLine("没有可用的 MCP 服务器");
        return;
    }
    const result = await ctx.mcp.callTool('browser', 'navigate', {
        url: 'https://example.com'
    });
    ctx.output.appendLine(`页面标题: ${result.title}`);
}
脚本运行时拥有完整的 Node.js 权限，请确保只运行可信来源的脚本。MCP 配置优先读取 mcp.json 文件，其次才是 VS Code 设置。
