这是什么文件

.gitignore 是 Git 的忽略清单。写进这里的文件或目录，Git 默认不会跟踪。

为什么 ANH 项目里需要它

因为有些东西适合本地生成，不适合进入版本历史，比如写作统计缓存或本地历史目录。如果把这些文件也提交进 Git，仓库会很脏，历史也会膨胀。

初始化时常见内容

novel-helper/.anh-fsdb/
.history/

这两条分别是什么意思

  • novel-helper/.anh-fsdb/：写作统计数据库缓存
  • .history/：某些本地历史插件写出来的历史快照

哪些东西不要随便忽略

  • 章节正文
  • anhproject.md
  • project-config.json5
  • novel-helper/ 里你真正维护的角色、词汇、敏感词、正则规则文件
一句话：忽略“可重建的缓存”，不要忽略“真正的创作资产”。

Git ignore 和 .wcignore 不是一回事

文件 影响什么
.gitignore Git 是否跟踪文件
.wcignore ANH 的字数统计 / 某些扫描是否忽略

适合写进 .gitignore 的内容

  • 缓存目录
  • 临时导出文件
  • 自动生成但可重建的产物
  • 本地编辑器插件历史

不适合写进 .gitignore 的内容

  • 正文
  • 角色和词汇资源库
  • 项目配置文件
  • 你打算跨设备同步的真正资料

常见误区

  • 把整个 novel-helper/ 都忽略掉，结果角色词汇完全不同步
  • 把导出目录和当前正文目录混在一起，不知道哪些该忽略
  • 已经被 Git 跟踪过的文件，后来加进 .gitignore 却以为会自动消失
