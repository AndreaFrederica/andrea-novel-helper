这一页讲什么

这页专门讲 VS Code 的界面和布局。如果你刚打开 VS Code，看到左边一堆图标、下面一个面板、中间很多标签页，不知道各自是干什么的，就从这里开始。

内容主要依据 VS Code 官方的 User Interface 文档整理，但会按写作者最常遇到的场景来讲：打开项目、切换视图、整理编辑器、专注写作、找回刚才开的文件。

图上英文对照：Activity Bar = 活动栏；Primary Side Bar = 主侧边栏；Editor Groups = 编辑器分组；Panel = 底部面板；Status Bar = 状态栏。

先记住 6 个核心区域

  1. 活动栏：最左侧竖着的一排图标，用来切换资源管理器、搜索、源代码管理、运行与调试、扩展、聊天和 ANH 视图。
  2. 主侧边栏：活动栏对应打开的那块区域，例如文件树、搜索结果、Git 改动列表。
  3. 编辑器区：中间最大那块，负责显示你正在写的文件、预览页、设置页、文档页。
  4. 面板：通常在底部，默认放终端、输出、问题、调试控制台。
  5. 状态栏：最底下一整条，显示语言模式、编码、行列号、Git 分支、ANH 的统计和快捷入口。
  6. 命令面板：不是固定区域，而是按 Ctrl+Shift+P 弹出的全局入口，几乎所有命令都能从这里搜到。
VS Code 官方把侧边栏还分成主侧边栏和次侧边栏。你如果没刻意调整过布局，可以先把“左边那块看成侧边栏”就够用了。

活动栏怎么用

  • 单击图标：打开对应视图，例如资源管理器、搜索、源代码管理。
  • 再次单击当前图标：通常会收起或切换该视图。
  • 右键活动栏：可显示/隐藏某些视图入口。
  • 拖动图标：可以调整活动栏中视图的顺序。
  • 看徽标数字：某些图标上会出现数字，比如 Git 的待同步数量、扩展更新数、通知数。

对 ANH 用户来说，活动栏里最重要的通常是：资源管理器、搜索、源代码管理、扩展，以及 ANH 提供的写作相关视图。

侧边栏怎么理解

侧边栏不是“一个功能”，而是一块容器。你点不同图标，这里就会显示不同内容。

  • 资源管理器：看文件和文件夹。
  • 搜索：全项目搜索和替换。
  • 源代码管理：看 Git 改动、提交、同步。
  • 扩展：安装和管理扩展。
  • ANH 自定义视图：包管理器、写作资源管理器、字数统计等。
  • 聊天：和 Copilot 或其他 AI 交互。

如果你觉得左边太挤，可以按 Ctrl+B 暂时隐藏侧边栏，再按一次恢复。

编辑器区是什么

编辑器区就是你真正读写内容的地方。VS Code 不只用它打开文本文件，也会在这里打开设置页、键盘快捷键页、预览页、差异对比页、文档中心等。

  • 单击文件：通常以预览标签方式打开。
  • 双击文件：固定成正式标签，后面不会轻易被别的预览替换。
  • 拖动标签：调整标签顺序，或拖到另一侧形成分屏。
  • 右键标签：可以固定、关闭其他标签、复制到新窗口。

面板是什么

面板通常在底部。很多新手会把面板和侧边栏混在一起，但它们用途不一样：

  • 侧边栏更像导航和列表。
  • 面板更像输出和操作台。

最常见的面板内容包括：

  • 终端：跑命令。
  • 问题：看报错、警告、提示。
  • 输出：查看插件和系统输出。
  • 调试控制台：调试程序时用。

按 Ctrl+J 可以显示或隐藏面板。

状态栏怎么看

状态栏是最容易被忽略，但也最实用的区域。它不是摆设，很多功能都能从这里直接点开。

  • 左侧：常放 Git 分支、同步状态、问题计数、ANH 的一些状态按钮。
  • 右侧：常放行列号、空格/Tab、编码、换行符、语言模式、通知。
  • 可点击：很多状态文字本身就是按钮，例如语言模式、编码、Git 分支、ANH 字数统计。

写作时你最常点的通常是语言模式、字数统计、版式/快速设置入口和 Git 分支。

最常见的日常动作

  1. 先打开一个项目文件夹。
  2. 在活动栏点资源管理器看文件。
  3. 双击正文文件，固定成正式标签。
  4. 按 Ctrl+B 收起侧边栏，腾出写作空间。
  5. 按 Ctrl+` 临时开终端。
  6. 按 Ctrl+Shift+P 搜命令，完成不常用动作。

专注写作时的推荐布局

  • 只保留一个编辑器组：避免屏幕被切碎。
  • 收起侧边栏：用 Ctrl+B。
  • 收起底部面板：用 Ctrl+J。
  • 开启自动换行：长段落更自然。
  • 需要更沉浸时开 Zen Mode：Ctrl+K Z。
如果你是第一次用 VS Code，不建议一开始就把所有面板都藏掉。先知道它们在哪，再慢慢走向极简布局，成本更低。

布局细节：主侧边栏、次侧边栏、面板

VS Code 官方当前的工作台布局已经不仅仅是“左边 + 中间 + 下边”三块：

  • Primary Side Bar：通常在左边，放 Explorer、Search、SCM 等。
  • Secondary Side Bar：通常在右边，可容纳额外视图，例如聊天。
  • Panel：通常在底部，也可移到左/右。

如果你习惯一边看 ANH 文档或 AI 聊天，一边写正文，可以把聊天或文档拖到次侧边栏，把中间编辑器完整留给正文。

标签页与预览模式

VS Code 默认有“预览标签”概念：

  • 单击文件：通常以斜体预览标签打开。
  • 继续单击别的文件：预览标签会被复用。
  • 双击文件或开始编辑：标签会固定下来。

如果你讨厌预览标签反复替换，可在设置里关闭：

"workbench.editor.enablePreview": false,
"workbench.editor.enablePreviewFromQuickOpen": false

分屏与编辑器组

VS Code 的分屏不是只能左右两栏。你可以做横向、纵向、多组网格布局。

  • Ctrl+\：把当前编辑器一分为二。
  • 拖动标签到边缘：可创建新的编辑器组。
  • Ctrl+1 / Ctrl+2 / Ctrl+3：快速切编辑器组。
  • Ctrl+PageUp / Ctrl+PageDown：切换编辑器或终端组。

对于写作者，最常见的分屏用途是：左边正文，右边大纲/设定/预览。

Breadcrumbs、Outline、Timeline

这些都是很容易被忽略，但非常实用的导航工具：

  • Breadcrumbs：编辑器上方显示路径和当前符号层级，适合快速跳章节标题或 Markdown 标题。
  • Outline：资源管理器底部的当前文件结构树。打开长 Markdown 时很好用。
  • Timeline：看某个文件的本地历史和 Git 历史。

对 Markdown 来说，Outline 会根据标题层级返回导航结果，这一点对长篇写作特别有价值。

图上英文对照：OUTLINE = 当前文件结构树；Find / Filter = 过滤框；Follow Cursor = 跟随光标；Sort By Position = 按出现顺序排序；Sort By Name / Type = 按名称 / 类型排序。

Minimap、Sticky Scroll、Indent Guides

  • Minimap：右侧小地图，快速看整页结构。写小说时有人喜欢关掉以节省宽度。
  • Sticky Scroll：滚动时把当前所处标题或代码块的开头“钉”在顶部，避免迷路。
  • Indent Guides：缩进参考线。写大纲、列表、JSON 时很有用。
"editor.minimap.enabled": false,
"editor.stickyScroll.enabled": true,
"editor.guides.indentation": true

Zen Mode 和 Centered Layout

官方文档把这两个当成专注布局的重要能力：

  • Zen Mode：隐藏大量 UI，只保留编辑器。快捷键 Ctrl+K Z。
  • Centered Layout：让编辑器在大屏上居中，不至于一行太长。

写作时如果你觉得“一行太宽导致视线来回横跳”，比起一味调小字号，更建议开自动换行和居中布局。

通知与勿扰模式

VS Code 官方已经提供 Do Not Disturb 模式来压低通知噪音。写作冲刺时，如果各种扩展一直弹提醒，可以通过状态栏的小铃铛开启勿扰。

这对安装了较多开发扩展的用户特别重要，否则你会在写作时不断被 lint、同步、更新等提示打断。

浮动窗口与多显示器

新版本 VS Code 支持把编辑器、终端甚至某些视图拖成独立浮动窗口。如果你有双屏：

  • 主屏放正文。
  • 副屏放预览、终端、文档、角色资料。

这比传统分屏更适合长时间写作，因为正文区不会被辅助面板侵占宽度。

界面问题的排查思路

  1. 先确认是哪个区域不见了：活动栏、侧边栏、面板、状态栏还是标签页。
  2. 优先去 View 菜单或命令面板搜索 Toggle 对应项。
  3. 再检查有没有开 Zen Mode、Centered Layout、全屏或自定义布局。
  4. 如果只是文件列表看不到某些目录，再检查 files.exclude 和 explorer.excludeGitIgnore。
