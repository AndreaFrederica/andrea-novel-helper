先别急着学命令，先理解“版本管理”

如果你现在的工作方式是“写到一个节点就复制一个文件夹，命名成 第3章最终版、第3章最终版2、第3章真的最终版”，那你其实已经在做一种很原始的版本管理了。

版本管理到底是什么

版本管理就是：把文件在不同时间点的状态，按顺序保存下来，并且能回答下面这些问题：

  • 我什么时候改了这段文字？
  • 我上周删掉的那段设定还能找回来吗？
  • 这次改动到底改了哪几行？
  • 我能不能在不破坏当前正文的情况下，试一版新剧情？
  • 两台电脑之间怎样同步，而不是互相覆盖？

为什么“复制粘贴式备份”不够用

做法 优点 问题
手工复制文件夹 直观 占空间、容易漏备份、看不出两版差异、文件名越来越混乱
网盘自动同步 省心 更擅长“同步当前状态”，不擅长“解释历史差异”
Git 既能保存历史，又能比较差异，还能同步到云端 前期要理解几个基本概念

Git 不是云盘，它更像时间机器 + 变更账本

普通备份关注的是：
“现在有一份副本”

Git 关注的是：
“这个项目从过去到现在是怎么一步步变成现在这样的”

你最该先认识的 6 个词

词 人话解释
仓库 Repository 一个被 Git 管理的项目目录
提交 Commit 一次有说明的版本快照
差异 Diff 这一版和上一版到底哪儿不同
分支 Branch 在主线之外开一条平行修改线
远端 Remote 放在云上的那份仓库，比如 GitHub 上的项目
同步 Push / Pull 本地和远端之间上传 / 下载提交

为什么小说作者也该用版本管理

  • 你会反复改稿：小说不像一次性文档，反复推翻很正常
  • 设定会互相牵连：角色、时间线、词汇表、正文常常一起改
  • 你可能跨设备写作：台式机、笔记本、甚至不同地点
  • 你可能会后悔：而 Git 的意义，就是让“后悔”变得廉价
  • 你以后可能协作：编辑、合作者、校对都需要清晰历史
如果你只记住一句话，请记住：版本管理不是为了炫技，而是为了让你敢改、敢试、敢回退。

版本管理不只是“回滚”

新手容易把 Git 理解成“撤销工具”，其实它至少有 4 个用途：

  1. 记录历史：知道每次改了什么。
  2. 安全试验：开分支写另一版剧情。
  3. 同步备份：把本地项目推到云端。
  4. 协作合并：多人修改后再合并到一起。

提交为什么比“保存”更重要

保存只是把当前文件写到磁盘；提交则是在说：

“我确认这一组修改值得被记成一个可解释的版本。”

所以好的提交通常满足三件事：

  • 边界清楚：这次提交解决了一件相对完整的事情
  • 说明清楚：别人或未来的你看得懂
  • 可回退：如果不满意，可以整组撤回

什么时候该提交

  • 写完一场戏
  • 补完一组角色设定
  • 改完一轮措辞或校对
  • 准备切设备之前
  • 准备尝试风险较大的大改之前

不该把 Git 当成什么

  • 不该把 Git 当唯一备份手段
  • 不该把 Git 当自动整理工具，乱提交只会制造垃圾历史
  • 不该把远端私有仓库当作“绝对保密保险箱”
