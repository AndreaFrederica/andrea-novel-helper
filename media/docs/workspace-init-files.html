工作区初始化会创建哪些文件

运行项目初始化向导后，ANH 会在你的工作区中自动创建以下文件和目录。它们是 ANH 正常工作的基础。

项目根目录文件

  • anhproject.md — 项目的"身份证"，包含项目名称、作者、描述、UUID、标签等元数据
  • project-config.json5 — 项目的功能配置表，定义了各类资源文件的路径和识别关键词
  • .gitignore — 告诉 Git 哪些文件不用备份（如写作统计缓存）
  • .wcignore — 告诉字数统计哪些目录不用统计（如 .vscode/）

novel-helper/ 资源目录

这是 ANH 的核心资源目录，所有角色、词汇、敏感词、正则规则都存放在这里。

  • novel-helper/character-gallery.json5 — 示例角色库（JSON5 格式），包含一个配角示例
  • novel-helper/character-gallery.csv — 示例角色库（CSV 格式），与上面内容相同，格式不同
  • novel-helper/sensitive-words.json5 — 示例敏感词库，包含两个敏感词示例
  • novel-helper/vocabulary.json5 — 示例词汇表，包含两个世界观专有名词
  • novel-helper/regex-patterns.json5 — 正则着色规则库，内置中文引号、书名号等标点符号的着色规则
  • novel-helper/roles.md — Markdown 格式的示例角色，展示完整的角色定义写法
这些文件都是初始化样例，不是推荐你以后永远只维护这几个根目录 JSON5 文件。按包机制，更成熟的做法通常是把资源拆到多个子目录和多个独立文件里：手工长期维护优先 Markdown，Excel / 表格来源优先 CSV，复杂结构再用 JSON5。想看完整理由，直接读 包机制与外部包详解。

正则着色规则文件详解

regex-patterns.json5 是初始化时自带的正则匹配规则库。它为你的小说提供了默认的标点符号着色：

如果你不只是想知道“这里有四条规则”，而是想弄明白这些规则为什么这样写、以后怎么自己改，可以继续看 正则表达式入门。
  • 中文引号 "" — 金色（#fbdc98ff），匹配双引号内的对话内容
  • 角引号 「」 — 金色（#fbdc98ff），匹配角引号内的对话内容
  • 单引号 '' — 浅蓝色（#98bbfbff），匹配单引号内的思考内容
  • 书名号 《》 — 橙色（#fbbc98ff），匹配书名号内的内容

每条规则包含以下字段：

  • name — 规则名称
  • type — 固定为 "正则表达式"
  • regex — 正则表达式 pattern
  • regexFlags — 正则标志（如 g 表示全局匹配）
  • color — 匹配到的文本的着色颜色
  • priority — 优先级（数值越小优先级越高）
  • description — 规则描述

初始化文件结构

向导根据用户选择创建文件。以下是一个初始化后的起步结构，不是成熟项目的唯一推荐终局：

workspace/
├── anhproject.md              # 项目元数据
├── project-config.json5       # 功能配置
├── .gitignore                 # Git 忽略规则
├── .wcignore                  # 字数统计忽略规则
└── novel-helper/
    ├── character-gallery.json5  # 角色库 (JSON5)
    ├── character-gallery.csv    # 角色库 (CSV)
    ├── sensitive-words.json5    # 敏感词库
    ├── vocabulary.json5         # 词汇表
    ├── regex-patterns.json5     # 正则着色规则
    └── roles.md                 # 示例角色 (Markdown)

更符合包机制的长期结构

项目真正写起来以后，更常见的演化结果会像这样：

workspace/
  ├── anhproject.md
  ├── project-config.json5
  ├── 第01章 初到星港.md
  ├── 第02章 失控的货舱.md
  └── novel-helper/
    ├── cast-main/
    │   ├── roles.md
    │   └── character-gallery.csv
    ├── world/
    │   └── vocabulary.md
    ├── style-guide/
    │   └── sensitive-words.md
    └── coloring/
      └── regex-patterns.json5

也就是说：初始化默认文件主要负责“把系统点亮”，而成熟项目通常会继续按包拆分。

anhproject.md

项目元数据文件，使用 Markdown 格式存储。包含 ## 分节的键值对：项目名称、描述、作者、UUID、封面、摘要、标签、文件关键词、创建时间、更新时间。UUID 由向导自动生成（uuidv4()）。

project-config.json5

项目级配置文件（JSON5 格式），定义资源文件路径映射和文件识别关键词：

  • rolesFile — 角色库文件路径
  • sensitiveWordsFile — 敏感词库路径
  • vocabularyFile — 词汇表路径
  • regexPatternsFile — 正则规则路径
  • defaultRoleLookupKeys — 默认角色查找键
  • extendedLookupKeyPrefixes — 扩展查找键前缀

正则着色规则 (regex-patterns.json5)

每条规则的完整字段：

  • name — 规则名称（显示在匹配结果中）
  • type — 固定为 "正则表达式"
  • regex — JavaScript 正则表达式 pattern
  • regexFlags — 正则标志（g 全局 / i 忽略大小写 / m 多行）
  • color — 匹配文本的着色颜色（HEX/RGB/HSL）
  • priority — 优先级（数值越小越优先，重叠时先处理优先级更高的规则）
  • description — 规则描述
  • uuid — 唯一标识符（可选）

.gitignore / .wcignore

向导会修改（而非覆盖）已有的 .gitignore 和 .wcignore：

  • .gitignore — 默认排除 novel-helper/.anh-fsdb/（写作统计缓存）和 .history/（本地历史）
  • .wcignore — 默认排除 .vscode/ 和 .out-of-code-insights/，避免字数统计误计入

novel-helper/ 资源文件格式

每个资源文件支持多种格式。向导默认给你放几个 JSON5 / CSV / Markdown 样例，但这不代表 JSON5 永远是第一推荐：

  • Markdown — 最适合手工长期维护；可读性最好，也最符合包机制鼓励的“拆分手册式资源”
  • CSV — 最适合从 Excel / 表格软件迁入，或者做大量简单条目导入
  • JSON5 — 最适合字段复杂、样式多、结构化强的条目
  • TXT — 纯文本格式，适合简单列表
向导执行的所有操作均可手动撤销或修改。如果你已有项目，也可以直接创建 anhproject.md 和 project-config.json5 来激活 ANH。
