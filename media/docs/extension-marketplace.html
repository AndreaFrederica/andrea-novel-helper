官方 VS Code 默认在用什么市场

官方 VS Code 文档里说的“Extension Marketplace”，默认指的是 Visual Studio Marketplace。你在扩展视图里搜扩展、查看评分、点 Install，通常走的就是这条路径。

最常用的入口

  • Ctrl+Shift+X 打开扩展视图。
  • 搜索框 输入扩展名、作者名或功能关键词。
  • 详情页 查看简介、命令、设置、支持的语言和功能贡献。
  • 齿轮菜单 处理禁用、卸载、降级、安装其他版本等管理动作。
图上英文对照：Extensions: Marketplace = 扩展市场列表；Install = 安装；Repository = 仓库主页；License = 许可证；Details = 详情； Contributions = 功能贡献；Changelog = 更新日志。

你在市场里通常会看到什么

  • 扩展名称和发布者：先确认是不是你要的那个作者。
  • 安装量、评分、更新日期：用来快速判断活跃度和维护情况。
  • 功能截图和 README：决定它到底做什么。
  • Feature Contributions：看它加了哪些命令、设置、语言支持、视图、菜单。
  • Dependencies / Extension Pack：看它是否依赖其他扩展，或本身是否是扩展包。

安装、禁用、卸载的区别

  • 安装：把扩展加入当前编辑器环境。
  • 禁用：保留已安装状态，但暂时不让它生效。适合排查冲突。
  • 卸载：彻底移除。适合确定不再使用时。

很多排查工作都应该先“禁用试试”，而不是直接卸载。

推荐、过滤和分类

官方 Marketplace 支持按分类、关键字、推荐来源来浏览扩展。你会看到类似这些场景：

  • 搜索关键词：例如 markdown、git、theme、spell。
  • 推荐扩展：根据语言、工作区或常见工作流给出建议。
  • 工作区推荐：某个项目通过配置告诉团队“建议装这些扩展”。
  • 扩展包：一次装进一组互相关联的扩展。

离线或手动安装：VSIX

官方扩展系统支持从 .vsix 文件安装扩展。这种方式适合：

  • 企业或校园网络限制较多。
  • 你需要锁定某个明确版本。
  • 扩展作者直接提供 VSIX，而不是要求你在线搜。

但要注意，能否成功安装只是第一步，扩展运行时是否还依赖外部服务是另一回事。

管理动作不只是“装完就完”

官方文档里，扩展管理至少包含下面几类常见操作：

  • Update：更新到新版本。
  • Disable (Workspace)：只对当前工作区禁用。
  • Disable (Always)：全局禁用。
  • Install Another Version：回退或切换版本。
  • Install from VSIX：从离线包安装。
  • Show Installed Extensions：只看本机已装内容。

对写作者最实用的不是“永远装更多”，而是会分辨哪些扩展应该长期启用，哪些扩展只在特定工作流或特定项目里启用。

推荐扩展和工作区扩展

官方扩展生态支持把“推荐装哪些扩展”记录到工作区配置里。这样团队成员或另一台设备打开项目时，就更容易装齐同一套工具链。对 ANH 项目来说，这个能力尤其适合：

  • 统一 Markdown 预览增强扩展。
  • 统一 Git 辅助扩展。
  • 统一主题、字体或拼写检查工作流。
  • 区分“写小说项目需要的扩展”和“你个人开发环境需要的扩展”。
图上英文对照：Feature Contributions = 功能贡献；Categories = 分类；Resources = 资源链接；Marketplace / Repository / License = 市场页 / 仓库 / 许可证；Install = 安装按钮。

安全、签名和企业限制

官方 Marketplace 文档已经把安全和来源管理讲得更细了，尤其是签名校验、企业环境 allowlist 之类的能力。普通个人用户不一定每天都会碰到，但至少要知道一点：扩展不是只看功能，还要看来源、维护者、更新频率和安装方式。

排查“装了扩展后编辑器不对劲”的基本顺序

  1. 先看扩展详情页最近更新时间和变更说明。
  2. 再用禁用动作判断是不是这个扩展导致的。
  3. 必要时为当前工作区单独禁用，而不是直接影响所有项目。
  4. 如果需要回滚，使用“安装其他版本”或临时改用 VSIX。
  5. 如果你用的不是官方 VS Code，再确认问题是不是扩展源差异导致的。

对 ANH 用户的实际建议

  • 写作核心环境：优先保证 ANH、Git、Markdown 预览、拼写或输入法辅助这几类稳定。
  • 花哨增强：主题、图标、动画类扩展尽量后装，避免把问题来源搞复杂。
  • 出现冲突时：优先按工作区禁用，保留你其他项目的使用习惯。
  • 跨编辑器切换时：不要默认 Marketplace 和 OpenVSX 上的可用扩展完全一致。
如果你现在用的是 VSCodium 或其他 code-compatible editor，请继续看 OpenVSX 与兼容编辑器；如果你想把扩展安装、设置范围和工作区定制串起来，再回到 设置、配置与扩展。
