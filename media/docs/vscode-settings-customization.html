这一页讲什么

这页讲 VS Code 的设置、工作区配置、主题、扩展。如果你已经知道“设置页在哪里”，但还不清楚“为什么有些设置只影响当前项目、有些会影响所有项目”，这页就是给你的。

用户设置和工作区设置

官方 Settings 文档里最重要的概念就是两个层级：

  • 用户设置：影响你这台电脑上的所有 VS Code 项目。
  • 工作区设置：只影响当前打开的项目。

例如：

  • 你想所有项目都用更大的字体，这是用户设置。
  • 你只想当前小说项目自动换行，这是工作区设置。
  • 你只想当前项目隐藏某些目录，也是工作区设置。

怎么打开设置页

  • Ctrl+,：打开设置编辑器。
  • 命令面板：搜 Preferences: Open Settings。
  • 齿轮菜单：左下角设置图标。

设置页怎么用

  • 顶部搜索框：输入关键词筛选设置。
  • User / Workspace 标签：切换修改范围。
  • 齿轮按钮：可重置、复制设置 ID、复制 JSON 写法。
  • 修改后立即生效：多数设置不需要重启。

这套体验和 ANH 自己的图形化设置页不同，但底层思想相同：都是在修改配置值。

图上英文对照：Settings = 设置页；User = 用户设置；Workspace = 工作区设置；Settings Found = 搜到的设置数量；Text Editor / Features / Debug = 设置分类；Modified elsewhere = 已在其他作用域被改过。

什么是 settings.json

VS Code 最终会把设置写入一个 JSON 文件，名字叫 settings.json。

  • 用户 settings.json：全局生效。
  • 工作区 settings.json：通常在当前项目的 .vscode/settings.json。

如果你不想碰 JSON，完全可以只用图形界面；但至少要知道这个文件存在，因为很多教程和错误提示都会提到它。

最值得先会的几个设置关键词

  • word wrap：自动换行。
  • font size：字体大小。
  • minimap：小地图。
  • files exclude：隐藏文件夹。
  • search exclude：搜索排除。
  • auto save：自动保存。
  • theme：主题。

主题和图标主题

VS Code 官方把主题分成两种：

  • Color Theme：整个界面的颜色风格。
  • File Icon Theme：文件图标样式。

如果你长期写作，找到一个眼睛舒服的主题非常重要。比起追求“好看”，更建议优先考虑：长时间阅读不刺眼、Markdown 标题层级明显、差异对比颜色容易看懂。

扩展是什么

VS Code 的很多能力来自扩展。ANH 自己就是一个扩展。

  • 打开扩展页：Ctrl+Shift+X
  • 搜索扩展：输入名字或功能关键词。
  • 安装扩展：点 Install。
  • 卸载/禁用扩展：进入扩展详情页操作。

新手常见误区是装太多扩展。建议先围绕实际需求装：写作、预览、版本管理、字体/主题，而不是一口气装几十个。

Settings Editor 过滤器

官方设置页有一整套过滤器系统，很适合中高级用户排查问题：

  • @modified：看你改过哪些设置。
  • @id:setting.name：按准确 ID 找设置。
  • @ext:publisher.extension：只看某个扩展贡献的设置。
  • @feature:explorer：只看某个功能组。
  • @lang:markdown：看某语言的可配置项。

其中 @modified 特别实用。只要编辑器行为异常，先看自己改了哪些设置，而不是直接怀疑扩展。

语言专属设置

官方文档强调，语言专属设置会覆盖一般设置。写法类似：

"[markdown]": {
  "editor.wordWrap": "on",
  "editor.renderWhitespace": "all"
}

这对写作者很有价值，因为你可以：

  • 让 Markdown 自动换行。
  • 让 JSON5 自动格式化保存。
  • 让日志文件使用不同字号或显示规则。

设置优先级

官方优先级从低到高大致是：

  1. 默认值
  2. 用户设置
  3. 工作区设置
  4. 语言专属设置
  5. 策略限制（企业环境）

这就是为什么“我明明在全局里设了 X，怎么当前项目还是 Y”：通常是工作区设置或语言专属设置把它覆盖了。

settings.json 的类型和合并规则

官方说明里还有一个非常容易被忽略的点：不同类型的设置覆盖方式不同。

  • 字符串 / 布尔 / 数字：通常直接被高优先级覆盖。
  • 数组：一般也是整体覆盖。
  • 对象：很多会做合并，例如 workbench.colorCustomizations、search.exclude 之类。

Profiles 与 Settings Sync

官方现在提供 Profile 和 Settings Sync：

  • Profile：一套完整使用风格，可以为“写作”“前端开发”“Python 调试”各建一套。
  • Settings Sync：把设置、快捷键、已安装扩展同步到其他设备。

如果你有多台电脑写作，Settings Sync 很省事；如果你同一台电脑要兼顾多种工作流，Profiles 更重要。

扩展设置和 Feature Contributions

官方文档提到，扩展的设置也会进入 Settings Editor 的 Extensions 分组。你还可以在扩展详情页的 Feature Contributions 看它加了哪些命令、设置、语言支持。

这对 ANH 用户特别有帮助，因为很多“这个插件到底加了什么”都能在这里快速看到。

Theme、File Icons、Customizations

除了切主题，你还能继续细调：

  • workbench.colorTheme：颜色主题。
  • workbench.iconTheme：文件图标主题。
  • workbench.colorCustomizations：自定义具体 UI 颜色。
  • editor.tokenColorCustomizations：细调语法着色。

如果你只是写小说，不建议一开始就沉迷颜色微调。先把主题、字号、自动换行、排除目录这四类设置调顺手，收益最高。

常见错误：Unable to write settings

官方 FAQ 里专门提到，如果 VS Code 报“Unable to write settings”，通常意味着 settings.json 语法坏了，比如：

  • 少了逗号。
  • 值类型不对。
  • 某个对象花括号没闭合。

这时不要盲目重装扩展，先打开 JSON 文件，看红色波浪线。
