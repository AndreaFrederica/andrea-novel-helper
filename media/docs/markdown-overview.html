这一组文档在解决什么问题

ANH 的日常写作离不开 Markdown，但这个“大类”其实包含两套不同问题：

  • 正文怎么用 Markdown 写得顺手。
  • 项目里的角色、词汇、关系、时间线等资源文件应该选什么格式。

以前这些内容主要压在一篇“文件格式指南”里，现在拆成独立分类，方便按工作流阅读。

建议阅读顺序

  1. VS Code 里的 Markdown 工作流：先搞清编辑、Outline、标题跳转、自动补全这些基础动作。
  2. 链接、图片与预览联动：解决链接失效、图片路径、双栏预览、移动文件后链接更新。
  3. Mermaid、KaTeX 与高级块：补图表、公式和预览安全边界。
  4. 文件格式指南：最后再回来看 ANH 资源文件为什么会分成 Markdown、JSON5、CSV、TOML、XJSON5 这些格式。

写作者先记住两件事

  • 正文章节文件 用标准 Markdown。
  • 资源文件 不一定都该用同一种格式，应该按“手写舒服”还是“结构严格”来选。

和角色系统的边界

roles.md 这种文件虽然也是 Markdown，但它属于角色系统的建模文档；这里更侧重的是 Markdown 作为一种写作格式、预览格式和链接格式怎样在 VS Code 里工作。

为什么 Markdown 不能只讲语法糖

很多教程把 Markdown 讲成“标题、粗体、列表、表格”就结束了，但对 ANH 用户真正关键的是下面这些工程化问题：

  • 标题结构怎样影响 Outline 和导航。
  • 文件移动后链接怎样自动更新。
  • 图片路径怎样保持跨目录稳定。
  • 预览、复制、导出、Typst、双链、标签之间的边界在哪里。
  • 什么内容该继续留在 Markdown，什么内容该改成 JSON5、CSV 或专用图形文件。

这组文档的定位

  • Markdown 原生工作流：对齐 VS Code 官方 Markdown 文档。
  • ANH 的写作增强：解释双链、标签、角色着色、导出链路。
  • 格式选择：把“写作正文”和“结构化资源”分开处理。
如果你现在最具体的困扰是“我只想知道某个文件到底该用什么扩展名”，可以直接跳到 文件格式指南。
