## 🎭 角色与资源体验增强

### 包管理器：资源文件和常用入口

这些变更发生在左侧包管理器树视图中，主要解决“文件里有什么角色”和“常用功能从哪里打开”的问题：

- **文件+角色一体化**：`.md` / `.json5` / `.ojson5` 等角色文件旁显示角色数量，展开后列出该文件中的全部角色。
- **拖放/复制过滤**：拖放、复制、剪切时自动过滤角色层级节点，只操作真实文件系统节点，避免误把角色条目当文件移动。
- **常用功能节点**：新增“常用功能”根节点，集中放置项目初始化向导、项目设置、引用维护、外部资源、Copilot 文档释放、功能引导、文档中心等入口。
- **项目设置文件节点**：新增“项目设置文件”根节点，直接展示 `anhproject.md` 和 `project-config.json5` 的存在状态。

### 角色树：显示与展开控制

这些变更发生在侧边栏“角色”面板，用于改善角色列表的可读性：

- **SVG 图标支持**：角色数据含 `svg` 字段时，可渲染为角色节点图标（需开启设置）。
- **角色名称着色**：开启后角色名旁显示颜色预览色块，颜色字段值也以色块展示。
- **详情展开控制**：支持配置角色属性节点是否可展开、属性文本自动折行宽度等。

### 预览面板：按角色类型着色

这些变更发生在写作预览/阅读器面板，用于控制正文里哪些角色名会被高亮：

- 新增**角色类型多选开关**，可以只给主角着色，也可以只给主角和正则表达式着色。
- 敏感词、词汇等类型可以从预览着色中排除，避免预览画面过于杂乱。
- 内置类型默认色：主角（金 `#FFD700`）、配角（淡蓝 `#ADD8E6`）、联动角色（淡绿 `#90EE90`）、正则表达式（橙 `#FFA500`）。

### 角色查询键：补全和检索能力

这些变更影响角色补全、正文匹配、引用索引和 AI/工具侧检索，让角色可以用多种语言和拼写形式被找到：

- **查询键家族**：自动识别 `lookupKeys` / `searchKeys` / `queryKeys` / `keywords` / `检索键` / `索引键` 等字段。
- **拼音自动生成**（`pinyin-pro`）：中文姓名 → 无调拼音，例如“林克”生成 `lin ke` / `linke` / `lk`。
- **日文假名罗马字**（`wanakana` / `kuroshiro`）：日文假名/汉字 → Hepburn 罗马字。
- **通用罗马字**（`transliteration`）：多语种文本转写。
- **智能 LLM 转写**：本地 LLM 为韩文、日文难译姓名生成候选转写。
- **扩展前缀**：自定义 `refkeys`、`tagkeys` 等字段，也可被识别为查询键家族成员。

> 自动生成选项默认关闭，需要在设置中开启 `lookupKeys.autoGeneratePinyin` / `lookupKeys.autoGenerateRomanized`。

### 角色补全：多段前缀匹配

针对中文等**无空格语言**，补全现在会从光标前提取最多 **8 个分词段**、最长 **48 个字符**的组合作为候选前缀。

例如输入“愤怒的孙悟空”时，系统会依次尝试“愤怒的孙悟空”→“的孙悟空”→“孙悟空”，找到最长有效匹配后替换整个前缀。

### 项目配置：角色索引默认字段

这些变更写在 `project-config.json5` 中，影响新建角色和查询键识别规则：

- **默认角色索引键**：新建角色时自动补齐指定空数组字段，例如 `lookupKeys_jp`、`lookupKeys_en`。
- **扩展索引键前缀**：自定义前缀，例如 `refkeys`、`tagkeys`，会被系统识别为查询键家族成员。

## 📊 文件追踪与写作统计可靠性升级

### 文件追踪全面异步化

核心 API 从同步阻塞改为异步，侧边栏和状态栏不再卡顿。

### SQLite 后端初始化保护

- 给予最多 **15 秒**初始化窗口，期间操作排队缓存
- 超时未就绪则**自动回退 JSON 分片存储**，扩展始终可用
- 就绪后自动 Drain 排队操作并导入旧数据

### 智能路径修复

新增 `AndreaNovelHelper.fileTracking.repairPathKeys` 命令，一键修复：

- Windows 大小写混乱
- 绝对/相对路径混用
- 同一路径映射到多个 UUID 的冲突
- 元数据丢失时从磁盘重新扫描重建

### 写作统计高性能数据层

为统计仪表板设计的**轻量摘要系统**：

- **项目级摘要**：总时长、今日统计、24小时热力图、日粒度历史
- **单文件索引**：每文件的 CPM、字符增减、活跃时间、最后活跃时间
- **秒开体验**：Dashboard 直接从摘要读取，无需遍历所有文件
- **增量更新**：单文件修改只更新该文件摘要，防抖重建避免频繁写盘

## 🛠️ 修复与可靠性提升

这些修复主要来自 0.4.65 之后的文件追踪、预览、补全和 AI 集成重构，重点解决“功能已经有，但在复杂项目里偶发失效或不稳定”的问题。

### 预览面板角色着色恢复稳定

- 修复预览角色着色偶发失效的问题：Webview 重建、页面脚本尚未加载或角色数据刷新时，不再依赖扩展侧抢先推送导致消息丢失。
- 角色着色改为 Webview 主动请求数据；角色库变化时扩展只发送“角色颜色已变化”通知，再由预览页拉取最新角色和高亮范围。
- 高亮范围改为基于正文纯文本块和角色匹配结果重新计算，支持别名、修复词、查询键和正则角色，并按当前启用的角色类型过滤。
- DOM 更新后会自动补充着色，同时避免着色节点自身触发 MutationObserver 反复重入。

### 文件追踪与写作统计修复

- 文件创建、删除事件加入防抖，减少批量操作、重命名和保存时的重复刷新、重复索引和目录统计抖动。
- 删除、重命名等异步文件追踪操作会等待持久化完成，避免数据库和侧边栏状态短时间不一致。
- 修复 SQLite 后端初始化窗口中的竞态：初始化未完成时先排队写操作，并优先查询持久化路径映射，避免为已存在文件生成新 UUID。
- 修复路径索引历史脏数据：绝对路径、相对路径、Windows 大小写差异和同一路径多 UUID 冲突都可以被统一修复。
- 修复写作统计摘要在文件删除、重命名、路径修复后可能不一致的问题；摘要失效时会标记并防抖重建。

### 补全、包管理器与 AI 接口修复

- 修复中文等无空格文本下角色补全只匹配最后一个分词，导致完整角色名无法补全或替换范围错误的问题。
- 包管理器拖拽、复制、剪切会过滤角色层级节点，只操作真实文件系统节点，避免误把角色条目当文件移动。
- MCP HTTP 服务器错误响应不再暴露内部异常/堆栈信息，`.vscode/mcp.json` 写入日志也统一进入扩展日志。
- 优化 VS Code Webview 资源映射，补充 `vscode-webview` / `vscode-resource` 协议兼容，减少工作台和热力图资源加载失败。

## 🧩 2026-05-07 补充：创作工作台与图谱能力

### 创作工作台

包管理器的“常用功能”中新增 **+ 创作工作台**。它把写作相关的计划、任务、时间记录和快速入口集中到一个工作台里：

- 支持时钟、计时器、写作日志、任务列表、甘特任务、年度计划等组件。
- 支持自由平铺窗口，组件可以拖动、调整大小、置顶和独立查看。
- 支持工作台组件顶栏配置，常用窗口可以更快整理到适合自己的布局。
- 写作统计摘要会优先用于工作台，避免每次打开都遍历全项目文件。

### 时间线甘特与任务四象限

时间线与任务管理补充了更适合长期规划的视图：

- **时间线甘特图编辑器**：把时间线事件以横向计划方式展示，便于安排章节、剧情阶段和伏笔回收。
- **工作台甘特组件**：可在创作工作台中嵌入任务/时间线视图。
- **任务四象限**：按重要/紧急维度整理待办，适合拆分本周写作目标、修改任务和资料整理任务。
- 时间线保存逻辑拆分为同步与保存两步，减少编辑器和工作台之间互相覆盖的风险。

### 批注管理器

新增独立的 **批注管理器** 页面，用于统一处理项目批注：

- 集中查看当前项目中的批注线程。
- 支持从批注列表跳转到原文位置。
- 批注存储结构升级，保留回复、解决状态和锚点信息。
- 适合管理伏笔、修改意见、审稿反馈和待补资料。

### 角色关系图谱

新增 **角色关系图谱**，用于查看角色库中的引用和关系网络。它不是 `.rjson5` 文件的单图编辑器，而是面向整个角色库的聚合图谱：

- 数据来源包括角色文件内引用、角色 `relations` / `relationships` 标记，以及 `.rjson5/.json5` 关系表。
- 仅扫描合法包目录内的角色资源，角色文件中引用到另一个角色记为一次引用。
- 使用 Sigma.js / Graphology 渲染接近 Obsidian 的网络图效果。
- 支持力导向、环形、中心层级、按类型分组、选中角色放射等布局策略。
- 支持连线显示策略：全部连线、只显示高亮、只看选中角色、隐藏自动引用边、智能聚焦。
- 选中角色后可只显示一跳网络，并在侧栏查看与其他角色的关系及关系元数据。
- 悬停角色可高亮一级邻居和连线；该行为可单独关闭。
- 角色 Hover 卡片可单独开关，内容参考正文 Monaco Hover，展示描述、类型、从属、别名、修复、扩展字段、颜色和一级关系。
- Hover 内容过长时可用可配置快捷键捕获滚轮滚动卡片，默认 `Ctrl + 滚轮`。

## 🧭 0.5.2：图形化快速设置与角色编辑器升级

### 交互式设置向导

图形化快速设置新增真正的分步设置向导，用于把常见写作配置整理成可理解、可调整、可暂存的流程：

- 第一步只选择写作场景，场景只负责填入预设，不会直接保存设置。
- 后续按模块逐项确认：编辑器显示、智能编辑、补全与查询键、角色列表、AI 与错字系统、状态栏。
- 每个模块都可以单独启用或跳过，并且可以在保存前调整具体值。
- 最后一步提供“取消 / 暂存 / 保存”，暂存只更新快速设置界面，保存才写入 VS Code 设置。
- 首次打开当前版本的图形化快速设置时，会先询问写入项目设置还是全局设置，再询问是否打开设置向导。

### 写作场景预设重新校准

设置向导的预设按写作习惯重新收敛：

- 所有场景的 `editor.wrappingIndent` 都改为 `none`，避免折行后出现代码式缩进，更符合小说写作阅读习惯。
- 中文写作场景下 `editor.tabSize` 默认使用 `4`，配合段首缩进更接近两个中文字符的视觉宽度。
- “通用写作”保持保守默认；“专注起草”只调整编辑器、智能编辑和状态栏；“角色密集”只强化补全与角色列表；“AI 校对”只启用错字/LLM 相关模块。
- AI 校对不默认开启自动打开扫描和变更扫描，避免在用户未明确确认前发送文档内容。

### 快速设置覆盖范围扩展

图形化快速设置补充了更多常用配置，并把复杂配置换成更容易理解的图形化编辑器：

- 新增 Markdown 描述渲染组件，设置说明中的粗体、代码、列表和代码块可以正确显示。
- 新增 LLM 模型选择器，支持自动拉取兼容 API 的模型列表，也允许手动输入自定义模型名。
- 自动补齐括号对、里程碑目标、角色自定义分组等数组/对象类设置支持图形化编辑。
- AI、错字系统、查询键生成、包管理器行为、VS Code 托管禁用、状态栏显示等设置被纳入快速设置。
- 每个设置项显示当前值来源，区分默认、全局和工作区设置；布尔项也能显示当前是否显式设置。

### 角色列表预览与详情折行

角色列表相关设置现在有独立预览，并且尊重不同角色列表的隔离配置：

- 当前文章角色、全部角色、包管理器角色节点分别使用各自设置，不再混用预览状态。
- 新增角色列表预览组件，按实际角色列表实现展示分组、颜色、SVG 图标和详情展开效果。
- 新增角色详情折行开关；路径、URI、UUID、正则、SVG/图标等内容始终保持不折行，避免关键信息被拆断。
- 角色详情折行逻辑抽出为共享工具，角色树、当前文章角色视图和包管理器角色节点保持一致。

### 角色卡 JSON5 编辑器体验

角色卡 JSON5 可视化编辑器继续向表格化、可预览和可生成方向调整：

- 新增表格化角色卡组件，减少原角色编辑区域的纵向臃肿感。
- 新老 UI 可切换，便于在迁移期保留稳定编辑路径。
- 随机角色生成器拆成 Vue 组件并接入角色编辑器，支持在编辑角色卡时直接生成角色草案。
- 角色编辑器的 Webview 资源与 VS Code 语言环境适配得到加强。

### 稳定性与交互修复

- 修复快速设置保存按钮反馈不明显的问题，保存后会更新状态提示和原始设置快照。
- 修复设置向导遮罩和布局导致的闪烁、标题溢出、内容不能滚动、底部按钮间距异常等问题。
- 修复智能编辑自动补全括号预览中光标位置错误，补全后光标会落在括号内部。
- 字体家族预览增加分页，避免示例句子过多导致卡片显示不下。
