# 角色合并优先级策略测试

## 概述

现在支持三种角色合并优先级策略：

1. **loadOrder** - 按加载顺序（默认）
   - 先加载的角色作为基础角色，后加载的合并到基础角色上
   - 适用于简单场景，加载顺序决定优先级

2. **fileType** - 按文件类型
   - 根据文件扩展名确定优先级
   - 默认优先级：`.ojson5` (3) > `.json5` (2) > `.md` (1) > `.txt` (0)
   - 适用于有明确文件类型优先级需求的场景

3. **fileName** - 按文件名
   - 支持特殊前缀提升优先级（如 `__` 或 `!!`）
   - 默认：带有特殊前缀的文件优先级最高（1000）
   - 其余按文件类型优先级处理
   - 适用于需要强制提升某个文件优先级的场景

## 配置方法

在 VSCode 设置中搜索 `AndreaNovelHelper.rolePriority`，可以配置：

```json
{
  "AndreaNovelHelper.rolePriority": {
    "strategy": "fileName",  // 选择策略
    "highPriorityPrefixes": ["__", "!!"],  // 高优先级前缀
    "fileTypePriority": {  // 文件类型优先级
      ".md": 1,
      ".json5": 2,
      ".ojson5": 3,
      ".txt": 0
    }
  }
}
```

## 实际示例

### 示例1：文件名前缀优先级

- `zhangsan.md` - 普通MD文件，优先级 1
- `__zhangsan.json5` - 带高优先级前缀的文件，优先级 1000
- `zhangsan.json5` - 普通JSON5文件，优先级 2

合并时，`__zhangsan.json5` 的角色属性将作为基础角色，其他文件的角色会合并到它上面。

### 示例2：文件类型优先级

- `zhangsan.md` - MD文件，优先级 1
- `zhangsan.json5` - JSON5文件，优先级 2
- `zhangsan.ojson5` - OJSON5文件，优先级 3

合并时，`zhangsan.ojson5` 的角色属性将作为基础角色。

### 示例3：混合策略

使用 `fileName` 策略时：
- `__zhangsan.md` (1000) > `zhangsan.ojson5` (3) > `zhangsan.json5` (2) > `zhangsan.md` (1)

## 使用建议

1. **推荐使用 `fileName` 策略**，因为它最灵活：
   - 可以通过 `__` 前缀强制提升某个文件的优先级
   - 同时保留文件类型的优先级作为基础

2. **特殊前缀用途**：
   - `__角色名.json5` - 强制优先的角色文件
   - `!!角色名.md` - 紧急角色覆盖文件
   - 可以用于临时覆盖、特殊情况处理

3. **一致性**：
   - 在同一个项目中保持一致的命名策略
   - 避免过多的高优先级文件，以免管理混乱

## 注意事项

- 优先级只在合并相同UUID的角色时生效
- 不同名称但相同UUID的角色，非基础角色的名称会自动添加到别名中
- 配置修改后需要重新加载角色库才能生效
