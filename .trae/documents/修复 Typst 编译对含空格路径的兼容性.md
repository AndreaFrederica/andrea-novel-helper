## 测试范围
- 覆盖含空格、中文、括号()、方括号[]、和号&、叹号!、加号+、逗号,、分号;、等号=、波浪号~、井号#、Emoji 的路径。
- 同时验证：输入文件路径、输出文件路径、工作目录三者均可能包含上述字符。
- 格式矩阵：`pdf`、`png`、`svg` 各至少 1 条用例；`png` 验证多页 `{p}` 模式。
- 也验证 CLI 路径包含空格的情况（例如 `C:\Program Files\Typst\typst.exe`）。

## 用例准备
- 在仓库 `tests` 目录下创建以下子目录与输入文件（避免非法字符与保留名，不以点或空格结尾）：
  - `Space Path/输入 测试.md`
  - `中文 路径/章节 一.md`
  - `括号(测试)/内容.md`
  - `方括号[测试]/内容.md`
  - `和号&符/内容.md`
  - `叹号!测试/内容.md`
  - `加号+号/内容.md`
  - `逗号,测试/内容.md`
  - `分号;测试/内容.md`
  - `等号=测试/内容.md`
  - `波浪号~测试/内容.md`
  - `井号#测试/内容.md`
  - `Emoji 🐱/内容.md`
- 每个 `内容.md` 写入简单 Markdown（含一级标题与段落）。

## 执行步骤
- 使用脚本：`node scripts/typst-test.js` 进行编译，分别指定输出到同名目录下的目标文件，确保输出路径也包含特殊字符，例如：
  - `-i "tests\中文 路径\章节 一.md" -t sample -f pdf -o "tests\中文 路径\输出 文件.pdf"`
  - `-i "tests\括号(测试)\内容.md" -t sample -f png -o "tests\括号(测试)\输出-{p}.png"`
  - `-i "tests\Emoji 🐱\内容.md" -t sample -f svg -o "tests\Emoji 🐱\输出 文件.svg"`
- 为 CLI 路径含空格的用例，设置环境变量 `TYPST_PATH` 指向 `C:\Program Files\Typst\typst.exe`（或仿真路径）。

## 验证标准
- 进程返回码为 `0`，控制台输出 `ok: <输出路径>`。
- 目标文件按指定路径成功生成；`png` 生成序列文件（如 `输出-1.png`）。
- 输出路径和文件名保留原样字符（中文、符号、Emoji 不丢失）。

## 扩展内验证
- 在 VS Code 中用命令 `andrea.typst.exportCurrent` 对含空格/中文路径的 Markdown 文档导出 PDF：
  - 输出面板打印命令行与参数；`exit 0`。
  - 自动打开导出的 PDF，无异常报错。

## 失败处理
- 若任一用例失败：记录 `stderr`、实际命令、输入/输出/工作目录路径；定位是否为 CLI 限制或文件系统限制。
- 必要时增加回退测试：在不含特殊字符路径下跑同一输入以确认编译器本身正常。
