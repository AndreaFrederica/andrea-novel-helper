## 结论
- 是的：当原文对应的选区文本“整段删除”（无法在当前文档中重定位）时，自动删除对应的批注是有效且符合直觉的方案。
- 为避免误删，删除应以“严格重定位失败”为判断依据：精确匹配失败 + 上下文回钩失败 + 距离超阈值；其后不再兜底到段落索引。

## 技术要点
- 触发点：`onDidChangeTextDocument` 后 250ms 的批处理重定位（src/comments/controller.ts:92-99, 780-859）。
- 删除粒度：
  - 多范围线程逐段判断；无法重定位的范围从锚点移除。
  - 若该线程所有范围均移除 → 软删除该线程（src/comments/storage.ts:555-567）。
- 严格重定位准则：
  - `findBestOccurrence` 命中仅在“距原 offset ≤ N 字符/行 + 至少一个上下文片段匹配”时接受；否则拒绝。
  - `rebindByContextMulti` 返回 undefined 视为失败；不再调用 `approxStartOfParagraph` 兜底生成新范围。
- 文本存在性判定：
  - `if (!text.includes(selText))` 且上下文重定位失败 → 直接认定该范围已缺失。
- 配置开关：
  - `AndreaNovelHelper.comments.cleanup.mode`：`delete-thread`（默认）/ `delete-range` / `mark-resolved` / `none`。
  - `AndreaNovelHelper.comments.relink.strict`：默认开启；可降级为宽松重定位（保留现行为备选）。

## 修改点
- src/comments/controller.ts:780-859 `relinkAllAnchors`
  - 调整重定位流程为“严格模式”，加入距离阈值与上下文一致性校验。
  - 对失败范围不再段落兜底，直接将其从 `t.anchor.ranges` 移除。
  - 当 `newRanges.length === 0` 时调用 `deleteThread(t.id)`，随后 `loadComments(docUuid)` 刷新数据与装饰。
- package.json 配置：新增上述两个配置项，中文说明与默认值。

## 验证用例
- 删除：选区文本整段删除 → 线程自动软删除；编辑器装饰消失；面板卡片减少。
- 多范围：删除其中一段 → 仅该段被清理，线程保留并更新范围行信息。
- 移动：剪切粘贴到远处但上下文不吻合/距离超限 → 不重定位，按删除处理；若两侧上下文吻合且距阈值内 → 正常重定位。
- 误继承保护：文档中存在同词的另一处位置，删除原位置 → 因上下文/距离不符，不会继承到新处。

## 跨设备注意
- 批注数据位于 `novel-helper/comments`；需确保该目录纳入 Git/WebDAV 同步，避免“其他设备看不到”。
- 若使用自动提交，建议开启 `AndreaNovelHelper.autoGit.includeUntracked` 以纳入新批注文件的跟踪。
