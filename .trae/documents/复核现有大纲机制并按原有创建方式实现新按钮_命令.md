## 约束

* 不改动既有“当前文件/当前目录”两套动态URL的刷新逻辑：`andrea-outline://outline/目录大纲.md|文件大纲.md` 继续仅依赖 `refreshByTraditionalRel(...)` 设置 `lastFolderRel/lastFileRel`。

* 新增一种“直接URL”打开固定大纲文件的能力，仍然使用 `andrea-outline` scheme，使智能分组锁识别为大纲窗口。

## 方案概述（扩展 FileSystemProvider 映射）

* 在 `MemoryOutlineFSProvider` 内新增一套直接映射规则：当收到 `andrea-outline://outline/direct/<encodedRel>` 或 `andrea-outline://outline?rel=<urlencodedRel>` 这类 URL 时，提供器将其映射到 `outlineRoot + rel` 的真实物理文件，并在内存盘中缓存对应内容，读写都回落到该物理文件。

* 保留现有别名与刷新逻辑不变：

  * 别名 `/目录大纲.md` → `/current_dir_outline.md`

  * 别名 `/文件大纲.md` → `/current_file_outline.md`

  * `refreshByTraditionalRel(...)` 仅影响上述两个包装文件与 `lastFolderRel/lastFileRel`。

## 详细实现

* URI 设计：

  * Path 方式：`andrea-outline://outline/direct/<base64(rel)>`

  * Query 方式：`andrea-outline://outline/direct?rel=<encodeURIComponent(rel)>`

  * 只允许 `rel` 指向 `outlineRoot` 下的文件，拒绝包含 `..` 的路径，避免越界访问。

* 提供器扩展：

  * 新增 `private directMap = new Map<string, string>()`，键为内存盘路径（例如 `/direct/<hash>`），值为磁盘文件绝对路径。

  * `toMemPath(uri)` 增加分支：

    * 若为别名（现有两种），按原逻辑返回 `/current_*`。

    * 若为 `direct` URL：解析 `rel`，计算磁盘路径，生成稳定 `hash`（如 `sha1(rel)`），将内容载入到 `/direct/<hash>`，`directMap.set('/direct/<hash>', diskPath)`，返回该内存路径。

  * `readFile/stat`：对 `/direct/*` 直接读内存盘（首次访问时已懒载入）。

  * `writeFile`：

    * 若是别名包装文件，保持现逻辑（写回 `last*Rel`）。

    * 若是 `/direct/*`，用 `directMap.get(memPath)` 获取磁盘路径，写回磁盘并触发变更事件。

* 安全与健壮性：

  * 路径校验：`rel` 不得以 `/` 开头；拼接后必须以 `outlineRoot` 为前缀；禁止 `..`。

  * 缓存淘汰：必要时可简单复用，初版不做复杂 LRU。

## 命令层用法（保持现有刷新逻辑不变）

* 新选择器命令 `AndreaNovelHelper.openOutlinePicker`：

  * 选择“打开具体文件/目录的大纲”时，计算其 `rel`（遵循现有命名）；

  * 直接构造 `andrea-outline://outline/direct/<base64(rel)>` 并 `vscode.open`；不调用 `refreshByTraditionalRel`，以免影响“当前”别名的上下文。

  * 选择“当前文件/当前目录大纲”仍走原逻辑：`ensureOutlineFileExists` → `refreshByTraditionalRel` → 打开别名。

* 智能分组锁识别：保持 `andrea-outline` scheme，标签将被识别为 ANH 特殊窗体（src/utils/smartTabGroupLock.ts:193-203）。
