## 问题与成因（双目录大纲）
- 分屏操作会复制上半屏的活动编辑器到下半屏（VS Code 默认行为），若在下半屏未能及时替换为文件大纲，就会短暂出现两个“目录大纲”。现有去重逻辑仅在“下半屏”查找并关闭，但存在时序与匹配边界，导致偶发重复保留。
- 目录与文件大纲的视图语义不统一（两个独立文档），UI 交互更容易触发重复标签。

## 改造方案（不移除旧命令）
- 目录大纲合并为“该目录下的特殊文件大纲”：
  - 路径约定统一：
    - 文件大纲：`<相对目录>/<文件基名>._outline.md`
    - 目录大纲（特殊文件）：`<相对目录>/_folder._outline.md`
  - 别名不变，但映射到上述统一文档：`andrea-outline://outline/目录大纲.md` → 当前目录 `_folder._outline.md`；`andrea-outline://outline/文件大纲.md` → 当前文件 `fileBase._outline.md`。
- 新增交互命令与按钮：
  - 新命令 `AndreaNovelHelper.openOutlinePicker`（编辑器标题栏按钮），复用 `QuickPick` 交互（参考 `src/typeset/quickSettings.ts:21-34, 45-52`）。
  - 顶层选项：打开当前文件大纲 / 打开当前目录大纲（特殊文件）/ 选择具体文件或目录的大纲 / 视图位置（当前组/第二列/下分屏）。
- 生成与刷新统一：
  - 使用 `ensureOutlineFileExists(...)` 写入标题与提示；目录树使用新增 `buildFolderOutlineWithDepth(dir, depth)`（基于 `src/utils/outline.ts:7-19`）。
  - 刷新通过 `outlineFS.refreshByTraditionalRel(...)`（`MemoryOutlineFSProvider.ts:85-112`）。
- 分屏去重稳健化：
  - 在分屏后先检测下半屏是否为目录别名，若是先关闭再打开文件大纲；或在打开文件大纲时使用“替换当前编辑器”的命令变体，避免瞬时重复。
